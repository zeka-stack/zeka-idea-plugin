# IntelliAI Repairer 技术方案（Checkstyle/PMD XML 驱动的 AI 修复）

## 目标

在未安装 Checkstyle-IDEA 时，读取 Maven 生成的 Checkstyle/PMD 报告（XML/SARIF），将问题注入 IDEA 的 Problems/编辑器高亮，并提供 AI QuickFix
修复入口；在已安装 Checkstyle-IDEA 时，复用其 Inspection + QuickFix 扩展点。

## 总体架构

1. **输入源**
    - Checkstyle-IDEA 插件（优先）
    - Maven Checkstyle/PMD XML（兜底）
2. **统一模型**
    - `CodeViolation` 作为全局统一问题模型
3. **修复流水线**
    - Snippet 裁剪 → Prompt 生成 → AI 生成 → 校验 → 替换
4. **IDE 注入**
    - `ExternalAnnotator` 注入 Problems + 高亮
5. **触发机制**
    - 手动 Action（推荐）
    - Maven 执行完成 Hook（可选增强）

## 输入源策略

### 1) Checkstyle-IDEA 已安装

- 通过扩展点 `CheckStyle-IDEA.checkstyleQuickFixProvider` 提供 AI QuickFix
- 不进行 XML 解析

### 2) 未安装 Checkstyle-IDEA

- 解析 Maven 生成报告（XML/SARIF）
- 注入 Problems Tool Window + 编辑器高亮

## 统一数据模型

```java
public class CodeViolation {
    String tool;          // CHECKSTYLE / PMD
    String ruleId;        // LineLength / AvoidDuplicateLiterals
    String message;       // 人类可读描述
    int severity;         // 统一映射后的严重级别
    String filePath;
    int startLine;
    int startColumn;
    int endLine;
    int endColumn;
}
```

## 报告解析策略

### Checkstyle XML

```xml
<file name="...">
  <error line="12" column="5" severity="error"
         message="Line is longer than 120 characters"
         source="com.puppycrawl.tools.checkstyle.checks.sizes.LineLengthCheck"/>
</file>
```

映射规则：

- file/@name → filePath
- error/@line → startLine
- error/@column → startColumn
- error/@message → message
- error/@source → ruleId
- error/@severity → severity

### PMD XML

```xml
<file name="...">
  <violation beginline="42" endline="44" rule="AvoidDuplicateLiterals" priority="3">
    The String literal "test" appears 5 times in this file.
  </violation>
</file>
```

映射规则：

- file/@name → filePath
- violation/@beginline → startLine
- violation/@endline → endLine
- violation/@rule → ruleId
- violation/@priority → severity
- violation 文本 → message

## 触发机制

### 1) 手动 Action

入口：`Analyze -> Import Static Analysis Report`

流程：

1. 解析 XML → CodeViolation 列表
2. 写入 Project 级缓存
3. `DaemonCodeAnalyzer.getInstance(project).restart()` 触发注入

### 2) Maven 执行 Hook

监听 Maven 执行完成事件：

1. 识别目标（checkstyle/pmd/verify）
2. 自动解析报告
3. 刷新 Annotator

## 注入 Problems（ExternalAnnotator）

```java
class StaticAnalysisAnnotator extends ExternalAnnotator<Project, List<CodeViolation>> {
    public List<CodeViolation> doAnnotate(Project project) { return cache.get(project); }
    public void apply(PsiFile file, List<CodeViolation> violations, AnnotationHolder holder) {
        for (CodeViolation v : violations) {
            if (!v.filePath.equals(file.getVirtualFile().getPath())) continue;
            TextRange range = computeRange(file, v);
            holder.newAnnotation(HighlightSeverity.WARNING, v.message)
                  .range(range)
                  .withFix(new AiFixQuickFix(v))
                  .create();
        }
    }
}
```

## AI QuickFix（通用）

### 修复流程

1. 根据 `startLine/startColumn/endLine/endColumn` 提取 `originalSnippet`
2. 构造 Prompt
3. AI 返回替换片段
4. 校验：
    - 片段未被修改
    - 输出不含 markdown 标记
5. 替换

### Prompt 模板（统一）

```
你是一个 IntelliJ IDEA 插件中的代码修复引擎。
你只允许修改提供的代码片段，不得假设其他上下文。
不要输出解释，只返回修复后的代码片段本身。

【规则信息】
- 工具：${tool}
- Rule：${ruleId}
- 描述：${message}

【原始代码片段】
<<<CODE>>>
${snippet}
<<<END>>>

【要求】
- 仅修改上述代码片段
- 保持原有语义不变
- 修复该规则问题
- 不引入额外格式化
- 返回完整替换后的代码片段
```

## 里程碑

1. **M1**：完成 XML 解析 → Violation 映射
2. **M2**：ExternalAnnotator 注入 + 手动 Action
3. **M3**：Maven Hook 自动刷新
4. **M4**：PMD/Checkstyle 统一批量修复 + Problems 面板增强
