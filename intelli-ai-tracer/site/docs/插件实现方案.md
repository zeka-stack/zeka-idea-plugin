要做 “IntelliAI Tracer”，那「如何获取方法的调用上下文（调用链）」 就是最核心的基础能力。

🧭 一、总体目标：获取某个方法的上下文信息

假设用户光标在：

orderService.createOrder(userId, productId);

你希望拿到的信息包括：

信息类型 示例
当前方法签名 OrderController#createOrder(...)
当前调用点所在类 OrderController
调用链上层 UserController -> OrderController -> OrderService -> OrderRepository
被调用方法定义位置 OrderService#createOrder(...)
该方法又调用了哪些方法 下层依赖关系（如 InventoryService#lockStock()）
所在包、模块、文件等 com.company.project.module.order
相关注解 @Transactional, @Service, @RestController
Javadoc / 注释内容 便于 AI 理解业务语义

⸻

⚙️ 二、IntelliJ 平台可用的关键 API

在 IntelliJ 插件开发中，我们依赖的是 PSI（Program Structure Interface）与索引机制。

1. 获取光标位置的 PSI 元素

Editor editor = FileEditorManager.getInstance(project).getSelectedTextEditor();
PsiFile psiFile = PsiDocumentManager.getInstance(project).getPsiFile(editor.getDocument());
PsiElement elementAtCaret = psiFile.findElementAt(editor.getCaretModel().getOffset());

👉 拿到光标对应的语法节点（PsiElement），然后逐层向上找是否在方法调用或声明中。

⸻

2. 判断是否是方法调用表达式

if (elementAtCaret instanceof PsiIdentifier) {
PsiElement parent = elementAtCaret.getParent();
if (parent instanceof PsiMethodCallExpression) {
PsiMethodCallExpression callExpr = (PsiMethodCallExpression) parent;
PsiMethod resolvedMethod = callExpr.resolveMethod();
}
}

这样你就能拿到当前调用的目标方法（resolvedMethod），包括：
• resolvedMethod.getName()
• resolvedMethod.getContainingClass()
• resolvedMethod.getParameterList()
• resolvedMethod.getModifierList()（可读注解）

⸻

3. 获取当前所在方法与类

PsiMethod currentMethod = PsiTreeUtil.getParentOfType(elementAtCaret, PsiMethod.class);
PsiClass currentClass = PsiTreeUtil.getParentOfType(elementAtCaret, PsiClass.class);

可以知道当前上下文（在哪个类的哪个方法里调用的）。

⸻

4. 分析调用关系：上行调用链

IntelliJ 提供了 ReferencesSearch 与 CallHierarchyBrowserBase，可以直接查找调用者。

Query<PsiReference> query = ReferencesSearch.search(resolvedMethod, GlobalSearchScope.projectScope(project));
for (PsiReference ref : query) {
PsiElement caller = ref.getElement();
PsiMethod callerMethod = PsiTreeUtil.getParentOfType(caller, PsiMethod.class);
}

这样可以递归地查出所有“谁调用了这个方法”。

⚠️ 注意：这类搜索是基于索引的，不是即时分析。
如果项目特别大，建议异步执行 + 缓存结果（例如用 ReadAction.nonBlocking()）。

⸻

5. 分析调用关系：下行调用链

在某个 PsiMethod 内，遍历其 body：

method.accept(new JavaRecursiveElementVisitor() {
@Override
public void visitMethodCallExpression(PsiMethodCallExpression expression) {
PsiMethod called = expression.resolveMethod();
if (called != null) {
// 收集被调用方法信息
}
}
});

这样可以知道当前方法中又调用了哪些方法，从而向下扩展调用链。

⸻

6. 提取结构化上下文（供 AI 使用）

整理结构：

{
"current": {
"class": "OrderService",
"method": "createOrder",
"signature": "public Order createOrder(Long userId, Long productId)",
"annotations": ["@Transactional", "@Service"]
},
"callerChain": [
"OrderController#createOrder()",
"OrderFacade#processOrder()"
],
"calleeChain": [
"InventoryService#lockStock()",
"PaymentService#charge()"
],
"docComment": "Handles the creation of a new order and associated payment."
}

最终送给 AI 进行工作流解释。

🧩 三、调用链获取的综合思路

1. 定位光标 → 方法调用表达式
   拿到被调用方法与当前上下文。
2. 分析调用关系（ReferencesSearch + RecursiveVisitor）
   递归生成上/下行调用树。
3. 缓存结果（SmartPsiElementPointer）
   避免重复解析。
4. 提供结构化 JSON（供 AI）
   AI Prompt 可以直接用这个上下文生成可视化说明、时序描述、业务解释等。

⸻

🧠 四、性能与精度建议

问题 优化方向
大项目调用链过长 限制深度（如 2~3 层）
异步执行 使用 ProgressManager.runProcessWithProgressAsynchronously()
缓存 PSI 解析结果 ConcurrentHashMap<PsiMethod, CallGraph>
结果可视化 可以先用 GraphBuilder 生成简单树形结构
精度问题 对于接口方法，建议结合 ImplementationSearch 查找实际类实现

⸻

📦 五、示例：递归构建调用链

简化版伪代码：

public class CallGraphBuilder {

    public CallGraph build(PsiMethod method, int depth) {
        if (depth > MAX_DEPTH) return new CallGraph(method);
        
        CallGraph graph = new CallGraph(method);

        // 下层调用
        method.accept(new JavaRecursiveElementVisitor() {
            @Override
            public void visitMethodCallExpression(PsiMethodCallExpression expression) {
                PsiMethod target = expression.resolveMethod();
                if (target != null) {
                    graph.addCallee(build(target, depth + 1));
                }
            }
        });

        // 上层调用
        Query<PsiReference> query = ReferencesSearch.search(method);
        for (PsiReference ref : query) {
            PsiMethod caller = PsiTreeUtil.getParentOfType(ref.getElement(), PsiMethod.class);
            if (caller != null) {
                graph.addCaller(build(caller, depth + 1));
            }
        }

        return graph;
    }

}

🚀 六、AI 结合思路（预览）

有了上面的上下文后，你就可以让 AI 来解释调用链：

“根据以下调用关系，解释该方法在业务流程中的作用。”

比如输入：

{
"currentMethod": "OrderService#createOrder",
"callerChain": ["OrderController#createOrder", "OrderFacade#processOrder"],
"calleeChain": ["InventoryService#lockStock", "PaymentService#charge"]
}

AI 输出：

🧠 该方法位于订单创建流程的核心逻辑中，由 OrderController#createOrder 调用。
它依次锁定库存并触发支付，属于订单业务的事务性聚合层。
典型调用顺序为：

Controller → Service → Repository

整体属于订单提交的主业务流。

目标：既能让 AI 准确理解上下文逻辑，又不至于太长或冗余。
数据以 JSON（或 YAML）形式传入最合适。

🧠 二、字段说明与用途

字段 说明 用于
project 项目名、包路径 给 AI 业务范围上下文
currentClass 当前类信息 判断层级（Controller/Service/Repository）
currentMethod 当前方法详细信息 主体逻辑描述
parameters 参数类型与用途 生成时序图中对象节点
callers 谁调用了当前方法 生成上层调用链
callees 当前方法调用了哪些方法 生成下层流程
bodySummary 方法中关键步骤（通过静态分析提取） 帮助 AI 理解逻辑内容

🧠 Prompt: IntelliAI Tracer

You are a senior software architect and system analyst.

Your task is to analyze the following method context and generate a clear explanation
of its workflow, including a visual call sequence (Mermaid format) and a concise business logic summary.

Requirements:

1. Understand how this method fits into the overall call chain.
2. Identify the sequence of method calls from the caller to the callees.
3. Generate a readable sequence diagram in Mermaid format.
4. Explain in plain technical language what this method does, and its role in the system.
5. Avoid adding any speculative details that are not supported by the given context.

Here is the method context (JSON):

{your JSON data here}

Now please output:

- A **Mermaid sequence diagram** describing the call flow.
- A **technical explanation** (3-5 sentences) summarizing the business logic and purpose of this method.

⸻

✅ 输出示例（AI 预期生成）

### 🧩 Workflow: OrderService#createOrder

#### Sequence Diagram

```mermaid
sequenceDiagram
    participant Controller as OrderController
    participant Service as OrderService
    participant Inventory as InventoryService
    participant Payment as PaymentService

    Controller->>Service: createOrder(userId, productId)
    Service->>Inventory: lockStock(productId)
    Service->>Payment: charge(userId, orderId)
    Payment-->>Service: PaymentResult
    Service-->>Controller: Order

Explanation
The createOrder method orchestrates the core order creation process.
It is invoked by the OrderController#createOrder endpoint.
Within the method, it validates inputs, locks inventory, creates the order record, and triggers payment processing.
This method serves as the main business workflow that coordinates between the order, inventory, and payment modules.
