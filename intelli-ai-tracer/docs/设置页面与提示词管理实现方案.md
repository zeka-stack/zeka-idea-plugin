# IntelliAI Tracer 设置页面与提示词管理实现方案

## 1. 背景

IntelliAI Tracer 目前仍是 MVP，AI 服务提供商固定取全局配置中的第一个，Prompt 模板也硬编码在 `WorkflowExplainerService` 中。导致以下痛点：

- 使用者无法在插件层面选择首选的 AI 提供商/模型，当全局配置了多个服务商时体验受限。
- Prompt 模板难以根据项目场景快速调整，也无法复用 IDE 设置同步能力。
- 缺少设置界面来暴露上述能力。

intelli-ai-changelog 插件已经实现了「可选提供商下拉框 + Prompt 管理 + 全局配置监听」能力，本方案参照其实现思路进行复用。

## 2. 目标

1. 在 IntelliAI Tracer 中新增设置页面，允许用户：
    - 从全局已校验的 AI 提供商列表中选择一个默认配置；
    - 当全局配置变化时，通过监听器自动刷新下拉列表；
    - 在无可用提供商时提供跳转入口到 IntelliAI Engine 设置页。
2. 提供 Prompt 管理功能：
    - 支持编辑系统提示词与工作流生成提示模板；
    - 可折叠展示，默认隐藏，避免配置页过长；
    - 提供「恢复默认」按钮，快速回到内置模板；
    - 文本区域支持自动扩展高度，提高编辑体验。
3. Workflow 调用逻辑接入新的设置：
    - 调用 AI 时优先使用设置页中选择的服务商；
    - 构建 Prompt 时读取用户定义的模板，若为空则回退默认值。
4. 配置需持久化（`PersistentStateComponent`）并在插件卸载/重启后生效。

## 3. 范围

- **新增** 设置相关的状态、面板、Configurable；
- **修改** `WorkflowExplainerService` 的 AI 选取逻辑与 Prompt 构建方式；
- **国际化**：在 `messages.properties` 中新增相关文案；
- **插件配置**：在 `plugin.xml` 中注册 `projectConfigurable`;
- **文档/更新说明**：`docs/`, `includes/pluginChanges.html` 等待功能完成后更新。

## 4. 详细设计

### 4.1 SettingsState

参考 `intelli-ai-changelog` 的 `SettingsState`：

| 字段                                                               | 说明                      |
|------------------------------------------------------------------|-------------------------|
| `public AIProviderConfig providerConfig;`                        | 记录默认 AI 配置，序列化时只保存必要字段  |
| `public boolean showPromptSettings = false;`                     | 是否展开 Prompt 管理区         |
| `public String systemPrompt = getDefaultSystemPrompt();`         | 系统提示词                   |
| `public String workflowTemplate = getDefaultWorkflowTemplate();` | 输出模板（包含 Mermaid + 文案结构） |

实现要点：

- 使用 `@State` + `PersistentStateComponent<SettingsState>`；
- 提供 `getInstance()`、`getDefaultSystemPrompt()`、`getDefaultWorkflowTemplate()`；
- 默认模板直接复用现有 `buildSystemPrompt`/`buildUserPrompt` 内容（可适当结构化，例如使用占位符 `{contextJson}`）；
- 复杂字段（`AIProviderConfig`）存储时调用 `.copy()`，避免共享引用。

### 4.2 UI 与 Configurable

#### 4.2.1 `TracerSettingsPanel`

位置：`dev.dong4j.zeka.stack.idea.plugin.workflow.settings.ui`

结构复用 `ChangelogSettingsPanel`，差异在于 Prompt Tab 更精简：

- **AI Provider 区域**：参考 changelog 的 combo + 空状态提示：
    - 使用 `AIProviderSettings.getInstance().getVerifiedProviders()` 获取列表；
    - 通过 `AIProviderSettingsListener` 注册监听，触发 `refreshProviderComboBox()`；
    - 当无可用配置时展示 `JBLabel` 提示 + `HyperlinkLabel` 打开 IntelliAI Engine；
    - ComboBox 械 `AICommonIcons.getProviderIcon` 渲染 icon。
- **Prompt 区域**：
    - `JBCheckBox` 控制 `showPromptSettings`；
    - `JBTabbedPane` 包含两个 Tab：
        1. System Prompt（系统提示词）
        2. Workflow Template（输出格式/用户消息模板）
    - 每个 Tab 内放置 `JBTextArea` + 重置按钮；
    - 文本区域添加 `DocumentListener` 自动调整行数，逻辑可拷贝 changelog 版本。
- `isModified/apply/reset/dispose` 接口逻辑比照 changelog：
    - `isModified` 需要比较文本、checkbox、provider；
    - `apply` 将 UI 值写入 `SettingsState`;
    - `reset` 根据 `SettingsState` 填充数据，处理 provider 恢复；
    - `dispose` 里移除 listener。

#### 4.2.2 `TracerSettingsConfigurable`

- 实现 `SearchableConfigurable`（遵循设置页面规则）；
- `getId()` / `getDisplayName()` 从 `WorkflowBundle` 读取国际化文案；
- `createComponent()` 延迟创建 `TracerSettingsPanel`；
- `isModified/apply/reset/disposeUIResources` 调用 panel 对应方法；
- 需要在 `plugin.xml` 中 `extensions` 区域加入 `<projectConfigurable ...>`。

### 4.3 国际化

在 `messages.properties` / `messages_zh_CN.properties` 中新增键，例如：

- `settings.display.name`
- `settings.ai.provider`
- `settings.ai.provider.no.available.warning`
- `settings.ai.provider.open.engine.settings`
- `settings.prompt.settings.show`
- `settings.prompt.tab.system`
- `settings.prompt.tab.workflow`
- `settings.prompt.reset`
- `settings.prompt.hint`

提示词默认值也可放入 `SettingsState` 中的静态方法，避免 i18n 文件过长。

### 4.4 WorkflowExplainerService 改造

1. **Provider 选取**：新增私有方法 `@Nullable AIProviderConfig getSelectedProvider()`：
    - 优先读取 `SettingsState.getInstance().providerConfig`；
    - 验证该配置是否仍存在于 `AIProviderSettings.getVerifiedProviders()`；
    - 若失效则 fallback 到第一个可用 provider；
    - 若仍无可用 provider，则抛出已有错误信息。
2. **Prompt 构建**：`buildSystemPrompt()` 与 `buildUserPrompt()` 改为读取 `SettingsState` 中字段：
    - `String prompt = settings.systemPrompt; if (StringUtil.isEmptyOrSpaces(prompt)) prompt = SettingsState.getDefaultSystemPrompt();`
    - `workflowTemplate` 中的 `{contextJson}`（或 `{json}`）占位符替换为真实数据；若用户移除占位符，可在文档/tooltip 中提示。
3. 确保 Prompt 中的 Markdown/代码块要求不变，但允许用户自定义。

### 4.5 插件配置 plugin.xml

```xml
<projectConfigurable
        parentId="tools"
        instance="dev.dong4j.zeka.stack.idea.plugin.workflow.settings.TracerSettingsConfigurable"
        id="dev.dong4j.zeka.stack.idea.plugin.workflow.settings"
        displayName="..."/>
```

> displayName 取自 `WorkflowBundle`，如 `IntelliAI Tracer`。

### 4.6 依赖与工具

- 使用 `AICommonIcons`（位于 common 模块）展示 provider 图标；
- 需要 `AIProviderSettingsListener`（已有依赖）；
- 所有 UI 组件遵循 IntelliJ UI 规范（JB* 系列、FormBuilder、JBTabbedPane 等）。

## 5. 兼容性与风险

| 风险                    | 对策                                                                        |
|-----------------------|---------------------------------------------------------------------------|
| 用户删除了在设置页选择的 provider | 在 reset/apply 时验证 ID，不存在则 fallback 第一个或要求重新选择                             |
| Prompt 文本太长导致 UI 卡顿   | 文本域默认 15 行，并设置最大 50 行                                                     |
| 监听器未移除导致内存泄露          | 在 `TracerSettingsPanel.dispose()` 中调用 `AIProviderSettings.removeListener` |
| 老版本设置文件缺失新字段          | 所有字段提供默认值，XmlSerializer 自动填充                                              |
| 用户将 workflow 模板中占位符删掉 | Tooltip 内提醒必须包含 `{contextJson}`，构建 user prompt 时若缺失则 append JSON 以确保功能可用  |

## 6. 测试计划

1. **单元/集成**：暂无专门测试，依赖 IDE 设置框架；
2. **手动验证**：
    - `./gradlew :intelli-ai-tracer:runIde`；
   - 打开 Settings → Tools → IntelliAI Tracer，验证 provider 列表/监听；
    - 切换 IntelliAI Engine 中的 provider，观察列表刷新；
    - 修改 Prompt 并保存，重新打开验证；
    - 运行 Explain Workflow，确认调用的 provider 与设置一致，AI 输出遵循自定义模板；
    - 清空 provider，再次进入设置页，能看到 warning + 跳转链接；
3. **回归**：
    - 未配置 provider 时仍有错误提示；
    - Prompt 恢复默认按钮生效。
