# 保存时自动生成注释功能实现方案

## 1. 需求背景

### 1.1 问题描述

在开发过程中，开发者经常需要为代码添加 Javadoc 注释，但手动编写注释既耗时又容易遗漏。虽然插件已经提供了多种触发方式（快捷键、右键菜单、Generate
菜单等），但都需要用户主动触发，无法实现自动化。

### 1.2 用户痛点

1. **需要主动触发**：每次保存文件后，如果需要生成注释，必须手动触发生成操作
2. **容易遗漏**：在快速开发过程中，开发者可能忘记为新添加的类、方法、字段生成注释
3. **效率低下**：频繁的手动操作降低了开发效率
4. **不符合工作流**：无法与现有的保存操作无缝集成

### 1.3 目标

实现一个自动化功能，当用户保存文件时，如果启用了"保存时生成注释"选项，自动为保存的文件中缺失 Javadoc 的元素生成注释，无需用户手动触发。

### 1.4 使用场景

- **场景 1**：开发者编写了一个新的 Java 类，保存文件后，自动为该类及其方法、字段生成 Javadoc
- **场景 2**：开发者修改了现有代码，添加了新的方法，保存后自动为新方法生成 Javadoc
- **场景 3**：开发者希望保持代码文档的完整性，每次保存时自动检查并补充缺失的注释

### 2.3 关键技术点

#### 2.3.1 文件保存监听

使用 `FileDocumentManagerListener` 接口监听文件保存事件：

```java
public class GenerateOnSaveListener implements FileDocumentManagerListener {
    @Override
    public void beforeDocumentSaving(@NotNull Document document) {
        // 处理保存事件
    }
}
```

**注册方式**：在 `plugin.xml` 中注册为应用级监听器：

```xml
<applicationListener
    topic="com.intellij.openapi.fileEditor.FileDocumentManagerListener"
    implementation="dev.dong4j.zeka.stack.idea.javadoc.listener.GenerateOnSaveListener"/>
```

#### 2.3.2 延迟执行机制

为了避免在保存过程中修改文档导致循环保存，使用延迟执行机制：

```java
AppExecutorUtil.getAppScheduledExecutorService().schedule(() -> {
    // 生成逻辑
}, 500, TimeUnit.MILLISECONDS);
```

**延迟时间**：500ms，确保文件保存完成后再执行生成逻辑。

#### 2.3.3 线程安全

使用 `AtomicBoolean` 防止重复触发：

```java
private static final AtomicBoolean isGenerating = new AtomicBoolean(false);

// 设置标志
if (!isGenerating.compareAndSet(false, true)) {
    return; // 已有生成任务，忽略本次保存
}

// 生成完成后重置
isGenerating.set(false);
```

#### 2.3.4 异步执行

使用 `ReadAction.nonBlocking()` 在后台线程中收集任务，使用 `finishOnUiThread()` 在 UI 线程中执行生成逻辑：

```java
ReadAction.nonBlocking(() -> {
    // 后台线程：收集任务
    TaskCollector collector = new TaskCollector(project);
    List<DocumentationTask> tasks = collector.collectFromFile(psiFile);
    return new GenerationContext(project, tasks, psiFile.getName());
})
.finishOnUiThread(ModalityState.NON_MODAL, context -> {
    // UI 线程：执行生成逻辑
    DocumentationGenerationService service = new DocumentationGenerationService();
    service.generateDocumentation(...);
})
.submit(AppExecutorUtil.getAppExecutorService());
```

## 3. 实现细节

### 3.1 配置管理

在 `SettingsState` 中添加配置字段：

```java
/**
 * 是否在保存文件时自动生成注释
 * <p>
 * 当该选项启用时，每次保存 Java 或 Kotlin 文件时，自动为文件中缺失 Javadoc 的元素生成注释。
 * 默认值为 false，需要用户手动启用。
 *
 * @since 2.8.0
 */
public boolean generateOnSave = false;
```

在 `GenerationRulesPanel` 中添加 UI 控件：

```java
private JBCheckBox generateOnSaveCheckBox;

// 初始化
generateOnSaveCheckBox = new JBCheckBox(
    JavadocBundle.message("settings.generate.on.save"),
    settings.generateOnSave
);
generateOnSaveCheckBox.setToolTipText(
    JavadocBundle.message("settings.generate.on.save.tooltip")
);
```

### 3.2 文件类型过滤

只处理 Java 和 Kotlin 文件：

```java
private boolean isSupportedFile(@NotNull VirtualFile file) {
    String extension = file.getExtension();
    return PluginContents.JAVA.equalsIgnoreCase(extension)
        || PluginContents.KOTLIN.equalsIgnoreCase(extension);
}
```

### 3.3 项目查找

通过遍历所有打开的项目，查找包含该文件的项目：

```java
private Project getProjectForFile(@NotNull VirtualFile file) {
    Project[] openProjects = ProjectManager.getInstance().getOpenProjects();
    for (Project project : openProjects) {
        if (!project.isDisposed()
            && ModuleUtilCore.findModuleForFile(file, project) != null) {
            return project;
        }
    }
    return null;
}
```

### 3.4 状态检查

在生成前进行多重检查：

1. **配置检查**：`SettingsState.generateOnSave` 是否为 true
2. **生成状态检查**：`isGenerating` 是否为 false（防止重复触发）
3. **文件类型检查**：是否为 Java 或 Kotlin 文件
4. **项目状态检查**：项目是否有效、是否处于 Dumb Mode
5. **AI 配置检查**：AI Provider 是否已配置

### 3.5 任务收集

使用现有的 `TaskCollector` 收集需要生成 Javadoc 的任务：

```java
TaskCollector collector = new TaskCollector(project);
List<DocumentationTask> tasks = collector.collectFromFile(psiFile);
```

`collectFromFile()` 方法会根据用户配置（`generateForClass`、`generateForMethod`、`generateForField`、`overrideExisting`）自动过滤任务。

### 3.6 文档生成

使用现有的 `DocumentationGenerationService` 执行生成逻辑：

```java
DocumentationGenerationService service = new DocumentationGenerationService();
service.generateDocumentation(
    project,
    tasks,
    JavadocBundle.message("task.target.save", fileName),
    stats -> {
        // 生成完成回调
        isGenerating.set(false);
        log.info("保存时自动生成 Javadoc 完成: {}", stats);
    }
);
```

## 5. 工作流程

### 5.1 启用功能

1. 打开设置页面：`Settings` → `Tools` → `IntelliAI Javadoc`
2. 进入"生成规则"面板
3. 勾选"📝 Generate Comments on Save"复选框
4. 点击"Apply"保存配置

### 5.2 自动生成流程

1. **用户保存文件**（Cmd+S / Ctrl+S）
2. **监听器触发**：`GenerateOnSaveListener.beforeDocumentSaving()` 被调用
3. **配置检查**：检查 `generateOnSave` 是否为 true
4. **状态验证**：验证文件类型、项目状态、AI 配置等
5. **延迟执行**：延迟 500ms 后开始生成逻辑
6. **任务收集**：在后台线程中收集需要生成 Javadoc 的任务
7. **文档生成**：在 UI 线程中异步执行生成逻辑
8. **完成通知**：生成完成后显示通知并重置标志

### 5.3 生成范围

根据用户配置，自动为以下元素生成 Javadoc：

- **类**：如果 `generateForClass` 为 true
- **方法**：如果 `generateForMethod` 为 true
- **字段**：如果 `generateForField` 为 true
- **测试方法**：如果 `generateForTest` 为 true

**过滤规则**：

- 如果 `overrideExisting` 为 false，跳过已有 Javadoc 的元素
- 只处理缺失 Javadoc 的元素
