# Archive Man 参考插件复刻指南

## 1. 文档目的

本指南汇总 `idea-archive-browser` 与 `file-expander-plugin` 的核心能力、架构实现与可借鉴点，指导 **Archive Man** 在复刻两款插件的基础能力时的技术路线与注意事项。目标是：

- 继承其“在 Project View 中像目录一样浏览归档文件”的体验；
- 扩展多格式读写与嵌套归档处理能力；
- 为后续“可编辑压缩包”特性提供稳定、可维护的底层设施。

---

## 2. `idea-archive-browser` 调研

### 2.1 功能范围

- Project View 中直接展开各类归档（7z、zip、rar、tar、镜像类等 30+ 格式）。
- 支持嵌套归档的递归浏览（`.jar` 中的 `.zip` 等）。
- 借助 SevenZip-JBinding 支持 7-Zip 生态中几乎所有格式的读取。
- 仅提供只读视图，不含写回、编辑或解压动作。

### 2.2 架构要点

| 模块              | 作用                                            | 关键类                                                                           |
|-----------------|-----------------------------------------------|-------------------------------------------------------------------------------|
| Project View 注入 | 将归档文件节点替换为自定义 PsiNode，实现树展开                   | `com.github.b3er.idea.plugins.arc.browser.ArchivePluginStructureProvider`     |
| 抽象文件类型          | 统一不同归档类型对应的 PsiNode 创建逻辑                      | `base/BaseArchiveFileType`                                                    |
| 虚拟文件系统          | 基于 `ArchiveFileSystem` 的只读实现，提供 handler 缓存等能力 | `base/BaseArchiveFileSystem`、`formats/sevenzip/SevenZipArchiveFileSystemImpl` |
| Handler 层       | 真正解析归档条目、维护 `EntryInfo`、缓存句柄                  | `base/BaseArchiveHandler`、`formats/sevenzip/SevenZipArchiveHandler`           |
| 嵌套支持            | 将嵌套文件复制到临时目录，重新挂载到本地 VFS                      | `util/FSUtils`（`copyFileToTemp`、`isNestedFile` 等）                             |

### 2.3 数据流

1. `TreeStructureProvider.modify()` 拦截 Project View 的 `PsiFileNode`。
2. 若文件类型为 `BaseArchiveFileType` 或 IntelliJ 自带 `ArchiveFileType` 且路径包含 `!/`，判定为嵌套归档。
3. 嵌套条目经 `FSUtils.copyFileToTemp()` 写入 IDE 临时目录，再用 `LocalFileSystem` 重新获取 `VirtualFile`。
4. 根据文件类型生成对应的 `PsiFileNode` 子类（例如 `SevenZipPsiFileNode`），内部通过 `SevenZipArchiveFileSystemImpl` 定位根目录。
5. `BaseArchiveHandler` 读取条目时借助 `FileAccessorCache` 复用七字节句柄，避免重复打开归档。

### 2.4 可复用经验

- **统一抽象层次**：`BaseArchiveFileSystem` + `BaseArchiveHandler` 将缓存、路径处理、VFS 对接抽象出来，后续扩展新格式仅需实现
  `getHandlerForPath()` 与 `isCorrectFileType()`。
- **嵌套缓存策略**：基于 `档案内容 + 时间戳 + 长度` 生成散列目录，将嵌套包缓存成本地文件，兼顾性能与一致性。
- **7-Zip 全格式覆盖**：通过 SevenZip-JBinding `IInArchive` + `ISimpleInArchiveItem`，一次性接入 rar、iso、vmdk 等 IntelliJ 默认不支持的格式。
- **降级策略**：任何解析异常直接回退为原始节点，确保 Project View 不会崩溃。

### 2.5 局限

- 纯浏览模式，无压缩条目写回。
- 依赖 JNI 库（SevenZip-JBinding），在 Apple Silicon 上仍标注 experimental。
- 未提供 UI 指示/动作，用户无法选择性展开或执行额外操作。

## 3. `file-expander-plugin` 调研

### 3.1 功能范围

- 支持在 Project View 内展开 `.zip/.jar/.war/.tgz/.tar/.gz/.7z/.zst` 等归档，包含嵌套档案。
- 额外提供 “Decompile Jar” 动作，将 `.jar` 中的 `.class` 快速反编译为 `.java` 并输出到磁盘。
- 比 `idea-archive-browser` 更注重常见构件格式（Java 生态为主），并与 Apache Commons Compress 结合。

### 3.2 架构要点

| 模块              | 作用                                                                                       | 关键类                                                         |
|-----------------|------------------------------------------------------------------------------------------|-------------------------------------------------------------|
| Project View 注入 | 判断归档类型、复制嵌套文件、替换节点                                                                       | `com.github.camork.extensions.ArchiveTreeProvider`          |
| 通用 VFS 基类       | 继承 `ArchiveFileSystem`，集中处理 `root path`、`normalize`、`!/` 解析                              | `filesystem/ArchiveBasedFileSystem`                         |
| 具体 VFS 实现       | 针对 zip/gz/tar/7z/zstd 各自实现 `getHandler`                                                  | `filesystem/*/*FileSystem`                                  |
| Handler 抽象      | 基于 `ArchiveHandlerBase`，配合 `FileAccessorCache` + Apache Commons Compress/SevenZFile 解析条目 | `filesystem/ArchiveHandlerBase`、`filesystem/*/*FileHandler` |
| 节点包装            | `PsiDirectoryNodeWrapper` + `ArchiveBasedPsiNode` 负责以目录形式展示条目，并兼顾嵌套场景                    | `nodes` 包                                                   |
| Jar 反编译动作       | `DecompileJarAction` 遍历 `JarFileSystem` 根节点，将 `.class` 的反编译文本输出为 `.java`                 | `action/DecompileJarAction`                                 |

### 3.3 数据流

1. `ArchiveTreeProvider.modify()` 中，若节点对应归档文件：
    - 通过 `ArchiveBasedFileSystem.isNestedFile()` 判断是否位于 `!/` 下。
    - 嵌套场景调用 `CoreUtil.getTempFilePath()`，复制到 `%tmp%/fileExpanderFiles`。
2. 根据文件类型选择对应的 FileSystem（zip/gz/tar/7z/zstd）。
3. `PsiDirectoryNodeWrapper` 将归档根包装成 `PsiDirectory` 节点；其 children 委托 `ArchiveBasedPsiNode` 递归生成。
4. Handler 端借助 `ArchiveUtils.calculateEntries()` 读取条目并构造 `EntryInfo` 树，利用 `FileAccessorCache` 避免重复 IO。
5. “Decompile Jar” 通过 `JarFileSystem.getRootByLocal()` 获取虚拟目录，`VfsUtilCore.visitChildrenRecursively()` 遍历条目，针对 `.class`
   读取反编译文本写回磁盘。

### 3.4 可复用经验

- **多协议并存**：不同格式对应独立的 `virtualFileSystem` 注册项，避免单一 Handler 过于复杂。
- **工具方法**：`CoreUtil` 为嵌套文件生成 **路径 + 时间戳** 的哈希名，可避免命名冲突。
- **二次增值能力**：`DecompileJarAction` 展示了在 Project View 注入动作、结合自定义 VFS 的扩展思路，可作为 Archive Man 未来“解压/导出/批量操作”的参考。
- **测试覆盖**：`src/test/...GZFileTest.kt` 等单测验证 handler 行为，值得在 Archive Man 的多格式支持中同步建设。

### 3.5 局限

- 仅覆盖常见归档格式，缺少镜像类/系统类格式。
- 依赖 Apache Commons Compress + SevenZip，由于拆分在多个 FileSystem，跨格式通用逻辑重复较多。
- 同样不支持编辑与写回。

## 4. 对比总结

| 维度              | Archive Browser                                         | File Expander                                       | Archive Man 复刻方向                                               |
|-----------------|---------------------------------------------------------|-----------------------------------------------------|----------------------------------------------------------------|
| 支持格式            | 借助 SevenZip-JBinding，覆盖 7z 支持的几乎所有格式                    | 聚焦 zip/tar/gz/7z/zstd 等常见格式                         | 第一阶段优先实现 zip/tar/gz/7z；需要镜像类格式时可移植 `SevenZipArchiveHandler` 思路 |
| 嵌套文件            | `FSUtils.copyFileToTemp()` + handler 输入流直拷贝（含单文件归档特殊处理） | `CoreUtil.getTempFilePath()` + `Files.copy`         | 统一抽象为 `NestedArchiveCacheService`，提供基于哈希的缓存与引用计数               |
| Project View 注入 | `TreeStructureProvider` + 自定义 `PsiFileNode`             | `TreeStructureProvider` + `PsiDirectoryNodeWrapper` | 复用 `TreeStructureProvider`，但在节点上挂接“可编辑/只读”标记                   |
| Handler 缓存      | `FileAccessorCache` + `ReusableRandomAccessFileStream`  | `FileAccessorCache` + `ResourceHandle`              | 复刻缓存层，加入写回场景下的“脏标记”与“独占锁”                                      |
| 附加能力            | 无                                                       | Jar 反编译动作                                           | Archive Man 可提供“导出/复制路径/快速解压”动作，保持扩展性                          |

## 5. Archive Man 复刻规划

### 5.1 模块拆分建议

1. **ArchiveViewBridge（新）**
    - 参考 `ArchivePluginStructureProvider`，集中处理 Project View 节点替换、错误降级与设置开关。
    - 保留扩展点以便后续添加“右键菜单动作/状态提示”。

2. **ArchiveVfsCore（新）**
    - 复用 `BaseArchiveFileSystem` + `BaseArchiveHandler` 的抽象思路，定义统一接口 `ArchiveFormatProvider`：
      ```text
      interface ArchiveFormatProvider {
          val protocol: String
          val fileType: FileType
          fun createFileSystem(): ArchiveFileSystem
          fun createHandler(path: String): ArchiveHandler
      }
      ```  
    - 不同格式（Zip/Tar/GZ/7z/Zstd）以 Provider 形式注册，避免多个继承链重复逻辑。

3. **NestedArchiveCacheService（新）**
    - 结合两个插件的散列策略：`hash(文件名, 时间戳, 长度, 单文件归档实际内容)`。
    - 负责：
        - 选择缓存目录（存放在 `PathManager.getTempPath()/ArchiveMan`）。
        - 引用计数（多个节点引用同一嵌套副本时避免重复复制）。
        - 生命周期管理（IDE 退出或磁盘清理时移除）。
    - 支持“直接流式拷贝”与“落地文件”两种策略（单文件归档优先使用流式写入）。

4. **ArchiveOperationActions（可选）**
    - 参考 `DecompileJarAction`，实现“快速导出/复制/解压目录”动作。
    - 动作层统一依赖 `ArchiveVfsCore` 暴露的 API，例如 `openEntryInputStream()`、`exportEntry(Path)`。

### 5.2 开发阶段

| 阶段            | 目标                                                | 参考实现                                                           |
|---------------|---------------------------------------------------|----------------------------------------------------------------|
| P0：Zip & Jar  | 以 IntelliJ 自带 Zip VFS 为基础，打通 Project View 展开与嵌套缓存 | `file-expander-plugin` 的 `ZipFileSystem`、`ArchiveTreeProvider` |
| P1：Tar/Gz/Tgz | 引入 Apache Commons Compress，使用统一 Handler 抽象        | `ArchiveHandlerBase` + `ArchiveUtils`                          |
| P2：7z/大体积镜像   | 集成 SevenZip-JBinding，解决 Apple Silicon 兼容与 JNI 部署  | `SevenZipArchiveHandler` + `ReusableRandomAccessFileStream`    |
| P3：扩展动作       | Jar 反编译 / 批量导出 / 快速打开临时目录                         | `DecompileJarAction`                                           |

### 5.3 与可编辑功能的衔接

- **只读层**：上述两个插件全部基于只读 VFS；Archive Man 在复刻时应确保 `ArchiveVfsCore` 对写回透明（可通过 `EditableArchiveFileSystem`
  继承只读实现并覆盖写操作）。
- **文档监听整合**：只读视图打开文件后，可继续沿用 `EditableArchiveDocumentListener` 将文档内容写入临时文件，再触发写回。
- **冲突检测**：借鉴两个插件的 `timestamp/length` 判断逻辑，在写入前再次校验归档是否被外部修改。

### 5.4 风险与缓解

| 风险     | 说明                                   | 缓解策略                                                                             |
|--------|--------------------------------------|----------------------------------------------------------------------------------|
| JNI 依赖 | SevenZip-JBinding 在不同架构需不同 native 库  | 将 native 库随插件打包，或提供下载引导；同时保留“仅启用 zip/tar”配置                                      |
| 临时目录膨胀 | 嵌套包复制导致磁盘占用上涨                        | Nested cache 定期清理、设置最大缓存大小、IDE 退出时清理                                             |
| 多线程并发  | Project View 展开 + 文档读取可能并发访问 Handler | 仿照 `FileAccessorCache` 的 `synchronized` 流程，引入 `ReadWriteLock` 保护句柄               |
| 大文件读取  | 单个条目过大导致内存占用                         | 借鉴 `SevenZipArchiveHandler.contentsToByteArray()` 中的 `FileTooBigException`，并提供配置 |

### 5.5 测试建议

- Port `file-expander-plugin` 中的 `GZFileTest` 思路，针对各格式编写 Handler 层单测。
- 补充嵌套缓存集成测试：构造 `outer.zip!/inner.tar!/app.jar`，确保能递归展开且缓存命中。
- Jar 反编译/导出等动作需结合 `TempDirectoryTestRule` 写入临时目录，确认文件存在。

## 6. 实施清单（供 Archive Man 团队追踪）

1. **整合 TreeStructureProvider**
    - 新建 `ArchiveManTreeStructureProvider`，支持在设置中启用/禁用。
    - 节点转换逻辑复用 `Archive Browser` 的异常回退策略。
2. **抽象 Handler & VFS 接口**
    - 定义 `ArchiveFormatProvider`，首批实现 Zip/Tar/Gz/7z。
    - 统一对接 `FileAccessorCache`，并对接日志/Telemetry。
3. **嵌套缓存服务**
    - 提供 `acquireNestedFile(VirtualFile): VirtualFile` API，内部负责复制/缓存。
    - 支持“引用计数 + 自动清理”。
4. **Jar 增值动作**
    - 移植 `DecompileJarAction` 思路，换成 Archive Man 的包名 & i18n。
    - 预留 Hook 给未来的“快速解压/导入”。
5. **测试与文档**
    - 针对每个格式新增 Handler 单测。
    - 在用户手册新增“归档浏览/导出”章节，与写能力区分。
    - 在更新记录中说明新增的浏览/导出功能。

---

通过以上调研与规划，Archive Man 可以在现有“ZIP 可编辑”能力之上，快速复刻这两款插件的浏览体验，并为未来的多格式写入、导出与交互扩展打下统一的基础设施。下一步建议根据阶段规划输出详细任务拆分与时间评估，随后逐步实现。
