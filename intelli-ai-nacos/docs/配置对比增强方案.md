## 背景与目标

现有 `CompareConfigService` 依赖 IntelliJ 自带 Diff 对话框，只支持静态对比：

- 缺乏基于文件类型的语法高亮；复杂 JSON/YAML 配置可读性差。
- 左侧本地内容不可编辑，无法直接修正后再次推送。
- Diff 窗口独立于工具窗口，用户需在多个窗口之间切换，体验割裂。

目标：在 `Nacos` Tool Window 内提供带语法高亮、可编辑本地内容的对比视图，并与已有标签体系整合。

## 需求拆解

1. **文件类型高亮**
    - 根据 `dataId` 后缀或 `type` 字段自动识别 `FileType`。
    - 所有编辑器面板按识别出的类型设置语法高亮与格式化能力。
2. **本地配置可编辑**
    - 左侧展示本地配置内容，对应的 `Document` 需与真实 `VirtualFile` 同步（若存在）。
    - 允许用户编辑后手动保存或一键同步到原文件。
    - 远程内容和历史版本内容保持只读，防止误改。
3. **多面板对比支持**
    - 支持 2 面板对比（本地 vs 云端）和 3 面板对比（本地 vs 云端 vs 历史版本）。
    - 第三个面板（历史版本）支持下拉选择版本，动态加载对应版本内容。
    - 使用 `JBSplitter` 实现灵活的分割布局，支持用户调整面板宽度。
4. **Tool Window 内对比**
    - 通过 `NacosToolWindow#openConfigTab`（或新增 API）在 `TabBar` 中新增"对比"页签。
    - 支持多个对比标签共存，命名示例：`{dataId} (Compare)`。
    - 对比页签关闭/切换行为与普通配置页一致。

## 实现方案

### 1. ConfigComparePanel

新增 `ui.components.ConfigComparePanel`：

- **布局设计**：
    - 使用 `JBSplitter` 实现多面板分割布局。
    - 支持 2 面板模式（本地 vs 云端）和 3 面板模式（本地 vs 云端 vs 历史版本）。
    - 面板比例可调整，默认 2 面板各占 50%，3 面板各占 33.3%。

- **编辑器面板**：
    - 使用 `EditorTextField` + `EditorFactory` 构建编辑器。
    - **左侧（本地配置）**：
        - 若传入本地文件路径，使用 `LocalFileSystem` 获取 `VirtualFile`，并通过 `FileDocumentManager` 获得可编辑 `Document`。
        - 若仅有字符串，创建临时 `Document`，允许编辑并在关闭前写回调用方。
        - 右下角提供"保存到本地"按钮，当存在 `VirtualFile` 时执行 `WriteCommandAction` 写入磁盘。
    - **中间（云端配置）**：
        - 使用 `EditorTextField` 设置 `setReadOnly(true)`。
        - 显示当前云端最新配置内容。
    - **右侧（历史版本，可选）**：
        - 使用 `EditorTextField` 设置 `setReadOnly(true)`。
        - 顶部提供版本选择下拉框（`ComboBox`），显示历史版本列表。
        - 下拉框选项格式：`{lastModifiedTime} (ID: {id})`，按时间倒序排列。
        - 选择版本后异步加载对应版本内容并更新编辑器。
        - 支持"加载中"状态提示。

- **文件类型识别**：
    - 统一通过 `FileTypeManager.getFileTypeByFileName(dataId)` 或回退到 `PlainTextFileType.INSTANCE`。
    - 所有编辑器面板使用相同的 `FileType`，确保语法高亮一致。

- **信息栏**：
    - 面板顶部提供信息栏显示 namespace/group/dataId 及提示。
    - 3 面板模式下，历史版本面板显示当前选中版本信息（时间、操作类型等）。

- **版本选择下拉框设计**：
    - 位置：历史版本面板顶部，信息栏下方。
    - 布局：使用 `BorderLayout`，下拉框放在 `NORTH`，编辑器放在 `CENTER`。
    - 下拉框选项格式：`{lastModifiedTime} (ID: {id})`，例如：`2024-01-15 10:30:00 (ID: 203)`。
    - 选项排序：按 `lastModifiedTime` 倒序（最新的在前）。
    - 交互：
        - 选择版本后，显示"加载中"状态（可在下拉框旁显示加载图标或禁用下拉框）。
        - 异步加载版本内容，完成后更新编辑器并恢复下拉框可用状态。
        - 加载失败时显示错误提示，保持当前显示内容不变。

### 2. CompareTab 支持

- 扩展 `ui.toolwindow.Tab` & `TabBar`，增加 Tab 类型或 metadata 标记（例如 `TabKind { CONFIG, COMPARE }`）。
- `Tab` 保存 `JComponent content` 而非仅 `JsonEditor`，对比页签可承载 `ConfigComparePanel`。
- `TabBar` 根据 tab 类型决定工具栏按钮可用性（对比页不允许直接推送）。

### 3. 历史版本数据模型

新增 `client.model.ConfigHistoryItem`：

```java
public class ConfigHistoryItem {
    private String id;              // 历史配置 ID
    private String lastId;          // 上一版本 ID
    private String dataId;
    private String group;
    private String tenant;
    private String content;
    private String md5;
    private String srcIp;
    private String srcUser;
    private String opType;          // 操作类型：I(插入)、U(更新)、D(删除)
    private String createdTime;
    private String lastModifiedTime;
}
```

### 4. NacosClient 扩展

在 `NacosClient` 中新增方法：

- `getConfigHistoryList(String namespaceId, String group, String dataId, Integer pageNo, Integer pageSize)`：
    - 调用 `NacosEndpoint#getConfigHistoryList` 获取历史版本列表。
    - 返回 `List<ConfigHistoryItem>`，按 `lastModifiedTime` 倒序排列。

- `getConfigHistory(String namespaceId, String group, String dataId, long nid)`：
    - 调用 `NacosEndpoint#getConfigHistory` 获取指定版本内容。
    - 返回 `ConfigHistoryItem`。

### 5. NacosToolWindow 集成

- 新增 `openCompareTab(ConfigFile remote, @Nullable Path localPath, String localContent, boolean includeHistory)`：
    - `includeHistory` 参数控制是否显示历史版本面板。
    - 若 `includeHistory = true`，异步加载历史版本列表并初始化 3 面板布局。
    - 组装 `ConfigComparePanel`，注入 `FileType`、本地/远程内容等。
    - 将 `ConfigComparePanel` 作为 tab content，传入 `TabBar#addTab`。
    - Tab 标题：`dataId + " (Compare)"`，支持 `*` 标记本地修改状态。

- `CompareConfigService` 调整：
    - 通过 `project.getUserData(TOOL_WINDOW_KEY)` 获取 `NacosToolWindow`。
    - 若 Tool Window 可用，调用 `openCompareTab`；否则回退到原 Diff 窗口（兼容旧行为）。
    - 新增方法：
        - `compareConfigurationsWithHistory(Project, ConfigFile, @Nullable Path, String)`：3 面板对比。
        - `compareConfigurations(Project, ConfigFile, @Nullable Path, String)`：2 面板对比（保持向后兼容）。
    - 入参扩展：支持传入 `ConfigFile`/文件路径，便于后续拓展。

### 6. 国际化与配置

- 在 `messages.properties` / `messages_zh_CN.properties` 添加：
    - `compare.tab.title={0} (Compare)`
    - `compare.toolbar.saveLocal` - 保存到本地按钮
    - `compare.panel.local` - 本地配置面板标题
    - `compare.panel.remote` - 云端配置面板标题
    - `compare.panel.history` - 历史版本面板标题
    - `compare.history.select.version` - 选择版本下拉框提示
    - `compare.history.loading` - 加载历史版本中提示
    - `compare.history.empty` - 无历史版本提示
    - `compare.history.version.format` - 版本显示格式（时间 + ID）
    - `compare.info.namespace/group/...` - 信息栏文本
    - `compare.error.local.save` - 保存失败错误提示
    - `compare.error.history.load` - 加载历史版本失败提示
- Panel 内所有可见文本使用 `NacosBundle.message`.

### 7. 数据流与同步

#### 2 面板对比流程（本地 vs 云端）

1. 用户触发对比（如"Compare with Nacos"）。
2. `CompareConfigService` 拉取远程内容，并定位本地 `VirtualFile`。
3. 若 Tool Window 可用：
    - 调用 `openCompareTab(remote, localPath, localContent, false)`。
    - Panel 初始化 2 个编辑器，并注册 DocumentListener 标记 Tab 修改状态。
4. 用户编辑完成后：
    - `保存到本地` -> 写入原文件，触发 `VirtualFile` 刷新。
    - 后续可使用已有推送逻辑发布。

#### 3 面板对比流程（本地 vs 云端 vs 历史版本）

1. 用户触发历史版本对比。
2. `CompareConfigService` 执行以下异步操作：
    - 拉取远程最新内容。
    - 定位本地 `VirtualFile`。
    - 调用 `NacosClient#getConfigHistoryList` 获取历史版本列表。
3. 若 Tool Window 可用：
    - 调用 `openCompareTab(remote, localPath, localContent, true)`。
    - Panel 初始化 3 个编辑器：
        - 左侧：本地配置（可编辑）。
        - 中间：云端最新配置（只读）。
        - 右侧：历史版本面板（只读），顶部显示版本选择下拉框。
    - 版本下拉框填充历史版本列表，默认选中第一个（最新历史版本）。
    - 异步加载默认选中版本的内容并更新右侧编辑器。
4. 用户选择历史版本：
    - 下拉框选择事件触发。
    - 显示"加载中"状态。
    - 异步调用 `NacosClient#getConfigHistory` 获取指定版本内容。
    - 更新右侧编辑器内容。
5. 用户编辑完成后：
    - `保存到本地` -> 写入原文件，触发 `VirtualFile` 刷新。
    - 后续可使用已有推送逻辑发布。

- `ui.toolwindow.NacosToolWindow` - 新增 `openCompareTab` 方法
- `ui.toolwindow.Tab` & `TabBar` - 支持对比类型 Tab

- 国际化资源文件 - 新增历史版本相关文本

## 测试计划

### 2 面板对比测试

1. **语法高亮**：针对 `.json/.yaml/.properties` 打开对比，确认左右编辑器语法正确。
2. **本地编辑**：
    - 修改左侧内容后保存，验证磁盘文件同步。
    - 对不存在文件的情况，确保保存按钮禁用或提供提示。
3. **Tab 行为**：
    - 同时打开多个 compare tab，切换/关闭无异常。
    - Tool Window 未打开时仍可回退到旧 Diff 行为。
4. **回退路径**：Tool Window 不可用或初始化失败时，Diff 弹窗正常展示。

### 3 面板对比测试

1. **历史版本列表加载**：
    - 打开 3 面板对比，验证历史版本列表正确加载。
    - 验证版本下拉框选项格式正确（时间 + ID）。
    - 验证版本按时间倒序排列。
2. **版本选择与内容加载**：
    - 选择不同历史版本，验证右侧编辑器内容正确更新。
    - 验证"加载中"状态提示正常显示和消失。
    - 验证加载失败时的错误提示。
3. **多面板布局**：
    - 验证 3 个面板的默认比例（各占 33.3%）。
    - 验证用户可以通过拖动分割线调整面板宽度。
    - 验证面板宽度调整后，编辑器内容正确显示。
4. **语法高亮一致性**：
    - 验证 3 个面板使用相同的 `FileType`，语法高亮一致。
5. **边界情况**：
    - 无历史版本时，验证下拉框显示"无历史版本"提示。
    - 历史版本加载失败时，验证错误提示和回退行为。
    - 网络异常时，验证错误处理和用户提示。

## 向后兼容性

1. **现有 API 保持不变**：
    - `CompareConfigService#compareConfigurations` 保持原有签名和行为。
    - 默认使用 2 面板对比，保持向后兼容。

2. **新增 API**：
    - `CompareConfigService#compareConfigurationsWithHistory` 用于 3 面板对比。
    - 调用方可根据需求选择使用 2 面板或 3 面板对比。

3. **回退机制**：
    - 若 Tool Window 不可用，自动回退到原有的 Diff 对话框。
    - 确保现有功能不受影响。

## 性能优化考虑

1. **历史版本列表加载**：
    - 默认只加载第一页（pageSize=100），满足大部分场景。
    - 若历史版本超过 100 个，考虑添加分页或"加载更多"功能（后续优化）。
    - 使用异步加载，避免阻塞 UI 线程。

2. **版本内容懒加载**：
    - 初始只加载默认选中版本的内容。
    - 用户选择其他版本时才加载对应内容，减少不必要的网络请求。

3. **编辑器性能**：
    - 大文件内容使用虚拟滚动（`EditorTextField` 已支持）。
    - 避免频繁刷新编辑器内容，只在版本切换时更新。
