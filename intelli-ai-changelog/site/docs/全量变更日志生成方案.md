## 1 功能概述

IntelliAI Changelog 插件提供了两种生成项目发布日志（Release Log）的方式：

1. **AI 生成**：基于 AI 模型分析 Git 提交记录，生成面向用户的发布说明
2. **Git-cliff 生成**：使用 git-cliff 工具自动解析 Conventional Commits 规范，生成结构化的变更日志

两种方式都支持：

- 基于 Git 标签（Tag）的范围生成
- 基于提交哈希（Hash）的范围生成
- 从项目根目录生成全量日志
- 从 Git Log 工具窗口选中提交生成增量日志
- 流式输出到工具窗口，实时查看生成进度

## 2 使用方法

### 2.1 方式一：从项目生成发布日志

1. **通过项目视图**：
    - 在项目视图中右键点击项目根目录或任意文件
    - 选择 `IntelliAI Changelog → 生成发布日志`

2. **通过主菜单**：
    - 菜单栏：`Tools → IntelliAI Changelog → 生成发布日志`

### 2.2 方式二：从 Git Log 生成发布日志

1. 打开 Git Log 工具窗口（`View → Tool Windows → Git`）
2. 选择一个或多个提交记录
3. 右键点击选中的提交
4. 选择 `IntelliAI Changelog → 生成发布日志`

### 2.3 配置发布日志生成方式

1. 打开设置：`Settings → Tools → IntelliAI Changelog`
2. 在 "Release Log" 面板中选择生成方式：
    - **⚡ AI**：使用 AI 模型生成（默认）
    - **⚡ git-cliff**：使用 git-cliff 工具生成

### 2.4 配置生成范围

在设置页面的 "Release Log" 面板中：

- **使用 Tag 作为起点**：从指定的 Git 标签开始生成
    - 首次使用会自动检测最新的标签
    - 生成后会自动更新 "Last used tag"
- **使用 Hash 作为起点**：从指定的提交哈希开始生成
    - 生成后会自动更新 "Last used hash"
- **清除 Tag 和 Hash**：清空已保存的起点信息，下次生成时将生成全量日志

### 2.5 查看生成结果

生成完成后，结果会自动显示在 `IntelliAI Changelog` 工具窗口中：

- 支持实时流式输出，边生成边查看
- 支持复制全部内容
- 支持编辑和保存

## 3 技术选型

### 3.1 AI 生成方式

**优势**：

- 生成面向用户的自然语言描述
- 能够理解提交意图，生成更易读的发布说明
- 支持自定义提示词模板
- 自动过滤无意义的提交

**适用场景**：

- 需要面向用户的发布说明
- 提交记录不够规范，需要 AI 理解语义
- 需要自定义输出格式和风格

### 3.2 Git-cliff 生成方式

**优势**：

- 基于 Conventional Commits 规范，输出格式统一
- 性能高，无需调用 AI 服务
- 支持丰富的配置选项（Tera 模板）
- 自动分类提交（Features、Bug Fixes、Refactor 等）

**适用场景**：

- 项目遵循 Conventional Commits 规范
- 需要快速生成，不依赖网络
- 需要标准化的输出格式

### 3.3 技术栈

- **Git 操作**：JGit（Eclipse JGit）
- **AI 服务**：通过 `intelli-ai-engine` 插件提供的统一 AI 服务接口
- **Git-cliff**：Rust 编写的命令行工具，通过进程调用
- **UI 框架**：IntelliJ Platform UI（Swing）
- **网络请求**：IntelliJ Platform `HttpRequests` API
- **压缩解压**：Apache Commons Compress（tar.gz）、Java Zip API（zip）

## 4 架构设计

### 4.1 类层次结构

```
AbstractReleaseLogAction (抽象基类)
├── GenerateReleaseLogFromProjectAction (项目入口)
└── GenerateReleaseLogFromGitLogAction (Git Log 入口)
```

### 4.2 核心组件

1. **AbstractReleaseLogAction**：抽象基类，封装通用生成逻辑
2. **ChangelogService**：服务层，负责 Git 操作和 AI 调用
3. **GitCliffRunner**：执行 git-cliff 工具
4. **GitCliffDownloadManager**：管理 git-cliff 的下载和安装
5. **GitCliffBinaryResolver**：解析 git-cliff 二进制文件路径
6. **ChangelogToolWindowService**：工具窗口输出服务
7. **SettingsState**：配置管理

### 4.3 数据流

```
用户触发动作
    ↓
AbstractReleaseLogAction.generate()
    ↓
判断生成方式（AI / git-cliff）
    ↓
┌─────────────────┬─────────────────┐
│   AI 生成路径    │  Git-cliff 路径  │
├─────────────────┼─────────────────┤
│ ChangelogService│ GitCliffRunner  │
│ .generateRelease│ .run()          │
│ LogByAiStream() │                 │
│       ↓         │       ↓         │
│ 读取 Git 提交    │ 执行 git-cliff   │
│ 构建 Prompt     │ 进程并捕获输出   │
│ 调用 AI 服务    │                 │
│ 流式输出        │ 流式输出        │
└─────────────────┴─────────────────┘
    ↓
ChangelogToolWindowService
    ↓
工具窗口显示结果
```

## 5 实现细节

### 5.1 AI 提供者生成发布日志

#### 5.1.1 读取 Git 提交记录

**位置**：`ChangelogService.readCommitsFromRange()`

```java
private List<CommitInfo> readCommitsFromRange(@NotNull Path gitRoot, @Nullable String range)
```

**实现逻辑**：

- 使用 JGit 打开 Git 仓库
- 根据范围字符串（如 `tag..HEAD`）或空范围读取提交
- 解析每个提交的哈希、消息、日期、作者等信息
- 返回 `CommitInfo` 列表

**范围格式**：

- `tag..HEAD`：从指定标签到 HEAD
- `hash1..hash2`：两个提交之间的范围
- `null`：全量提交

#### 5.1.2 构建 AI Prompt

**位置**：`ChangelogService.buildReleaseLogPrompt()`

**Prompt 模板**：从 `SettingsState.aiReleaseLogPrompt` 获取，默认模板包含：

```java
请根据以下 Git 提交记录生成项目 Release Log。

要求：
1. 将提交记录分类到以下类别（使用二级标题，格式与 git-cliff 保持一致）：
   - ## ✨ Features（新功能）
   - ## 🐛 Bug Fixes（问题修复）
   - ## ♻️ Refactor（代码重构）
   - ## 📚 Documentation（文档更新）
   - ## ⚡ Performance（性能优化）
   - ## ✅ Tests（测试相关）
   - ## 📦 Build（构建相关）
   - ## 🔧 Chore（其他改进）
   - ## 🔄 CI（CI/CD 相关）
   - ## ⚙️ Miscellaneous Tasks（其他任务）
2. 每个条目应重写为简洁、易读的描述，删除提交信息中的类型前缀（如 feat:、fix: 等）。
3. 删除无意义或琐碎的提交（例如"更新代码"、"合并分支"、"chore: update"等）。
4. 严格按照 Markdown 格式输出...
```

**提交记录格式化**：

- 按日期分组提交记录
- 格式：`### yyyy-MM-dd\n\n- 提交消息\n`

#### 5.1.3 调用 AI 服务

**位置**：`ChangelogService.callAIServiceStreamForChangelog()`

**实现流程**：

1. 构建 `AIChatRequest`（包含系统提示词和用户提示词）
2. 获取 AI 服务配置（`SettingsState.providerConfig`）
3. 调用 `AIService.generateContentStream()` 进行流式生成
4. 通过 `AIStreamResponseListener` 接收生成结果
5. 实时输出到工具窗口

**系统提示词**：从 `SettingsState.systemPrompt` 获取，默认使用 `SettingsState.getDefaultSystemPrompt()`

#### 5.1.4 格式化输出

**位置**：`CommitMessageFormatter.format()`

**处理内容**：

- 中英文之间添加空格（使用 Pangu）
- 删除代码围栏标记（```）
- 将中文标点替换为英文标点

### 5.2 Git-cliff 生成发布日志

#### 5.2.1 检查 git-cliff 是否安装

**位置**：`GitCliffDownloadManager.isInstalled()`

**检查逻辑**：

- 检查 `${home}/.zeka-stack/plugin/changelog/git-cliff` 目录
- 检查二进制文件是否存在：
    - macOS/Linux：`git-cliff`
    - Windows：`git-cliff.exe`

#### 5.2.2 构建 git-cliff 命令

**位置**：`AbstractReleaseLogAction.buildGitCliffArgs()`

**参数构建逻辑**：

- 如果提供了范围字符串，直接使用
- 如果使用 Tag 作为起点：
    - 有 `lastUsedTag`：使用 `tag..HEAD`
    - 无 `lastUsedTag`：使用 `--latest`（从最新标签开始）
- 如果使用 Hash 作为起点：
    - 有 `lastUsedHash`：使用 `hash..HEAD`
    - 无：返回空列表（生成全量）

#### 5.2.3 执行 git-cliff

**位置**：`GitCliffRunner.run()`

**执行流程**：

1. 构建命令列表：`[binary, -c, configPath, ...args]`
2. 如果提供了配置字符串，创建临时 TOML 配置文件
3. 使用 `ProcessBuilder` 启动进程
4. 在 Git 仓库根目录执行
5. 实时读取标准输出并流式输出到工具窗口
6. 等待进程完成，检查退出码
7. 格式化输出结果（去除代码围栏、标点转换等）

**配置格式**：TOML 格式，包含：

- `[changelog]`：输出格式配置（header、body、footer）
- `[git]`：Git 解析配置（conventional_commits、commit_parsers）

**默认配置**：从 `SettingsState.getDefaultGitCliffConfig()` 获取

#### 5.2.4 输出格式化

生成完成后，使用 `CommitMessageFormatter.format()` 对输出进行格式化处理。

### 5.3 Git-cliff 二进制下载与安装

#### 5.3.1 下载触发时机

**位置**：`ChangelogSettingsPanel.checkAndDownloadGitCliff()`

**触发条件**：

- 用户在设置页面选择 "git-cliff" 单选框
- 本地未安装 git-cliff（`GitCliffDownloadManager.isInstalled()` 返回 false）

#### 5.3.2 下载流程

**位置**：`GitCliffDownloadManager.downloadAndInstall()`

**完整流程**：

```
检查是否已安装
    ↓ 否
检查本地压缩包（dists 目录）
    ↓
┌─────────────────┬─────────────────┐
│  找到本地压缩包  │  未找到压缩包    │
├─────────────────┼─────────────────┤
│ 尝试本地安装    │ 从 GitHub 下载   │
│ installFromLocal│ fetchLatestVersion│
│ Package()       │ downloadPackage()│
│       ↓         │       ↓         │
│   安装成功？    │   下载成功？     │
│       ↓         │       ↓         │
│   是：完成      │   是：解压安装   │
│   否：继续下载  │ extractPackage()│
└─────────────────┴─────────────────┘
    ↓
更新 UI（显示版本号）
```

#### 5.3.3 获取最新版本

**位置**：`GitCliffDownloadManager.fetchLatestVersion()`

**实现**：

- 调用 GitHub API：`https://api.github.com/repos/orhun/git-cliff/releases/latest`
- 解析 JSON 响应，提取 `tag_name` 字段
- 超时设置：连接超时 3 秒，读取超时 3 秒

**示例响应**：

```json
{
  "tag_name": "v2.11.0",
  ...
}
```

#### 5.3.4 生成压缩包名称

**位置**：`GitCliffDownloadManager.generatePackageName()`

**命名规则**：

```
git-cliff-{version}-{arch}-{os}-{toolchain}.{ext}
```

**平台映射**：

| 操作系统    | 架构      | 工具链               | 扩展名     | 示例                                                  |
|---------|---------|-------------------|---------|-----------------------------------------------------|
| macOS   | aarch64 | apple-darwin      | .tar.gz | `git-cliff-2.11.0-aarch64-apple-darwin.tar.gz`      |
| macOS   | x86_64  | apple-darwin      | .tar.gz | `git-cliff-2.11.0-x86_64-apple-darwin.tar.gz`       |
| Windows | aarch64 | pc-windows-msvc   | .zip    | `git-cliff-2.11.0-aarch64-pc-windows-msvc.zip`      |
| Windows | x86_64  | pc-windows-msvc   | .zip    | `git-cliff-2.11.0-x86_64-pc-windows-msvc.zip`       |
| Linux   | aarch64 | unknown-linux-gnu | .tar.gz | `git-cliff-2.11.0-aarch64-unknown-linux-gnu.tar.gz` |
| Linux   | x86_64  | unknown-linux-gnu | .tar.gz | `git-cliff-2.11.0-x86_64-unknown-linux-gnu.tar.gz`  |

**架构规范化**：

- `aarch64` / `arm64` → `aarch64`
- `x86_64` / `amd64` → `x86_64`

#### 5.3.5 下载压缩包

**位置**：`GitCliffDownloadManager.downloadPackage()`

**实现细节**：

- 使用 IntelliJ Platform `HttpRequests` API
- 超时设置：连接超时 5 秒，读取超时 30 秒
- 下载到：`${home}/.zeka-stack/plugin/changelog/dists/`
- 支持进度回调（`DownloadProgressListener`）
- 使用 8KB 缓冲区逐块下载

#### 5.3.6 解压安装

**位置**：`GitCliffDownloadManager.extractPackage()`

**解压逻辑**：

**tar.gz 文件**（macOS/Linux）：

1. 使用 `GzipCompressorInputStream` 解压 gzip
2. 使用 `TarArchiveInputStream` 读取 tar 归档
3. 跳过顶层目录（如果存在）
4. 提取所有文件到目标目录
5. 设置可执行权限（非 Windows）

**zip 文件**（Windows）：

1. 使用 `ZipInputStream` 读取 zip 归档
2. 跳过顶层目录（如果存在）
3. 提取所有文件到目标目录
4. Windows 不需要设置可执行权限

**目标目录**：`${home}/.zeka-stack/plugin/changelog/git-cliff/`

**顶层目录处理**：

- 如果压缩包内包含 `git-cliff-{version}/` 目录，自动跳过
- 直接提取二进制文件到目标目录根目录

#### 5.3.7 本地压缩包优先策略

**位置**：`GitCliffDownloadManager.findLocalPackage()`

**查找逻辑**：

1. 扫描 `dists` 目录
2. 匹配当前系统架构和操作系统
3. 匹配文件扩展名（.tar.gz 或 .zip）
4. 返回第一个匹配的压缩包

**优势**：

- 避免重复下载
- 支持离线安装
- 提高安装速度

#### 5.3.8 版本检测

**位置**：`GitCliffDownloadManager.getInstalledVersion()`

**实现**：

- 执行 `git-cliff --version` 命令
- 解析输出，提取版本号（如 `git-cliff 2.11.0`）
- 返回版本字符串

**UI 更新**：

- 安装成功后，动态更新单选框文本：`⚡ git-cliff (2.11.0)`

### 5.4 跨平台适配

#### 5.4.1 系统检测

**使用 IntelliJ Platform API**：

- `SystemInfo.isMac`：检测 macOS
- `SystemInfo.isWindows`：检测 Windows
- `System.getProperty("os.arch")`：获取系统架构

#### 5.4.2 架构规范化

**位置**：`GitCliffDownloadManager.normalizeArch()`

**映射规则**：

```java
"aarch64" / "arm64" → "aarch64"
"x86_64" / "amd64" → "x86_64"
其他 → 原样返回
```

#### 5.4.3 二进制文件路径

**位置**：`GitCliffDownloadManager.getBinaryPath()`

**路径规则**：

- macOS/Linux：`{gitCliffDir}/git-cliff`
- Windows：`{gitCliffDir}/git-cliff.exe`

#### 5.4.4 可执行权限

**位置**：`GitCliffBinaryResolver.resolve()`

**处理逻辑**：

- macOS/Linux：调用 `binary.toFile().setExecutable(true)`
- Windows：跳过（不需要）

#### 5.4.5 压缩格式

- macOS/Linux：`.tar.gz`
- Windows：`.zip`

#### 5.4.6 进程执行

**位置**：`GitCliffRunner.run()`

**跨平台兼容**：

- 使用 `ProcessBuilder`，自动处理路径分隔符
- Windows 自动处理 `.exe` 扩展名
- 统一使用 UTF-8 编码读取输出

## 6 配置说明

### 6.1 Release Log 生成方式

**配置项**：`SettingsState.releaseLog`

**类型**：`ReleaseLogProvider` 枚举

- `AI`：使用 AI 生成（默认）
- `GIT_CLIFF`：使用 git-cliff 生成

### 6.2 Git-cliff 配置

**配置项**：`SettingsState.gitCliffConfig`

**格式**：TOML 格式

**默认配置**：

```toml
[changelog]
header = ""
body = "{% for group, commits in commits | group_by(attribute=\"group\") %}
{% if group == \"Features\" %}
## ✨ Features\n
{% elif group == \"Bug Fixes\" %}
## 🐛 Bug Fixes\n
...
{% endfor %}"
footer = ""

[git]
conventional_commits = true
filter_unconventional = false
split_commits = false
commit_parsers = [
  { message = "^feat", group = "Features" },
  { message = "^fix", group = "Bug Fixes" },
  ...
  { message = ".*", group = "Miscellaneous Tasks" }
]
```

### 6.3 AI Release Log 提示词

**配置项**：`SettingsState.aiReleaseLogPrompt`

**默认提示词**：见 `SettingsState.getDefaultAiReleaseLogPrompt()`

**占位符**：

- `{commits}`：提交记录列表（按日期分组）
- `{version}`：版本号（默认 "Unreleased"）
- `{date}`：当前日期（yyyy-MM-dd）

### 6.4 起点配置

**使用 Tag 作为起点**：`SettingsState.useTagAsStart`（boolean）
**最近使用的 Tag**：`SettingsState.lastUsedTag`（String）
**最近使用的 Hash**：`SettingsState.lastUsedHash`（String）

## 7 异常处理

### 7.1 Git 仓库不存在

- **检测**：`resolveGitRoot()` 返回 null
- **处理**：显示错误通知，提示用户初始化 Git 仓库

### 7.2 Git-cliff 未安装

- **检测**：`GitCliffDownloadManager.isInstalled()` 返回 false
- **处理**：
    - 设置页面：自动触发下载
    - 动作执行：显示错误通知，提示用户先安装

### 7.3 下载失败

- **网络超时**：连接超时 5 秒，读取超时 30 秒
- **处理**：显示错误对话框，提示用户检查网络或手动下载

### 7.4 解压失败

- **处理**：删除已下载的压缩包，提示用户重试

### 7.5 AI 服务调用失败

- **处理**：显示错误通知，包含详细错误信息
- **降级**：保留已采集的提交记录，支持重试

### 7.6 Git-cliff 执行失败

- **检测**：进程退出码非零
- **处理**：抛出异常，显示错误通知

### 7.7 无有效提交

- **处理**：输出空结果或提示"无更新"

---

## 8 总结

IntelliAI Changelog 的发布日志生成功能提供了两种互补的生成方式：

1. **AI 生成**：适合需要面向用户的自然语言描述，能够理解提交语义
2. **Git-cliff 生成**：适合遵循 Conventional Commits 规范的项目，输出格式统一
