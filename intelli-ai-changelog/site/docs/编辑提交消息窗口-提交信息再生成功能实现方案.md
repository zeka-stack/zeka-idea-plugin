# 编辑提交消息窗口提交信息再生成功能实现方案

## 背景

在 Commit 工具窗口的历史列表中使用“编辑提交消息”时，会打开专用编辑对话框。当前 IntelliAI Changelog 的“生成提交信息”动作在该对话框内可见，但由于缺少提交面板变更上下文（
`CommitWorkflowHandler`），点击后不生效。

## 目标

- 在“编辑提交消息”对话框中基于**已提交记录的真实 diff**重新生成提交信息。
- 支持单条提交记录（符合当前 UI 行为）。
- 生成结果直接写入对话框中的提交消息编辑器。

## 非目标

- 不支持多条提交记录的批量生成。
- 不改变现有提交面板（未提交变更）生成流程。
- 不更改 AI 模型配置与模板结构。

## 方案概述

1. **识别上下文**：在 `GenerateCommitMessageAction` 中增加对 `VcsLogCommitSelection` 的兼容处理。
2. **获取真实 diff**：通过 `ChangelogGitService.readCommitDiffs()` 获取指定提交的 unified diff 文本。
3. **构建提交信息 prompt**：新增 `ChangelogPromptBuilder` 方法，将 Git diff 转换为结构化 JSON + raw patch + diff summary，占位符沿用现有模板
   `{codeDiffs}` / `{rawPatch}` / `{diffSummary}`。
4. **生成与写入**：新增 `ChangelogService.generateCommitMessageFromGitLogStream()`（或等价非流式方法），在 `CommitMessageGenerator` 中复用流式
   UI 与写入逻辑。

## 实现细节

### 1) Action 逻辑分支

- 现有分支：`CommitWorkflowHandler` 存在 → 使用未提交变更生成（保持不变）。
- 新增分支：当 `CommitWorkflowHandler` 为空时，尝试从 `VcsLogDataKeys.VCS_LOG_COMMIT_SELECTION` 获取选中提交。
    - 若无选择或选择数量≠1 → 给出提示并退出。
    - 若有且为单条 → 进入“历史提交再生成”流程。

### 2) 提交 diff 解析

- 基于 `ChangelogGitService.readCommitDiffs()` 返回的 `diffText`。
- 解析规则：
    - `diff --git a/... b/...` 作为文件分隔。
    - 统计 `+`/`-` 行数（排除 `+++`、`---`）。
    - 根据 `new file mode`/`deleted file mode`/`rename from` 判断变更类型（默认 `MODIFY`）。

### 3) Prompt 构建

- 新增 `ChangelogPromptBuilder.buildCommitMessagePromptFromCommitDiffs(...)`：
    - `codeDiffs`：构建简化 JSON（项目名、分支、统计、文件级 diff）。
    - `rawPatch`：拼接原始 diff 文本（必要时截断）。
    - `diffSummary`：按文件级统计生成简要摘要。
- 保持模板不变，避免影响用户自定义提示词。

### 4) 生成与写入

- 新增 `ChangelogService.generateCommitMessageFromGitLogStream(...)` 以复用流式输出。
- `CommitMessageGenerator` 新增 `generateForCommitHash(...)`，复用现有 typing indicator 与写入逻辑。

## 测试计划

- 在 Commit 工具窗口历史列表选择单条提交 → 右键“编辑提交消息” → 在对话框点击“生成提交信息”，应写入新消息。
- 在未提交变更的 Commit 面板点击“生成提交信息”，行为不变。

## 风险与回退

- 风险：部分 Git diff 内容较大，可能导致 prompt 过长。
- 处理：在 prompt 构建时限制长度并保留结构化摘要。
- 回退：保留原分支逻辑，如解析失败则提示并退出，不影响现有功能。
