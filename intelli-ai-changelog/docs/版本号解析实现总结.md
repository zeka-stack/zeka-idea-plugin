# 版本号解析功能实现总结

## 问题排查结果

### 问题原因

在 `ChangelogPromptBuilder.java` 中，版本号被硬编码为固定值：

1. **第 89 行**：`buildChangelogPrompt` 方法中版本号硬编码为 `"v1.0.0"`
2. **第 126 行**：`buildReleaseLogPrompt` 方法中版本号硬编码为 `"Unreleased"`

这导致每次生成 Release Log 时，版本号都是一样的。

## 解决方案

### 1. 创建版本号解析器

创建了 `ProjectVersionResolver` 工具类（
`intelli-ai-changelog/src/main/java/dev/dong4j/zeka/stack/idea/plugin/changelog/util/ProjectVersionResolver.java`），支持从多种来源自动解析项目版本号。

### 2. 解析策略（按优先级）

1. **Maven 项目**：从 `pom.xml` 读取版本号
    - 优先使用 IntelliJ Maven 插件 API（如果可用）
    - 备用方案：直接解析 `pom.xml` 文件

2. **Gradle 项目**：从 `build.gradle` 或 `build.gradle.kts` 读取版本号
    - 优先使用 IntelliJ Gradle 插件 API（如果可用）
    - 备用方案：直接解析 `build.gradle` 文件

3. **Git 标签**：从最新 Git 标签读取版本号
    - 使用 JGit 库获取所有标签
    - 按提交时间排序，选择最新的标签

4. **默认值**：如果所有方式都失败，使用 `"Unreleased"`

### 3. 特性

- **可选性**：所有解析方式都是可选的，如果失败会静默返回 `null`，不影响插件正常使用
- **优雅降级**：即使 Maven/Gradle 插件不可用，也能通过直接文件解析获取版本号
- **版本号规范化**：自动去除 `v` 前缀，统一版本号格式
- **线程安全**：所有方法都是静态方法，无状态，线程安全

### 4. 修改的文件

1. **新增文件**：
    - `intelli-ai-changelog/src/main/java/dev/dong4j/zeka/stack/idea/plugin/changelog/util/ProjectVersionResolver.java`
    - `intelli-ai-changelog/docs/版本号解析技术方案.md`
    - `intelli-ai-changelog/docs/版本号解析实现总结.md`

2. **修改文件**：
    - `intelli-ai-changelog/src/main/java/dev/dong4j/zeka/stack/idea/plugin/changelog/service/ChangelogPromptBuilder.java`
        - 在 `buildChangelogPrompt` 方法中使用 `ProjectVersionResolver.resolveVersion(project)` 替换硬编码的 `"v1.0.0"`
        - 在 `buildReleaseLogPrompt` 方法中使用 `ProjectVersionResolver.resolveVersion(project)` 替换硬编码的 `"Unreleased"`

## 使用说明

### 自动解析

版本号解析是自动的，无需用户配置。插件会按优先级顺序尝试不同的解析方式：

1. 如果是 Maven 项目，从 `pom.xml` 读取
2. 如果是 Gradle 项目，从 `build.gradle` 或 `build.gradle.kts` 读取
3. 如果有 Git 标签，从最新标签读取
4. 否则使用默认值 `"Unreleased"`

### 示例

假设项目是 Maven 项目，`pom.xml` 中版本号为 `1.2.3`：

```xml
<project>
    <version>1.2.3</version>
</project>
```

生成 Release Log 时，`{version}` 占位符会被替换为 `1.2.3`。

如果项目是 Gradle 项目，`build.gradle` 中版本号为 `2.0.0-SNAPSHOT`：

```gradle
version = '2.0.0-SNAPSHOT'
```

生成 Release Log 时，`{version}` 占位符会被替换为 `2.0.0-SNAPSHOT`。

如果项目有 Git 标签 `v3.0.0`，生成 Release Log 时，`{version}` 占位符会被替换为 `3.0.0`（自动去除 `v` 前缀）。

## 技术细节

### Maven 版本号解析

- **插件 API 方式**：使用反射调用 `MavenProjectsManager.getInstance(project).getRootProjects()` 获取根项目版本号
- **文件解析方式**：使用正则表达式 `"<version>([^<]+)</version>"` 匹配版本号，并跳过 `<parent>` 标签内的版本号

### Gradle 版本号解析

- **插件 API 方式**：使用反射调用 `ExternalProjectsManager` 和 `ProjectDataManager` 获取项目版本号
- **文件解析方式**：
    - 对于 `build.gradle`：使用正则表达式 `"(?:^|\\s)(?:version\\s*[=:]\\s*['\"]?)([^'\"\\s,]+)(?:['\"]?)(?:\\s|$)"`
    - 对于 `build.gradle.kts`：使用正则表达式 `"(?:^|\\s)(?:version\\s*[=:]\\s*[\"'])([^\"']+)(?:[\"'])(?:\\s|$)"`

### Git 标签解析

- 使用 JGit 库获取所有标签
- 使用 `RevWalk` 解析每个标签对应的提交时间
- 按提交时间排序，选择最新的标签
- 自动去除 `v` 前缀

## 注意事项

1. **插件依赖**：Maven/Gradle 插件 API 方式需要用户安装相应的插件，但这不是必需的，插件会优雅降级到文件解析方式

2. **性能**：版本号解析是轻量级操作，不会影响插件性能

3. **错误处理**：所有解析方法都使用 try-catch 静默处理异常，确保即使解析失败也不会影响插件正常使用

4. **缓存**：当前实现没有缓存机制，每次调用都会重新解析。如果未来需要优化性能，可以考虑添加缓存

    - 创建非 Maven/Gradle 项目，且没有 Git 标签
    - 生成 Release Log，验证是否使用默认值 `"Unreleased"`

## 后续优化建议

2. **添加缓存机制**：缓存解析结果，避免重复解析

3. **支持更多项目类型**：支持 npm、Python 等其他项目类型的版本号解析

4. **版本号格式验证**：验证解析出的版本号是否符合语义化版本规范

5. **用户提示**：在设置页面显示当前解析到的版本号，方便用户确认
