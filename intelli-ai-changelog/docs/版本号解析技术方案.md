# 版本号解析技术方案

## 问题描述

当前在生成 Release Log 时，版本号被硬编码为固定值（`"v1.0.0"` 或 `"Unreleased"`），导致每次生成的版本号都是一样的。需要实现一个智能的版本号解析机制，能够从项目配置文件中自动读取版本号。

## 需求分析

1. **支持多种项目类型**：
    - Maven 项目（从 `pom.xml` 读取）
    - Gradle 项目（从 `build.gradle` 或 `build.gradle.kts` 读取）

2. **可选性**：
    - 用户可能没有安装 Maven 或 Gradle 插件
    - 项目可能不是 Maven/Gradle 项目
    - 需要优雅降级，不能影响插件正常使用

3. **优先级策略**：
    - 优先从项目配置文件读取（Maven > Gradle）
    - 其次从 Git 标签读取最新版本
    - 最后使用默认值（可配置）

## 技术方案

### 1. 架构设计

创建一个 `ProjectVersionResolver` 工具类，采用策略模式，按优先级顺序尝试不同的版本号获取方式。

```
ProjectVersionResolver
├── resolveVersion(Project) -> String
├── resolveFromMaven(Project) -> String?
├── resolveFromGradle(Project) -> String?
├── resolveFromGitTag(Project) -> String?
└── getDefaultVersion() -> String
```

### 2. 实现策略

#### 2.1 Maven 项目版本号读取

**方式一：使用 IntelliJ Maven 插件 API（推荐）**

- 检查 `MavenProjectsManager` 是否可用
- 获取项目的 Maven 项目列表
- 从根模块的 `pom.xml` 读取 `<version>` 标签

**方式二：直接解析 pom.xml 文件（备用）**

- 如果 Maven 插件不可用，直接读取项目根目录的 `pom.xml`
- 使用简单的 XML 解析或正则表达式提取版本号

**优点**：

- 方式一：准确、可靠，支持多模块项目
- 方式二：不依赖插件，兼容性好

**缺点**：

- 方式一：需要用户安装 Maven 插件
- 方式二：可能无法正确处理复杂的 pom.xml（继承、属性替换等）

#### 2.2 Gradle 项目版本号读取

**方式一：使用 IntelliJ Gradle 插件 API（推荐）**

- 检查 `GradleProjectSettings` 是否可用
- 获取项目的 Gradle 项目信息
- 从 `build.gradle` 或 `build.gradle.kts` 读取 `version` 属性

**方式二：直接解析 build.gradle 文件（备用）**

- 如果 Gradle 插件不可用，直接读取项目根目录的 `build.gradle` 或 `build.gradle.kts`
- 使用正则表达式提取版本号

**优点**：

- 方式一：准确、可靠，支持 Gradle DSL
- 方式二：不依赖插件，兼容性好

**缺点**：

- 方式一：需要用户安装 Gradle 插件
- 方式二：可能无法正确处理复杂的 Gradle 脚本（变量、函数等）

#### 2.3 Git 标签版本号读取

- 使用 JGit 库（项目已依赖）读取 Git 仓库信息
- 获取最新的 Git 标签
- 提取版本号（去除 `v` 前缀等）

**优点**：

- 不依赖项目构建系统
- 适用于所有 Git 项目

**缺点**：

- 需要项目是 Git 仓库
- 标签格式可能不统一

#### 2.4 默认版本号

- 如果所有方式都失败，使用默认值
- 默认值可以在设置中配置，或使用 `"Unreleased"`

### 3. 实现细节

#### 3.1 依赖检查

使用反射或 try-catch 机制检查相关插件是否可用：

```java
private boolean isMavenPluginAvailable() {
    try {
        Class.forName("org.jetbrains.idea.maven.project.MavenProjectsManager");
        return true;
    } catch (ClassNotFoundException e) {
        return false;
    }
}

private boolean isGradlePluginAvailable() {
    try {
        Class.forName("com.intellij.openapi.externalSystem.service.project.manage.ExternalProjectsManager");
        return true;
    } catch (ClassNotFoundException e) {
        return false;
    }
}
```

#### 3.2 版本号格式规范化

- 去除 `v` 前缀（如 `v1.0.0` -> `1.0.0`）
- 处理 SNAPSHOT 版本（如 `1.0.0-SNAPSHOT` -> `1.0.0-SNAPSHOT`）
- 支持语义化版本号（如 `1.2.3`）

#### 3.3 缓存机制

- 版本号解析结果可以缓存，避免重复解析
- 当项目文件发生变化时，清除缓存

### 4. 使用示例

```java
ProjectVersionResolver resolver = new ProjectVersionResolver();
String version = resolver.resolveVersion(project);
// version 可能是: "1.0.0", "1.2.3-SNAPSHOT", "Unreleased" 等
```

### 5. 配置选项

在 `SettingsState` 中添加配置项：

```java
/**
 * 版本号解析策略
 * <p>
 * AUTO: 自动检测（Maven > Gradle > Git Tag > 默认值）
 * MANUAL: 手动指定版本号
 * GIT_TAG: 仅从 Git 标签读取
 * DEFAULT: 使用默认值（Unreleased）
 */
public enum VersionResolutionStrategy {
    AUTO,
    MANUAL,
    GIT_TAG,
    DEFAULT
}

/**
 * 手动指定的版本号（当策略为 MANUAL 时使用）
 */
public String manualVersion = "";

/**
 * 默认版本号（当所有方式都失败时使用）
 */
public String defaultVersion = "Unreleased";
```

### 6. 错误处理

- 所有解析方法都应该静默失败，返回 `null`
- 使用日志记录调试信息，但不向用户显示错误
- 确保即使所有方式都失败，也能返回默认值

### 7. 性能考虑

- 版本号解析应该在后台线程执行
- 使用缓存避免重复解析
- 解析失败时快速降级到默认值

## 实施计划

1. **阶段一：基础实现**
    - 创建 `ProjectVersionResolver` 类
    - 实现直接文件解析方式（不依赖插件）
    - 实现 Git 标签读取
    - 集成到 `ChangelogPromptBuilder`

2. **阶段二：插件集成**
    - 实现 Maven 插件 API 集成
    - 实现 Gradle 插件 API 集成
    - 添加依赖检查机制

3. **阶段三：配置和优化**
    - 添加设置页面配置项
    - 实现缓存机制
    - 性能优化

4. **阶段四：测试和文档**
    - 单元测试
    - 集成测试
    - 更新用户手册

## 风险评估

1. **依赖插件风险**：如果用户没有安装 Maven/Gradle 插件，相关功能不可用（已通过备用方案解决）
2. **解析准确性风险**：直接文件解析可能无法处理复杂情况（已通过插件 API 优先策略解决）
3. **性能风险**：文件解析和 Git 操作可能较慢（已通过缓存机制解决）

## 总结

本方案采用多层次的版本号解析策略，既支持从项目配置文件自动读取版本号，又保证了在插件不可用时的兼容性。通过优先级策略和优雅降级，确保功能稳定可靠。
