⚙️ 三、功能设计

🎯 1. 主功能：AI 生成更新日志

操作入口：
• 在 IDEA 的 Git 工具窗口中，右键选中提交范围 → “💡 Generate Changelog with AI”
• 或通过菜单 “Tools → IntelliChangelog Generator”

核心流程：
1. 用户选择一个提交区间（两个 tag / 两个 commit / 某个 branch）。
2. 插件读取该区间内的提交记录（git log）。
3. AI 根据 commit 内容（及 diff 摘要）生成：
• 概要说明（Summary）
• 分类变更（Features / Fixes / Refactors / Docs / Chores）
• 可能的 Breaking Changes
• Markdown 输出

示例输出：

## 🚀 v2.4.0 (2025-11-10)

### ✨ Features

- Added user notification system with async email queue
- Introduced dynamic configuration refresh via API

### 🐞 Bug Fixes

- Fixed null pointer in UserService when profile is missing
- Resolved duplicate message issue in Kafka consumer

### 🧹 Refactor

- Simplified transaction management logic
- Optimized query builder for order module

### ⚠️ Breaking Changes

- `UserApi` endpoint `/v1/user/register` changed to `/api/user/register`

🧠 三、Prompt 模板设计

🔹 (1) System Prompt — “角色定义层”

You are an experienced software release manager and technical writer.
Your goal is to generate clear, structured, and concise changelogs
for software projects based on Git commit messages.
You always output well-formatted Markdown with consistent sections.

✅ 提示模型角色 → 避免出现闲聊或非 Markdown 输出。
✅ 保证语气正式、技术向。

⸻

🔹 (2) Instruction Prompt — “任务描述层”

英文版：

Please generate a release changelog based on the following Git commits.

Requirements:

1. Classify the commits into the following categories:
    - Features
    - Bug Fixes
    - Refactors
    - Documentation
    - Chores / Others
2. Each entry should be rewritten as a concise human-readable description.
3. Remove meaningless or trivial commits (e.g., "update code", "merge branch").
4. Format the output strictly as Markdown:
    - Use level-2 heading for version and date
    - Use level-3 heading for each category
5. Keep sentences short, objective, and technical.
6. If the language is set to Chinese, output all text in Simplified Chinese.
7. Do not include explanations or notes outside of Markdown.

中文指令版（当用户选择中文输出时使用）：

请根据以下 Git 提交信息生成一份结构化的版本更新日志（Changelog）。

要求：

1. 按以下类别分组：
    - 新增功能 (Features)
    - 问题修复 (Fixes)
    - 重构优化 (Refactors)
    - 文档更新 (Docs)
    - 其他改动 (Others)
2. 每条描述请转化为自然语言，简洁明了。
3. 忽略无意义的提交（如“update code”、“merge branch”）。
4. 输出严格遵循 Markdown 格式：
    - 二级标题为版本号和日期
    - 三级标题为类别
5. 不要添加除 Markdown 之外的任何额外说明。

在此层注入用户选择的实际内容，包括：

Date: 2025-11-11

- feat: add async event queue for notification system
- fix: npe in user service
- refactor: simplify job scheduling
- doc: update README
- chore: bump dependency version

💡 插件端可通过 JGit 自动格式化为 bullet 列表，限制总 token 长度（截断或分批发送）。

📦 四、上下文组织策略

为了保证性能与准确性：

策略 说明
提交摘要化 对 diff 内容进行摘要提取（仅保留修改文件路径 + 首句 message）
长度控制 超过 300 条 commit 时分批生成（每批按类别合并）
补充上下文 若用户提供模块结构或项目说明，可在 prompt 开头补一句：“This project is a microservice platform containing user, order, and billing
modules.”
缓存机制 缓存每次生成的 commit → changelog 映射，便于增量更新。

⚙️ 五、AI 输出控制与再生成机制

为了让输出更稳定：

1. 结构校验

生成后在本地进行正则匹配：

## .*\n(\n### .*\n(- .*\n)+)+

若不符合 Markdown 层级结构 → 触发一次“结构化重试” Prompt：

Your previous output missed the Markdown section headers.
Please regenerate following the required structure strictly.

2. 分类修正

若某类别缺失，可自动补空节：

If a category has no commits, still include the section header with "(none)".

3. 再生优化（Regenerate）

允许用户手动点击“Regenerate”按钮，插件会自动：
• 保留同一上下文；
• 增加“make it shorter” 或 “focus on business-level summary” 指令；
• 多次生成结果供选择。
