## 1 目标

- 只保留一个 Engine 状态栏入口图标。
- 子插件通过扩展点注册自己的快捷设置菜单。
- Engine 负责聚合显示，统一分区与交互规范。

## 2 现有结构与入口

Engine 提供状态栏聚合入口与扩展点：

- 扩展点接口：`dev.dong4j.zeka.stack.idea.plugin.common.statusbar.AIStatusBarPopupProvider`
- 扩展点 ID：`dev.dong4j.zeka.stack.idea.plugin.common.ai.statusBarPopupProvider`
- 状态栏入口：`dev.dong4j.zeka.stack.idea.plugin.common.statusbar.AIStatusBarWidget`

## 3 接入规范（子插件）

### 3.1 实现扩展点接口

实现 `AIStatusBarPopupProvider`，返回子插件的菜单分组与动作。

```java
public class ChangelogStatusBarPopupProvider implements AIStatusBarPopupProvider {
    @Override
    public @NotNull String getGroupName() {
        return ChangelogBundle.message("statusbar.provider.popup.title");
    }

    @Override
    public @NotNull ActionGroup createActionGroup(@NotNull Project project,
                                                  @NotNull DataContext context) {
        DefaultActionGroup group = new DefaultActionGroup();
        // 添加子插件快捷设置（Action/Toggle/ActionGroup）
        return group;
    }
}
```

### 3.2 在 plugin.xml 中注册

在子插件的 `plugin.xml` 中注册扩展点实现类：

```xml
<extensions defaultExtensionNs="dev.dong4j.zeka.stack.idea.plugin.common.ai">
    <statusBarPopupProvider
        implementation="dev.dong4j.zeka.stack.idea.plugin.xxx.statusbar.YourStatusBarPopupProvider"/>
</extensions>
```

### 3.3 命名规范

- 一级菜单标题使用设置页的 `displayName`，并保持表情一致。
- 子插件内所有可见标题/操作按钮，必须带表情，且与设置页面保持一致。
- 示例：`📒 IntelliAI Changelog`、`📘 IntelliAI Javadoc`。

## 4 Engine 聚合展示规范

Engine 的状态栏菜单结构为：

1) Engine 自身快捷设置（平铺）
2) 分隔线
3) `🧩 扩展插件` 分区标题
4) 子插件分组（每个子插件一个二级菜单）
5) 分隔线
6) `打开 Engine 设置`
7) `About`

子插件菜单是二级菜单，子插件内快捷设置仍保持原有结构（如“快捷设置”分组、二级菜单等）。

## 5 快捷设置一致性规范

### 5.1 必须包含表情

- 标题、分组、开关、按钮都必须带表情。
- 表情应与设置页面一致。

### 5.2 统一命名

- 中文统一使用“AI 服务商”，避免“AI 服务提供商/AI 提供商”混用。
- 英文统一使用 “AI service provider”。

### 5.3 语言/状态显示

需要显示当前状态或选择的项，建议用“标题 + 当前值”的形式：

- 输出语言：`输出语言 (中文)`
- Release Log 起点：`起点 (Tag)`

## 6 线程与性能要求

### 6.1 禁止 EDT 执行网络操作

- 不要在 `update()` 或 `createPopup()` 中执行网络请求。
- 例如 Agent 状态检查只能使用本地 PID/进程判断，避免访问端口。

### 6.2 ActionUpdateThread

- 统一使用 `ActionUpdateThread.BGT` 更新动作状态。
- 只有必须的 UI 操作才在 EDT 处理。

## 7 ActionGroup 处理注意事项

### 7.1 禁止使用 getChildren(null)

IntelliJ 2025+ 会报错：

```
Do not call `getChildren(null)`
```

请使用：

```java
getChildren(ActionManager.getInstance())
```

或使用 `getChildActionsOrStubs()`。

## 8 子插件菜单建议结构

建议子插件菜单保持固定结构：

- 服务商/模型选择（一级）
- 快捷设置分组（如“⚙️ 快捷设置”）
- 关键开关项（Toggle）
- 打开该子插件设置

## 9 接入检查清单

- 子插件实现了 `AIStatusBarPopupProvider`
- plugin.xml 已注册 `statusBarPopupProvider`
- 所有标题与按钮带表情
- 文案统一为“AI 服务商 / AI service provider”
- ActionUpdateThread 使用 BGT
- 未在 EDT 执行网络访问

## 10 常见问题

**Q: 子插件菜单标题从哪里来？**
A: `getGroupName()` 返回 displayName + 表情，并在 i18n 中统一维护。

**Q: 可以给子插件菜单排序吗？**
A: 目前按扩展点顺序展示。如需排序，建议在 Engine 层引入排序权重字段。

**Q: 状态栏只显示 Engine 图标吗？**
A: 是。子插件不再注册自己的 `StatusBarWidgetFactory`。
