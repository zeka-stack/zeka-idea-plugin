我现在在利用 ai 实现一个下一步修改预测功能， ideaplugin 有现成的 api 吗？

结论先给你：IDEA / IntelliJ Platform 没有“现成的 API”可以直接帮你做「下一步修改预测」。
但它提供了一整套非常适合你这个场景的底层能力，JetBrains 自己的很多“智能行为”（补全、重构建议、意图动作）本质上也是在这些 API 之上做预测与决策。

下面我按 **「有没有 → 能用什么 → 官方最佳实践 → 一个可落地架构」**来讲，完全站在 IDEA 插件官方设计思路 上说。

⸻

一、有没有现成的「下一步修改预测」API？

没有。

IntelliJ Platform 中不存在类似：

NextModificationPredictionService.predict(...)

这种 API。

原因很简单：

JetBrains 认为“下一步要做什么”是 高度语义化、场景化、语言相关 的问题，
不可能抽象成一个通用 API。

但它给了你 比 API 更底层、更强的东西。

⸻

你现在做的事情，在 IDEA 体系里 = “增强版 Intention / Smart Action”
你可以组合以下能力：

⸻

这是你必须用的，没有替代品

“任何‘我猜你接下来可能要做 X’的功能，都应该实现为 Intention”

也就是你看到的：

👉 Alt + Enter

示例：

→ Update Javadoc

我不需要这么全面这么复杂的功能，我只需要实现一个修改了文本，然后预测下一个类似的文本修改的功能

那我直接给你一个**“最小、官方友好、可落地”的方案**，完全不碰你不需要的那一套复杂东西。

目标重新定义（一句话）
👉 用户刚刚改了一段文本，IDE 帮他预测「接下来可能还会改的类似文本」

⸻

一、先给你一个明确结论（非常重要）

❗ IntelliJ IDEA 没有“文本修改预测”的现成 API

但：
👉 你完全可以用 Document + Editor API 在 20~30 行核心逻辑 内把这个功能做出来
👉 不需要 PSI、不需要重构、不需要 Intention

你现在这个需求 本质是 Editor 级别功能，不是 Code Intelligence

⸻

二、官方推荐你用的唯一一组 API（就这组）

✅ DocumentListener + Editor

这是 JetBrains 官方允许、也经常用来做智能编辑行为 的方式。

你要的“文本级预测”，用 PSI 反而是错误的。

⸻

三、最小可用实现思路（你会发现非常简单）

1️⃣ 监听用户“刚刚修改了什么文本”

EditorFactory.getInstance()
.getEventMulticaster()
.addDocumentListener(new DocumentListener() {

        @Override
        public void documentChanged(@NotNull DocumentEvent event) {
            CharSequence newFragment = event.getNewFragment();
            CharSequence oldFragment = event.getOldFragment();

            if (newFragment.length() == 0 || oldFragment.length() == 0) {
                return;
            }

            // 👇 这是你的「预测输入」
            onUserTextModified(
                oldFragment.toString(),
                newFragment.toString(),
                event.getOffset()
            );
        }
    }, disposable);

你现在已经拿到了：
• 用户 改了什么
• 从什么 → 变成什么
• 在什么位置

⸻

2️⃣ 构造一个「极简预测模型」（不是 AI 也行）

你现在的目标不是“智能”，而是 “相似修改”。

举个例子

"userName" → "username"
"UserName" → "username"
"USER_NAME" → "username"

你可以先抽象成：

TextChangePattern {
beforeRegex: "[A-Za-z_]+Name",
afterTransform: "lowercase + remove underscore"
}

⚠️ 这一步先不用 AI，规则就能跑通 80%

⸻

3️⃣ 在当前文档中找「类似文本」

String content = document.getText();

Pattern p = Pattern.compile(Pattern.quote(oldText));
Matcher m = p.matcher(content);

while (m.find()) {
int start = m.start();
int end = m.end();

    if (start == eventOffset) continue; // 跳过刚改的

    // 👇 这是“预测命中点”

}

⸻

4️⃣ 给用户一个“下一步”的最轻提示（不要打断）

不要自动改
不要弹对话框

👉 官方最推荐的方式：

A. Inlay Hint（灰色预览）

user_name → username ←（灰色）

B. 轻量 Popup（一次确认）

Apply same change to 3 similar places?
[Apply] [Ignore]

⸻

四、如果你一定要用 AI（但依然保持极简）

AI 只干一件事：

判断这是不是一个“可推广的修改模式”

你给 AI 的输入（极短）

{
"before": "user_name",
"after": "username"
}

AI 只需要回答：

{
"type": "rename_style_change",
"confidence": 0.92
}

❗不要把全文给 AI
❗不要做语义分析

五、为什么 IDEA 没有提供这种 API？

这是一个设计取舍问题：
• IDEA 无法知道：
• 你是改拼写
• 改格式
• 改业务术语
• 但它允许插件自由监听编辑行为
• 所以：能力在你这，不在平台

你现在做的功能，本质是：

Editor Macro + Smart Pattern Detection

而不是 “AI Code Intelligence”。
