# 反馈上报扩展点集成说明

## 背景
IntelliAI Engine 统一负责错误上报，但需要区分来源插件（如 Changelog、Javadoc、Terminal 等）。为此引入扩展点 `feedbackContextProvider`，由子插件提供来源信息，Engine 在上报时自动带上来源插件信息并调整标题。

## 扩展点定义（Engine）
- 扩展点名称：`dev.dong4j.zeka.stack.idea.plugin.common.ai.feedbackContextProvider`
- 接口类型：`dev.dong4j.zeka.stack.idea.plugin.common.diagnostic.FeedbackContextProvider`
- 推荐基类：`dev.dong4j.zeka.stack.idea.plugin.common.diagnostic.AbstractFeedbackContextProvider`

扩展点已在 Engine 中注册，无需子插件重复定义。

## Engine 侧行为
- 标题前缀：`[Report][PluginName]`（PluginName 为来源插件名）
- metadata 追加：
  - `sourcePluginId`
  - `sourcePluginName`
  - `sourcePluginVersion`
- 未命中来源时，回退为 Engine 自身信息

## 子插件接入步骤

### 1. 实现 FeedbackContextProvider
> 子插件无需手动填写插件信息，推荐继承 `AbstractFeedbackContextProvider`，由平台注入 `PluginDescriptor`。

示例（Changelog）：

```java
package dev.dong4j.zeka.stack.idea.plugin.changelog.diagnostic;

import org.jetbrains.annotations.Nullable;

import dev.dong4j.zeka.stack.idea.plugin.common.diagnostic.AbstractFeedbackContextProvider;

public class ChangelogFeedbackContextProvider extends AbstractFeedbackContextProvider {
    @Override
    public @Nullable String getTitlePrefix() {
        return null; // 返回 null 使用插件名称作为标题前缀
    }
}
```

### 2. 在 plugin.xml 注册扩展

```xml
<extensions defaultExtensionNs="dev.dong4j.zeka.stack.idea.plugin.common.ai">
    <feedbackContextProvider
        implementation="dev.dong4j.zeka.stack.idea.plugin.changelog.diagnostic.ChangelogFeedbackContextProvider"/>
</extensions>
```

## 可选：显式设置来源上下文
如果子插件需要在特定入口显式绑定来源，可以使用 `FeedbackContextHolder`：

```java
try (FeedbackContextHolder.Token token = FeedbackContextHolder.withPluginId("dev.dong4j.zeka.stack.idea.plugin.changelog")) {
    // 触发上报逻辑
}
```

## 注意事项
- 仅需实现扩展点即可完成来源识别。
- 未设置上下文时，Engine 会尝试从 `PluginException` 中提取插件 ID。
- 标题前缀可通过 `getTitlePrefix()` 自定义，为空则使用插件名称。
