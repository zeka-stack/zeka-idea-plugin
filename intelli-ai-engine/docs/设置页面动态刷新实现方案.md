# 设置页面动态刷新实现方案

## 📋 问题背景

### 问题描述

当用户在 IntelliAI Engine 设置页面（`Settings → Tools → IntelliAI Engine`）中添加、删除或清空可用服务商后，第三方插件（如 `intelli-ai-javadoc`
）的设置页面中的服务商下拉列表需要能够
**动态刷新**，而不需要用户关闭设置页面重新打开。

**问题场景**：

1. 用户打开 `Settings → Tools → IntelliAI JavaDoc` 设置页面
2. 此时没有可用的服务商，显示警告信息和跳转链接
3. 用户点击链接跳转到 `Settings → Tools → IntelliAI Engine` 设置页面
4. 在 IntelliAI Engine 中添加并测试通过一个服务商
5. 返回 IntelliAI JavaDoc 设置页面，下拉列表应该**自动刷新**，显示新添加的服务商

**原有方案的问题**：

- 下拉列表只在设置页面打开时初始化一次
- 用户在 IntelliAI Engine 中修改配置后，第三方插件的设置页面无法感知变化
- 用户必须关闭并重新打开设置页面才能看到更新

## ✅ 解决方案

使用**监听器模式（Observer Pattern）**来实现设置变更的实时通知和 UI 动态刷新。

### 方案优势

1. ✅ **实时更新**：配置变更后立即通知所有监听者
2. ✅ **解耦设计**：配置管理和 UI 更新分离，符合单一职责原则
3. ✅ **线程安全**：使用 `CopyOnWriteArrayList` 保证监听器列表的线程安全
4. ✅ **资源管理**：设置页面关闭时自动取消注册，避免内存泄漏

## 🔧 实现细节

### 1. 创建监听器接口

创建 `AIProviderSettingsListener` 接口：

```java
package dev.dong4j.zeka.stack.idea.plugin.common.config;

import org.jetbrains.annotations.NotNull;

/**
 * AI 提供商设置变更监听器
 * <p>
 * 用于监听 AIProviderSettings 中可用提供商列表的变化，以便在设置页面中动态刷新 UI。
 */
public interface AIProviderSettingsListener {
    /**
     * 当可用提供商列表发生变化时调用
     * <p>
     * 该方法在以下情况下会被调用：
     * <ul>
     *   <li>添加新的可用提供商</li>
     *   <li>移除可用提供商</li>
     *   <li>清空所有可用提供商</li>
     *   <li>通过 applyFrom 方法更新配置</li>
     * </ul>
     *
     * @param settings 更新后的 AIProviderSettings 实例
     */
    void onAvailableProvidersChanged(@NotNull AIProviderSettings settings);
}
```

### 2. 在 AIProviderSettings 中添加监听器机制

在 `AIProviderSettings` 类中添加监听器管理：

```java
/** 监听器列表（使用 CopyOnWriteArrayList 保证线程安全） */
private final List<AIProviderSettingsListener> listeners = new CopyOnWriteArrayList<>();

/**
 * 添加监听器
 * <p>
 * 当可用提供商列表发生变化时，会通知所有已注册的监听器。
 *
 * @param listener 监听器实例
 */
public void addListener(@NotNull AIProviderSettingsListener listener) {
    listeners.add(listener);
}

/**
 * 移除监听器
 *
 * @param listener 要移除的监听器实例
 */
public void removeListener(@NotNull AIProviderSettingsListener listener) {
    listeners.remove(listener);
}

/**
 * 通知所有监听器可用提供商列表已发生变化
 * <p>
 * 在 EDT 线程中执行监听器回调，确保 UI 更新的线程安全。
 */
private void notifyListeners() {
    if (listeners.isEmpty()) {
        return;
    }
    // 在 EDT 线程中执行监听器回调
    ApplicationManager.getApplication().invokeLater(() -> {
        for (AIProviderSettingsListener listener : listeners) {
            try {
                listener.onAvailableProvidersChanged(this);
            } catch (Exception e) {
                // 静默处理异常，避免影响其他监听器
            }
        }
    });
}
```

### 3. 在配置变更时触发监听器并主动保存

在以下方法中添加 `notifyListeners()` 调用，并在 `notifyListeners()` 中主动保存配置：

```java
public void addAvailableProvider(@NotNull AIProviderConfig config) {
    availableProviders.removeIf(existing -> Objects.equals(existing.credentialId, config.credentialId));
    availableProviders.add(config.copy());
    notifyListeners(); // 通知监听器并主动保存配置
}

public void removeAvailableProvider(@Nullable String credentialId) {
    boolean removed = availableProviders.removeIf(config -> Objects.equals(config.credentialId, credentialId));
    if (removed) {
        notifyListeners(); // 通知监听器并主动保存配置
    }
}

public void clearAvailableProviders() {
    if (!availableProviders.isEmpty()) {
        availableProviders.clear();
        notifyListeners(); // 通知监听器并主动保存配置
    }
}

public void applyFrom(@NotNull AIProviderSettings source) {
    // ... 复制配置 ...
    notifyListeners(); // 通知监听器可用提供商列表已更新并主动保存配置
}
```

#### 为什么要主动保存配置？

**问题**：

- 默认情况下，`PersistentStateComponent` 的配置只在以下时机持久化：
    1. 用户在设置页面点击 "Apply" 或 "OK" 按钮时
    2. IDE 关闭时自动保存
- 当用户在 IntelliAI Engine 设置页面中添加/删除提供商后，如果用户没有点击 "Apply"，配置只存在于内存中
- 第三方插件的设置页面通过监听器刷新时，虽然能看到内存中的最新配置，但如果 IDE 异常关闭，这些配置会丢失
- 更重要的是，如果用户关闭了 IntelliAI Engine 设置页面（没有点击 Apply），配置变更会丢失

**解决方案**：

- 在 `notifyListeners()` 方法中，除了通知监听器外，还要主动调用 `saveState()` 方法立即持久化配置
- 这样确保配置变更后立即保存到磁盘，即使 IDE 异常关闭也不会丢失
- 第三方插件刷新时读取的配置与磁盘中的配置保持一致

#### 如何主动保存配置？

在 `notifyListeners()` 方法中调用 `saveState()`：

```java
/**
 * 通知所有监听器可用提供商列表已发生变化
 * <p>
 * 在 EDT 线程中执行监听器回调，确保 UI 更新的线程安全。
 * 同时主动保存配置，确保配置变更立即持久化。
 */
private void notifyListeners() {
    if (listeners.isEmpty()) {
        return;
    }
    
    // 主动保存配置，确保配置变更立即持久化
    saveState();
    
    // 在 EDT 线程中执行监听器回调
    ApplicationManager.getApplication().invokeLater(() -> {
        for (AIProviderSettingsListener listener : listeners) {
            try {
                listener.onAvailableProvidersChanged(this);
            } catch (Exception e) {
                // 静默处理异常，避免影响其他监听器
            }
        }
    });
}

/**
 * 手动触发配置持久化
 * <p>
 * 在可用提供商列表发生变更时，立即持久化配置，确保第三方插件能够立即看到变更。
 * 这样就不需要用户手动点击 Apply 按钮。
 * <p>
 * 使用 ApplicationManager.getApplication().saveSettings() 主动保存所有配置。
 * 这是 IntelliJ Platform 提供的标准 API，会触发所有 PersistentStateComponent 的持久化。
 */
private void saveState() {
    ApplicationManager.getApplication().saveSettings();
}
```

**关键点**：

- `ApplicationManager.getApplication().saveSettings()` 是 IntelliJ Platform 提供的标准 API
- 它会触发所有 `PersistentStateComponent` 的 `getState()` 方法，将配置保存到磁盘
- 这是最直接、最可靠的方式来主动保存配置，无需使用反射或创建 Configurable 实例

### 4. 在设置面板中注册监听器

在第三方插件的设置面板（如 `JavaDocSettingsPanel`）中注册监听器：

```java
/** AI 提供商设置变更监听器 */
private AIProviderSettingsListener providerSettingsListener;

/** AI 提供商选择面板（用于动态刷新） */
private JPanel aiProviderSelectionPanel;

/**
 * 构造函数，初始化 JavaDoc 设置面板
 */
public JavaDocSettingsPanel() {
    createUI();
    setupListeners();
    registerProviderSettingsListener(); // 注册监听器
}

/**
 * 注册 AI 提供商设置变更监听器
 * <p>
 * 当 IntelliAI Engine 设置中的可用提供商列表发生变化时，自动刷新下拉列表。
 */
private void registerProviderSettingsListener() {
    AIProviderSettings globalSettings = AIProviderSettings.getInstance();
    providerSettingsListener = settings -> refreshProviderComboBox();
    globalSettings.addListener(providerSettingsListener);
}
```

### 5. 实现刷新逻辑

实现 `refreshProviderComboBox()` 方法来动态刷新下拉列表：

```java
/**
 * 刷新提供商下拉框
 * <p>
 * 从 IntelliAI Engine 设置中重新获取可用提供商列表，并更新下拉框内容。
 * 如果之前没有可用提供商，现在有了，会重新创建面板。
 */
private void refreshProviderComboBox() {
    if (aiProviderSelectionPanel == null) {
        return;
    }

    // 从 intelli-ai-engine 获取可用服务商列表
    AIProviderSettings globalSettings = AIProviderSettings.getInstance();
    List<AIProviderConfig> verifiedProviders = globalSettings.getVerifiedProviders();

    // 从已验证的提供商配置中提取 AIProviderType 列表
    List<AIProviderType> availableProviderTypes = new ArrayList<>();
    if (!verifiedProviders.isEmpty()) {
        for (AIProviderConfig config : verifiedProviders) {
            if (config.providerType != null && !availableProviderTypes.contains(config.providerType)) {
                availableProviderTypes.add(config.providerType);
            }
        }
    }

    // 判断之前是否有可用提供商（通过下拉框是否启用来判断）
    boolean hadProviders = providerComboBox != null && providerComboBox.isEnabled();
    boolean hasProviders = !availableProviderTypes.isEmpty();

    // 如果状态没有变化，只需要更新下拉框内容
    if (hadProviders && hasProviders) {
        // 保存当前选中的值
        AIProviderType selectedValue = (AIProviderType) providerComboBox.getSelectedItem();

        // 更新下拉框模型
        providerComboBox.setModel(new DefaultComboBoxModel<>(
            availableProviderTypes.toArray(new AIProviderType[0])));

        // 恢复之前选中的值（如果还存在）
        if (selectedValue != null && availableProviderTypes.contains(selectedValue)) {
            providerComboBox.setSelectedItem(selectedValue);
        } else if (!availableProviderTypes.isEmpty()) {
            // 如果之前选中的值不存在了，选择第一个
            providerComboBox.setSelectedIndex(0);
        }
        return;
    }

    // 如果状态发生变化（从无到有，或从有到无），需要重新创建整个面板
    JPanel parent = (JPanel) aiProviderSelectionPanel.getParent();
    if (parent != null) {
        int index = -1;
        for (int i = 0; i < parent.getComponentCount(); i++) {
            if (parent.getComponent(i) == aiProviderSelectionPanel) {
                index = i;
                break;
            }
        }
        if (index >= 0) {
            parent.remove(index);
            JPanel newPanel = createAIProviderSelectionPanel();
            aiProviderSelectionPanel = newPanel;
            parent.add(newPanel, index);
            parent.revalidate();
            parent.repaint();
        }
    }
}
```

### 6. 资源清理

在设置页面关闭时取消注册监听器，避免内存泄漏：

```java
/**
 * 释放资源
 * <p>
 * 取消注册监听器，避免内存泄漏。
 * 应该在设置页面关闭时调用。
 */
public void dispose() {
    if (providerSettingsListener != null) {
        AIProviderSettings globalSettings = AIProviderSettings.getInstance();
        globalSettings.removeListener(providerSettingsListener);
        providerSettingsListener = null;
    }
}
```

在 `Configurable` 的 `disposeUIResources()` 方法中调用：

```java
@Override
public void disposeUIResources() {
    if (settingsPanel != null) {
        settingsPanel.dispose(); // 取消注册监听器
        settingsPanel = null;
    }
}
```

## 🔄 工作流程

### 完整流程

1. **用户打开第三方插件设置页面**：
    - `JavaDocSettingsPanel` 构造函数被调用
    - 调用 `registerProviderSettingsListener()` 注册监听器
    - 初始化下拉列表（显示当前可用提供商）

2. **用户在 IntelliAI Engine 中修改配置**：
    - 用户在 IntelliAI Engine 设置页面中添加/删除/清空提供商
    - `AIProviderSettings` 的相应方法被调用（如 `addAvailableProvider()`）
    - 方法内部调用 `notifyListeners()` 通知所有监听器

3. **监听器收到通知**：
    - `notifyListeners()` 在 EDT 线程中执行监听器回调
    - `JavaDocSettingsPanel` 的监听器收到通知
    - 调用 `refreshProviderComboBox()` 刷新下拉列表

4. **UI 自动更新**：
    - 如果之前有提供商，现在也有：更新下拉框内容，保留当前选中值
    - 如果之前没有提供商，现在有了：重新创建面板，移除警告信息，显示下拉框
    - 如果之前有提供商，现在没有了：重新创建面板，显示警告信息

5. **用户关闭设置页面**：
    - `Configurable.disposeUIResources()` 被调用
    - 调用 `settingsPanel.dispose()` 取消注册监听器
    - 释放资源，避免内存泄漏

## ⚠️ 注意事项

1. **线程安全**：
    - 使用 `CopyOnWriteArrayList` 存储监听器列表，保证线程安全
    - 监听器回调在 EDT 线程中执行，确保 UI 更新的线程安全

2. **资源管理**：
    - 必须在设置页面关闭时调用 `dispose()` 取消注册监听器
    - 避免内存泄漏和重复通知

3. **异常处理**：
    - 监听器回调中的异常会被静默处理，避免影响其他监听器
    - 建议在监听器实现中添加适当的异常处理

4. **性能考虑**：
    - 监听器回调在 EDT 线程中执行，避免阻塞主线程
    - 刷新逻辑应该尽量轻量，避免复杂的 UI 操作

5. **状态同步**：
    - 刷新时需要判断状态是否发生变化，避免不必要的 UI 更新
    - 从无到有或从有到无的状态变化需要重新创建面板

## 🎯 总结

通过使用监听器模式，我们成功实现了设置页面的动态刷新功能：

- ✅ **实时更新**：配置变更后立即通知所有监听者，UI 自动刷新
- ✅ **解耦设计**：配置管理和 UI 更新分离，符合单一职责原则
- ✅ **线程安全**：使用 `CopyOnWriteArrayList` 和 EDT 线程执行，保证线程安全
- ✅ **资源管理**：设置页面关闭时自动取消注册，避免内存泄漏
- ✅ **用户体验**：用户无需关闭设置页面即可看到配置变更，提升用户体验
