# intelli-ai-engine 插件改造任务清单

## 目标

将 `intelli-ai-engine` 改造成一个独立的 IntelliJ 插件，让 `intelli-ai-javadoc` 通过插件依赖的方式使用 `intelli-ai-engine` 扩展 AI 功能。

## 任务清单

### 阶段一：intelli-ai-engine 插件化改造

#### 任务 1：创建 intelli-ai-engine 的 plugin.xml 配置文件

- [ ] 创建 `intelli-ai-engine/src/main/resources/META-INF/plugin.xml`
- [ ] 配置插件基本信息（id、name、version、vendor）
- [ ] 注册应用级服务：
    - `AIProviderSettings`（全局配置）
    - `AIService`（统一入口）
- [ ] 注册全局设置页面：`AICommonSettingsConfigurable`
- [ ] 注册状态栏组件：`AIProviderStatusBarWidgetFactory`

#### 任务 2：将 AIProviderSettings 改造为应用级服务

- [ ] 修改 `AIProviderSettings` 实现 `PersistentStateComponent<AIProviderSettings>`
- [ ] 添加 `@State` 注解，配置存储位置
- [ ] 实现 `getState()` 和 `loadState()` 方法
- [ ] 添加 `getInstance()` 静态方法
- [ ] 移除 `providerType` 字段（不再维护默认供应商，由各插件自己维护）

#### 任务 3：创建 AIService 接口和 AIServiceImpl 实现类

- [ ] 创建 `AIService` 接口（在 `intelli-ai-engine/src/main/java/dev/dong4j/zeka/stack/idea/plugin/common/ai/service/`）
- [ ] 创建 `AIServiceImpl` 实现类
- [ ] 实现从插件配置中读取默认供应商的逻辑
- [ ] 实现从全局配置中读取供应商详情的逻辑
- [ ] 支持 `AIResponseListener` 回调

#### 任务 4：创建 AICommonSettingsConfigurable 和 AICommonSettingsPanel

- [ ] 创建 `AICommonSettingsConfigurable`（实现 `SearchableConfigurable`）
- [ ] 创建 `AICommonSettingsPanel`（使用 `AIProviderConfigPanel`）
- [ ] 实现设置页面的加载、保存、重置逻辑
- [ ] 配置为全局设置页面（应用级）

#### 任务 5：更新 intelli-ai-engine 的 build.gradle.kts

- [ ] 将 `java-library` 改为 `java` 插件
- [ ] 添加 `intellijPlatform` 插件配置
- [ ] 配置插件基本信息（name、version、description）
- [ ] 配置插件发布信息
- [ ] 移除 Maven 发布配置（或保留用于开发测试）

### 阶段二：intelli-ai-javadoc 迁移到插件依赖

#### 任务 6：修改 intelli-ai-javadoc 的 plugin.xml

- [ ] 添加对 `intelli-ai-engine` 插件的依赖：`<depends>dev.dong4j.zeka.stack.idea.plugin.common.ai</depends>`
- [ ] 确保插件 ID 正确

#### 任务 7：修改 intelli-ai-javadoc 的 SettingsState

- [ ] 移除 `AIProviderSettings providerSettings` 字段
- [ ] 添加 `AIProviderType providerType` 字段（当前插件使用的默认供应商）
- [ ] 保留其他插件特定的配置（如 prompt 模板等）
- [ ] 更新 `resetToDefaults()` 方法

#### 任务 8：修改 intelli-ai-javadoc 的 JavaDocSettingsPanel

- [ ] 修改为只显示供应商选择下拉框（从全局可用列表中选取）
- [ ] 移除 `AIProviderConfigPanel` 的直接使用
- [ ] 使用 `AIService.getGlobalSettings()` 获取可用供应商列表
- [ ] 保存时只保存 `providerType` 到 `SettingsState`

#### 任务 9：修改 intelli-ai-javadoc 的 TaskExecutor

- [ ] 移除直接使用 `AIServiceFactory` 的代码
- [ ] 使用 `AIService.getInstance().generateContent()` 方法
- [ ] 传入 `project` 参数，让 `AIService` 自动从插件配置中读取默认供应商
- [ ] 传入 `AIConsoleLoggerImpl` 作为 `AIResponseListener`

#### 任务 10：修改 intelli-ai-javadoc 的 build.gradle.kts

- [ ] 移除 `implementation("dev.dong4j:intelli-ai-engine:1.0.0")` 依赖
- [ ] 确保插件构建时能找到 `intelli-ai-engine` 插件（可能需要先构建 `intelli-ai-engine`）

#### 任务 11：测试验证

- [ ] 构建 `intelli-ai-engine` 插件
- [ ] 构建 `intelli-ai-javadoc` 插件
- [ ] 测试 `intelli-ai-javadoc` 可以正常使用 `intelli-ai-engine` 插件的功能
- [ ] 测试设置页面可以正常配置
- [ ] 测试 AI 功能可以正常使用

## 注意事项

1. **插件 ID**：确保 `intelli-ai-engine` 的插件 ID 与 `intelli-ai-javadoc` 的依赖声明一致
2. **服务级别**：`AIProviderSettings` 和 `AIService` 必须是应用级服务（`Service.Level.APPLICATION`）
3. **配置隔离**：每个插件维护自己的 `providerType`，从全局 `availableProviders` 中选取
4. **向后兼容**：确保现有功能不受影响
5. **构建顺序**：可能需要先构建 `intelli-ai-engine` 插件，再构建 `intelli-ai-javadoc` 插件

## 实施顺序

按照任务编号顺序执行，每个任务完成后进行验证，确保没有问题后再继续下一个任务。
