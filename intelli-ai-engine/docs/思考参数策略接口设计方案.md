# 思考参数策略接口设计方案

## 1. 背景与问题

### 1.1 现状

Engine 将「是否思考」抽象为配置字段 `AIProviderConfig.enableThinking`，并在 **OpenAI 兼容通用路径** `AICompatibleProvider.buildRequestBody` 中写死：

```text
enable_thinking: true | (OMIT / false)
```

再叠加 `ThinkingCapabilityProbe` 的三探针（OMIT / true / false），专门服务 **DashScope / 通义类** 的 `enable_thinking` 扩展。

这在 DeepSeek 上不成立。

### 1.2 DeepSeek 官方参数（2026）

| 能力 | OpenAI 格式 | Anthropic 格式 | Responses API 格式 |
|------|-------------|----------------|--------------------|
| 思考开关 | `{"thinking":{"type":"enabled\|disabled"}}` | （与 thinking 对象配合） | `{"reasoning":{"effort":"none\|low\|high\|max"}}`（`none`=关） |
| 思考强度 | `{"reasoning_effort":"low\|high\|max"}` | `{"output_config":{"effort":"low\|high\|max"}}` | （effort 合一） |

OpenAI SDK 示例：

```python
client.chat.completions.create(
  model="deepseek-v4-pro",
  reasoning_effort="high",
  extra_body={"thinking": {"type": "enabled"}},
)
```

补充事实：

- DeepSeek **默认开启**思考，默认 effort=`high`
- 思考模式下 `temperature` / `top_p` / `presence_penalty` 等无效（传了不报错也不生效）
- 插件已有 `DEEPSEEK`（OpenAI 兼容）与 `DEEPSEEK_ANTHROPIC` 两条入口
- 思考输出字段仍是 `reasoning_content`（流式解析已部分覆盖）

### 1.3 根因

「用户意图（开/关 + 强度）」与「落到 HTTP JSON 的厂商字段」被绑死在一层。  
不同模型/协议的扩展参数本就不共享同一 schema，**不能在通用 `buildRequestBody` 末尾固定写一个字段**。

### 1.4 目标

1. 配置层只表达**用户意图**（是否思考、强度），不绑定具体 JSON 字段名  
2. 请求组装时由**策略对象**按「服务商 + 协议 + 模型」写入扩展字段  
3. DeepSeek OpenAI / Anthropic 首期落地；现有 `enable_thinking` + 三探针行为对通义类保持兼容  
4. 为后续 Responses API / 其他厂商预留扩展点  
5. **先方案、后编码**（本文仅设计）

## 2. 方案选项

### 选项 A：在 Provider 子类里各自 override `buildRequestBody`

- DeepSeek 单独 `DeepSeekOpenAIProvider`，覆盖 body 构建  
- 优点：改动面小  
- 缺点：Anthropic / 未来 Responses / Custom 网关难以复用；UI 仍不知道「有没有 effort」；探测逻辑继续耦合字段名  

| 项 | 评估 |
|----|------|
| 工作量 | 小 |
| 风险 | 中：多协议重复实现 |
| 可扩展性 | 差 |

### 选项 B（推荐）：`ThinkingParamStrategy` 策略接口 + 注册表

- 配置只保留意图：`enableThinking` + `thinkingEffort`  
- 请求体由 `ThinkingParamStrategy.apply(body, intent, context)` 注入  
- 探测、UI 能力描述也挂在策略上  

| 项 | 评估 |
|----|------|
| 工作量 | 中 |
| 风险 | 低：默认策略 = 现有 enable_thinking |
| 可扩展性 | 好：每厂商/协议一个实现 |

### 选项 C：通用「扩展参数 Map」让用户手填 JSON

- 灵活但体验差，易配错；与设置页 Think 开关割裂  
- **不推荐**作为主方案（可作为高级逃生舱远期考虑）

**推荐：选项 B。**

## 3. 推荐设计

### 3.1 分层

```text
┌─────────────────────────────────────────┐
│ UI / Settings                           │
│  enableThinking + thinkingEffort        │
│  （按 Strategy.uiCapability 显隐控件）   │
└─────────────────┬───────────────────────┘
                  │ ThinkingIntent
                  ▼
┌─────────────────────────────────────────┐
│ AIProviderConfig（意图持久化）           │
│  enableThinking: boolean                │
│  thinkingEffort: LOW|HIGH|MAX|AUTO      │
│  thinkingProbeResult: ...（可选）        │
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│ ThinkingParamStrategyRegistry           │
│  resolve(providerType, protocol, model) │
└─────────────────┬───────────────────────┘
                  │
        ┌─────────┼─────────┐
        ▼         ▼         ▼
 EnableThinking  DeepSeek   DeepSeek
  (Qwen-like)    OpenAI     Anthropic
        │         │         │
        └─────────┴─────────┘
                  │ apply(body)
                  ▼
           HTTP Request Body
```

### 3.2 核心接口（建议形态）

```java
/** 用户对「思考」的意图；与具体 JSON 字段无关 */
public record ThinkingIntent(
    boolean enabled,
    @NotNull ThinkingEffort effort  // AUTO / LOW / HIGH / MAX
) {}

/** UI 需要知道该策略支持哪些控件 */
public record ThinkingUiCapability(
    boolean supportsToggle,     // 是否显示 Think 开关
    boolean supportsEffort,     // 是否显示强度下拉
    boolean supportsProbe,      // 测连后是否跑探测
    @NotNull List<ThinkingEffort> allowedEfforts
) {}

/**
 * 思考参数策略：把意图变成请求扩展字段，并可选地负责探测。
 * <p>
 * 约束：只修改「思考相关」字段，不改 messages / model / stream 等公共字段。
 */
public interface ThinkingParamStrategy {

    @NotNull String id();

    @NotNull ThinkingUiCapability uiCapability(@NotNull ThinkingContext context);

    /**
     * 将思考相关字段写入已构建好的请求体。
     * enabled=false 时由策略决定 OMIT / disabled / effort=none，禁止通用层猜字段名。
     */
    void apply(@NotNull JsonObject body,
               @NotNull ThinkingIntent intent,
               @NotNull ThinkingContext context);

    /**
     * 测连成功后的能力探测；不支持则返回空结果或 UNKNOWN。
     * 必须在 BGT 调用。
     */
    @NotNull ThinkingProbeResult probe(@NotNull ThinkingProbeContext probeContext);

    /** 默认 effort（DeepSeek 文档默认 high；通义类可 AUTO） */
    @NotNull ThinkingEffort defaultEffort();
}

public record ThinkingContext(
    @NotNull AIProviderType providerType,
    @NotNull String modelName,
    @NotNull ApiProtocol protocol,   // CHAT_COMPLETIONS / RESPONSES（可先枚举预留）
    @Nullable ThinkingProbeResult probeResult
) {}
```

### 3.3 注册与选择

```java
public final class ThinkingParamStrategyRegistry {
    public static ThinkingParamStrategy resolve(ThinkingContext ctx) { ... }
}
```

解析优先级（从具体到通用）：

1. `providerType + protocol` 精确匹配（如 `DEEPSEEK` + Chat Completions）  
2. `providerType` 默认  
3. 模型名启发式（可选，慎用；Custom 网关场景）  
4. 回退：`EnableThinkingStrategy`（现有 `enable_thinking` + 三探针）

首期映射：

| Provider / 协议 | Strategy |
|-----------------|----------|
| `QIANWEN` / 多数 OpenAI 兼容（默认） | `EnableThinkingStrategy` |
| `DEEPSEEK` + Chat Completions | `DeepSeekOpenAIThinkingStrategy` |
| `DEEPSEEK_ANTHROPIC` | `DeepSeekAnthropicThinkingStrategy` |
| 未来 `OPENAI` + Responses | `OpenAIResponsesReasoningStrategy` |
| Anthropic 官方（非 DeepSeek） | 可后续单独做 `AnthropicThinkingStrategy`（budget_tokens），本期不强制 |

### 3.4 各策略写入规则

#### EnableThinkingStrategy（兼容现状）

- on → 按探测结果：`enable_thinking: true` 或 OMIT  
- off → OMIT（默认不写 false）  
- effort：忽略（UI 隐藏）  
- probe：现有三探针  

#### DeepSeekOpenAIThinkingStrategy

```json
// enabled
{
  "thinking": { "type": "enabled" },
  "reasoning_effort": "high"
}

// disabled
{
  "thinking": { "type": "disabled" }
}
```

- `AUTO` effort → `high`（官方默认）  
- `LOW/HIGH/MAX` → 原样写入；文档注明 pro 对 low 的映射由服务端处理  
- probe：本期可 **跳过三探针**（官方语义明确）；或做轻量「enabled vs disabled」双探针（可选 Phase 2）  
- 可选：思考开启时在日志提示 temperature 等无效  

#### DeepSeekAnthropicThinkingStrategy

```json
// enabled
{
  "thinking": { "type": "enabled" },
  "output_config": { "effort": "high" }
}

// disabled
{
  "thinking": { "type": "disabled" }
}
```

（`budget_tokens` 官方忽略，不传。）

#### 未来 Responses（预留，本期不实现）

```json
{ "reasoning": { "effort": "none|low|high|max" } }
```

开关与强度合一：`enabled=false` → `effort=none`。

### 3.5 接入点改造（避免再写死字段）

1. **`AICompatibleProvider.buildRequestBody`**  
   - 删除内联 `enable_thinking` 写入  
   - 公共字段构建完后：

```text
ThinkingIntent intent = config.toThinkingIntent();
ThinkingParamStrategy strategy = registry.resolve(context);
strategy.apply(body, intent, context);
```

2. **`AnthropicLikeProvider` 请求体构建**  
   - 同样在末尾 `strategy.apply(...)`（DeepSeek Anthropic 才写入；其他 Anthropic 策略可先 no-op）  

3. **`ThinkingCapabilityProbe`**  
   - 降级为 `EnableThinkingStrategy.probe` 的实现细节，不再被所有测连无条件调用  
   - Controller：`strategy.uiCapability().supportsProbe()` 为 true 才探测  

4. **设置对话框**  
   - Toggle 始终按 `supportsToggle`  
   - Effort 下拉按 `supportsEffort` + `allowedEfforts`  
   - 探测结论展示按策略文案（DeepSeek 可显示「官方 thinking / reasoning_effort」说明）  

### 3.6 配置模型演进

```text
AIProviderConfig
  enableThinking: boolean          // 保留，兼容已有 XML
  thinkingEffort: String/enum      // 新增，默认 AUTO；老配置缺失 → AUTO
  thinkingProbeResult              // 保留；仅 EnableThinkingStrategy 使用
```

`toThinkingIntent()`：

- `enableThinking=false` → `ThinkingIntent(false, AUTO)`（effort 不生效）  
- `enableThinking=true` + `AUTO` → 策略 `defaultEffort()`  

持久化：`copy` / `contentEquals` / 设置页 `isModified` 同步 `thinkingEffort`。

### 3.7 与「可用服务商后置编辑」的关系

`AvailableProviderSettingsDialog` 已是 Think 编辑入口：

- 增加「思考强度」控件（DeepSeek 显示，通义隐藏）  
- 探测标签由策略提供摘要，避免 DeepSeek 仍显示 `enable_thinking` 探针乱象

## 4. 攻击面评估（选项 B）

| 角度 | 结论 |
|------|------|
| 依赖失败 | 默认 `EnableThinkingStrategy`；未知厂商行为与现网一致 |
| 规模爆炸 | 策略数量随厂商线性增长，无运行时状态；注册表静态 |
| 回滚成本 | 配置多一个 effort 字段；关掉策略注册即可退回硬编码（保留 git） |
| 前提坍塌 | 「所有 OpenAI 兼容都用 enable_thinking」已证明错误 → 正是本设计要拆掉的前提 |

最脆弱点：Custom 网关挂 DeepSeek 模型但 `providerType=CUSTOM`。  
缓解：Phase 2 可按 modelName 含 `deepseek` 启发式；Phase 1 仅官方 `DEEPSEEK` / `DEEPSEEK_ANTHROPIC` 走新策略。

| 阶段 | 内容 |
|------|------|

## 7. 测试计划

| 场景 | 预期 |
|------|------|
| 通义 + Think 开 | 请求含 `enable_thinking: true`（或按探针）；无 `thinking.type` |
| 通义 + Think 关 | 不传 `enable_thinking` |
| DeepSeek OpenAI + Think 开 + effort=high | `thinking.type=enabled` + `reasoning_effort=high` |
| DeepSeek OpenAI + Think 关 | `thinking.type=disabled`，无 effort 或可不传 |
| DeepSeek Anthropic + Think 开 | `thinking.type=enabled` + `output_config.effort` |
| 非 DeepSeek 设置页 | 不显示强度下拉 |
| 老配置无 thinkingEffort | 反序列化为 AUTO，行为与现网一致 |
| 测连 DeepSeek | 不跑 enable_thinking 三探针（或按策略跳过） |

## 8. 已确认决策

### Phase 1（2026-08-06）
1. 同时做 `DEEPSEEK` + `DEEPSEEK_ANTHROPIC`
2. Effort 下拉默认自动
3. 关闭 Think：显式 `thinking.type=disabled`
4. Custom **不按模型名启发式**

### Phase 2（2026-08-06）
1. 范围：Kimi + 豆包 + 智谱 + **通义强度**
2. **不向用户展示策略名称**（用户不关心内部策略 id）
3. 明确：`enable_thinking` 是通义扩展，不是 OpenAI 官方参数；通义走 `QianwenThinkingStrategy`

---

## 9. 结论

不要继续在通用请求构建里追加 `if (deepseek) ...`。  
应引入 **`ThinkingParamStrategy`**：配置表达意图，策略负责协议字段。

Phase 1 / Phase 2 已按确认项实现。
