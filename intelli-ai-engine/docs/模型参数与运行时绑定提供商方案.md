## 功能概述

当前 `AIProviderSettings` 结构中：

- `defaultProviders` / `availableProviders` 仅存储 `AIProviderConfig`；
- `AIModelParameters` 与 `AIRuntimeSettings` 属于全局共享配置。

需求：将模型参数与运行时设置与具体 `AIProviderConfig` 绑定，使每个 provider 拥有独立的模型与 runtime 配置，便于针对不同服务商/模型做差异化调优。

## 现状分析

1. **数据结构**
    - `AIProviderSettings` 内部字段：
      ```java
      public final Map<AIProviderType, AIProviderConfig> defaultProviders = new HashMap<>();
      public final List<AIProviderConfig> availableProviders = new ArrayList<>();
      public final AIModelParameters modelParameters = new AIModelParameters();
      public final AIRuntimeSettings runtimeSettings = new AIRuntimeSettings();
      ```
    - `AIProviderConfig` 仅保存 `providerType`, `modelName`, `baseUrl`, `credentialId`, `remark` 等。

2. **UI 使用**
    - 设置页 (`AIProviderConfigPanel`) 读取/写入时直接访问 `workingSettings.modelParameters` 与 `runtimeSettings`，无论当前选择哪个 provider。

3. **调用链**
    - `AIServiceFactory.createProvider(...)` 接收 `AIProviderConfig`, `AIModelParameters`, `AIRuntimeSettings` 作为独立参数；
    - `AICompatibleProvider` 内部不区分 provider 级别参数来源。

4. **持久化**
    - `AIProviderSettings.getInstance()` 通过 `PersistentStateComponent` 序列化；
    - 因为 Model/Runtime 字段为全局单例，序列化文件结构也固定。

## 目标

1. **数据结构调整**
    - 每个 `AIProviderConfig` 拥有自身的 `AIModelParameters` 与 `AIRuntimeSettings`。
    - 全局 `modelParameters/runtimeSettings` 字段废弃或仅用于默认模板。

2. **兼容与迁移**
    - 插件尚未发布，无需历史迁移；
    - 全局 `modelParameters/runtimeSettings` 继续作为默认模板，创建或编辑 provider 时拷贝当前 UI 快照。

3. **UI 行为**
    - 切换 provider 时，面板展示该 provider 自身的 Model/Runtime 值；
    - 保存/验证时写回当前 provider 的配置；
    - 可用列表（多提供商）同样保存独立参数。

4. **调用链**
    - `AIServiceFactory.createProvider(...)` 调用侧需从 `AIProviderConfig` 中读取对应参数；
    - `AIServiceProvider` 子类应只依赖 `config` 内部的参数，避免再传递共享对象。

## 实现方案

### 1. 数据模型重构

1. `AIProviderConfig` 新增字段：
   ```java
   public AIModelParameters modelParameters = new AIModelParameters();
   public AIRuntimeSettings runtimeSettings = new AIRuntimeSettings();
   ```
    - `copy()`, `contentEquals()` 等方法同步处理；
    - `updateCredentialId()` 继续按原逻辑。

2. `AIProviderSettings`
    - 保留全局 `modelParameters/runtimeSettings` 作为默认模板；
    - `getDefaultProviderConfig()` 在缺省时复制模板并初始化 `modelParameters/runtimeSettings`；
    - ProviderConfig 内部始终持有独立副本，新增/编辑时覆盖其字段。

3. `AIServiceConfig`
    - 若对外 API 仍需共享模型/运行时，可保留字段，但在转换为内部 `AIProviderConfig` 时复制到对应实例。

### 2. UI 调整 (`AIProviderConfigPanel`)

1. `workingSettings.getDefaultProviderConfig(providerType)` 返回的实例包含独立参数；
2. `loadSettings()` 读取 `config.modelParameters/runtimeSettings`，填入对应 spinner；
3. `getSettings()` / `saveCurrentProviderConfig()`：将 UI 中的模型参数与 runtime 设置写回当前 `AIProviderConfig`；
4. `refreshModels()` / `testConnection()` 等方法创建临时 config 时需复制其参数；
5. `collectModelParameters()`、`collectRuntimeSettings()` 方法需基于当前 UI 快照，分别写入全局模板与 providerConfig；
6. 可用 provider 表格（`addAvailableProvider` 等）中，保存的 `AIProviderConfig` 也要带参数，供 TaskExecutor 使用。

### 3. 服务构建链路

1. `AIServiceFactory.createProvider(...)` 签名调整为仅接收 `AIProviderConfig config`（内部包含参数）。
2. 所有调用 `AIServiceFactory.createProvider` 的位置（刷新模型、测试连接、任务执行）需要更新。
3. `AICompatibleProvider` 及子类仍接收拆分后的参数，由工厂负责从 `config` 中提取并传递。

### 4. 持久化与迁移

1. **版本号**：完成功能后 bump 至 1.1.0，并在 `includes/pluginChanges.html` 记录。

### 5. 测试点

1. **单元测试**
    - `AIProviderSettings` 迁移逻辑；
    - `AIProviderConfig.copy()` 是否深拷贝新字段；
    - `AIServiceFactory` 是否使用独立参数。

2. **UI 手动验证**
    - 切换不同 provider 时对应参数独立生效；
    - 可用 provider 列表中新增条目使用本 provider 的参数；
    - 任务执行时，从不同 provider 触发请求，确认参数隔离。

## 影响面

- `AIProviderSettings`, `AIProviderConfig`, `AIProviderConfigPanel`, `AIServiceFactory`, `AICompatibleProvider`, 其他 `AIServiceProvider`
  实现。
- 可能影响所有依赖 `AIProviderSettings.getInstance()` 的下游插件，需要同步适配接口变化（建议保持旧 API 兼容或提供迁移指引）。

## 开发步骤

1. **数据层改造**：`AIProviderConfig` 扩展、`AIProviderSettings` 迁移逻辑；
2. **UI 层更新**：设置面板读写独立配置；
3. **服务层改造**：`AIServiceFactory` & Provider 实现；
4. **验证 & 文档**：新增/更新 changelog、用户手册。
