# IntelliJ IDEA 插件下拉搜索组件技术方案

## 一、背景

### 1.1 业务场景

在 IntelliAI Engine 插件中，需要实现 AI 模型选择功能。具体需求如下：

- **数据来源**: 通过 API 调用获取模型列表（异步加载）
- **数据规模**: 模型列表可能较长，约 100+ 项
- **用户痛点**: 在长列表中找到目标模型耗时且不便
- **用户体验**: 需要支持快速搜索/过滤，提升选择效率

### 1.2 当前实现问题

当前实现使用了 `ComboBox` + 自定义过滤器的方案（`AIProviderConfigUI.java`）：

```java
// 当前实现：手动过滤
modelComboBox.setEditable(true);
modelComboBox.getEditor().getEditorComponent().addDocumentListener(...);
```

**存在的问题**：

- ❌ 需要手动实现过滤逻辑，代码复杂
- ❌ 过滤逻辑维护成本高
- ❌ 用户体验不够原生，不符合 IntelliJ IDEA 的标准交互模式
- ❌ 不支持键盘快速导航（SpeedSearch 的默认能力）

### 1.3 目标

采用 IntelliJ IDEA 官方推荐的 `ComboBox + SpeedSearch` 方案，实现：

- ✅ 原生 IDE 体验（与 IDEA 内置下拉列表一致）
- ✅ 零配置集成（IDE 内置功能）
- ✅ 支持键盘快速搜索（下拉后直接输入过滤）
- ✅ 降低代码复杂度，减少维护成本

## 二、组件对比

### 2.1 IntelliJ IDEA 插件常用搜索组件

在 IntelliJ IDEA Plugin SDK 中，常用的搜索下拉组件方案如下：

| 组件方案                            | SDK 类                                            | 适用场景                    | 推荐度   |
|---------------------------------|--------------------------------------------------|-------------------------|-------|
| **SearchTextField**             | `com.intellij.ui.SearchTextField`                | ToolWindow 搜索、列表/树过滤    | ⭐⭐⭐⭐⭐ |
| **TextFieldWithAutoCompletion** | `com.intellij.ui.TextFieldWithAutoCompletion`    | 搜索 + 建议候选、API Key 选择    | ⭐⭐⭐⭐⭐ |
| **ComboBox + SpeedSearch**      | `ComboBox<T>` + `SpeedSearchSupply`              | 下拉 + 搜索（100-500 项）      | ⭐⭐⭐⭐☆ |
| **JBList + SpeedSearch**        | `JBList` + `SpeedSearch` + `PopupChooserBuilder` | 大数据搜索（500+ 项）、Action 弹窗 | ⭐⭐⭐⭐⭐ |

### 2.2 方案详细对比

#### 方案一：SearchTextField

**特点**：

- ✅ 内置清除按钮
- ✅ 支持文本变化监听
- ❌ 不自带数据源（需要手动过滤 list/tree）
- ✅ JetBrains 官方插件大量使用

**适用场景**：

- ToolWindow 搜索
- 设置页过滤
- 列表/树内容过滤

**示例**：

```java
SearchTextField searchField = new SearchTextField();
searchField.addDocumentListener(new DocumentAdapter() {
    @Override
    protected void textChanged(@NotNull DocumentEvent e) {
        String text = searchField.getText();
        filter(text);
    }
});
```

#### 方案二：TextFieldWithAutoCompletion

**特点**：

- ✅ 下拉补全 popup（IDE 原生样式）
- ✅ 支持模糊匹配
- ✅ 可异步提供候选
- ❌ 需要额外的输入框，界面占用空间较大

**适用场景**：

- 搜索 + 推荐候选
- Provider / Model / API Key 选择
- Command / Action 搜索

**示例**：

```java
TextFieldWithAutoCompletion<String> field =
    new TextFieldWithAutoCompletion<>(
        project,
        new StringsCompletionProvider(values, null),
        true,
        ""
    );
```

#### 方案三：ComboBox + SpeedSearch ⭐ **推荐**

**特点**：

- ✅ 下拉时直接输入过滤（无需额外输入框）
- ✅ 零成本集成（IDE 内置功能）
- ✅ IDEA 所有下拉列表默认体验
- ⚠️ 不适合大量数据（>1k）

**适用场景**：

- 下拉 + 搜索（100-500 项）
- Provider / Model 选择
- 配置项选择

**用户体验**：

1. 用户点击 ComboBox（或 `Alt + ↓`）
2. **直接开始输入**（不需要光标在输入框）
3. 下拉列表实时高亮/过滤匹配项
4. 回车选中

👉 这就是 IDEA 里选 Maven 版本 / SDK / JDK / Run Configuration 的体验

**示例**：

```java
ComboBox<String> comboBox = new ComboBox<>(items);
SpeedSearchSupply.installOn(comboBox);
```

#### 方案四：JBList + SpeedSearch + Popup

**特点**：

- ✅ 支持万级数据
- ✅ 键盘体验极佳
- ✅ Action 搜索 / AI 工具选择必用
- ❌ 实现复杂度较高
- ❌ 需要弹窗，交互较重

**适用场景**：

- 大数据搜索（500+ 项）
- ToolWindow / Popup
- Action 弹窗

**示例**：

```java
JBList<String> list = new JBList<>(data);
new SpeedSearch(list);

PopupChooserBuilder<String> builder =
    new PopupChooserBuilder<>(list);
builder.createPopup().showInFocusCenter();
```

### 2.3 方案选择矩阵

| 需求                     | 推荐组件                          | 说明           |
|------------------------|-------------------------------|--------------|
| 仅过滤内容                  | `SearchTextField`             | 适用于列表/树过滤    |
| 搜索 + 建议                | `TextFieldWithAutoCompletion` | 适用于输入框场景     |
| **下拉 + 搜索（100-500 项）** | **`ComboBox + SpeedSearch`**  | **✅ 符合当前需求** |
| 大数据搜索（500+ 项）          | `JBList + SpeedSearch`        | 适用于超大数据集     |
| ToolWindow 搜索          | `SearchTextField + JBList`    | 适用于工具窗口      |
| Action 弹窗              | `PopupChooserBuilder`         | 适用于命令选择      |

### 2.4 不推荐的做法

以下做法不符合 IntelliJ IDEA 的官方最佳实践：

- ❌ Swing 原生 `JComboBox` 自己 hack
- ❌ 自己写 popup + key listener
- ❌ 模仿 Web autocomplete（破坏 IDE 键盘模型）
- ❌ 在 EDT 做过滤 / IO

## 三、方案选择

### 3.1 需求分析

**当前场景特点**：

- ✅ 通过 API 异步获取模型列表（100+ 项）
- ✅ 需要在下拉列表中选择模型
- ✅ 用户需要快速定位目标模型
- ✅ 数据量适中（100-300 项）

**非功能性要求**：

- ✅ 符合 IntelliJ IDEA 原生交互体验
- ✅ 代码实现简洁，易于维护
- ✅ 性能良好，用户体验流畅

### 3.2 方案选择

**选择**: `ComboBox + SpeedSearch`

**理由**：

1. **完全匹配需求**: 100-300 项数据量在 SpeedSearch 最佳性能范围内
2. **原生体验**: 与 IDEA 内置下拉列表（Maven 版本、SDK、JDK 等）体验一致
3. **零配置集成**: IDE 内置功能，无需额外实现过滤逻辑
4. **键盘友好**: 支持键盘快速导航，符合 IDE 用户习惯
5. **代码简洁**: 一行代码即可启用搜索功能
6. **无额外 UI**: 无需额外的输入框，界面简洁

### 3.3 方案优势

| 优势        | 说明                   |
|-----------|----------------------|
| **原生体验**  | 与 IDEA 内置功能一致，用户无需学习 |
| **学习成本低** | API 简洁，一行代码即可启用      |
| **界面简洁**  | 无需额外输入框，界面更紧凑        |
| **键盘友好**  | 支持键盘快速导航和搜索          |
| **性能优秀**  | 100-500 项数据性能表现优异    |

### 3.4 适用性评估

| 数据量       | 适用性        | 说明                    |
|-----------|------------|-----------------------|
| ≤ 200 项   | ✅ **完全适用** | 最佳性能范围                |
| 200～500 项 | ✅ **仍可接受** | 性能良好                  |
| 500+ 项    | ❌ **建议升级** | 建议使用 `Popup + JBList` |

**结论**: 当前场景（100+ 项模型列表）完全在适用范围内。

## 四、实现方案

### 4.1 技术架构

```
ComboBox<String>
    ↓
SpeedSearchSupply.installOn(comboBox)
    ↓
异步加载模型列表（后台线程）
    ↓
更新 ComboBox Model（EDT）
```

### 4.2 核心实现

#### 4.2.1 基础实现（最小可用版本）

```java
import com.intellij.ui.ComboBox;
import com.intellij.ui.speedSearch.SpeedSearchSupply;
import javax.swing.DefaultComboBoxModel;

// 创建 ComboBox
ComboBox<String> modelComboBox = new ComboBox<>();

// 安装 SpeedSearch（一行代码启用搜索）
SpeedSearchSupply.installOn(modelComboBox);

// 填充数据（API 返回后）
List<String> models = apiClient.fetchModels();
modelComboBox.setModel(
    new DefaultComboBoxModel<>(models.toArray(new String[0]))
);
```

**说明**：

- `SpeedSearchSupply.installOn()` 会自动接管键盘输入
- 下拉后直接输入即可过滤
- 支持前缀匹配和子串匹配（取决于 renderer）

#### 4.2.2 异步加载实现（推荐）

**重要**: 绝不能在线程中直接调用 API 或更新 UI。

```java
import com.intellij.openapi.application.ApplicationManager;
import javax.swing.DefaultComboBoxModel;

// 在后台线程获取数据
ApplicationManager.getApplication().executeOnPooledThread(() -> {
    // 调用 API 获取模型列表
    List<String> models = apiClient.fetchModels();

    // 切换到 EDT 更新 UI
    ApplicationManager.getApplication().invokeLater(() -> {
        modelComboBox.setModel(
            new DefaultComboBoxModel<>(models.toArray(new String[0]))
        );
    });
});
```

**最佳实践**：

- ✅ 使用 `executeOnPooledThread()` 执行异步操作
- ✅ 使用 `invokeLater()` 切换到 EDT 更新 UI
- ✅ 避免在 EDT 中执行网络请求或耗时操作

#### 4.2.3 自定义 Renderer（可选）

如果模型名很长或有层级结构，建议自定义 Renderer：

```java
import com.intellij.ui.SimpleColoredComponent;
import com.intellij.ui.SimpleTextAttributes;
import javax.swing.ListCellRenderer;

modelComboBox.setRenderer(new ListCellRenderer<String>() {
    private final SimpleColoredComponent component = new SimpleColoredComponent();

    @Override
    public Component getListCellRendererComponent(
        JList<? extends String> list,
        String value,
        int index,
        boolean isSelected,
        boolean cellHasFocus
    ) {
        component.clear();
        // 自定义渲染逻辑
        if (value != null) {
            component.append(value, SimpleTextAttributes.REGULAR_ATTRIBUTES);
        }
        return component;
    }
});
```

**说明**：

- SpeedSearch 会自动基于 renderer 文本做匹配
- 可以自定义文本样式、图标等

### 4.3 完整实现示例

#### 4.3.1 ModelSelector 工具类

```java
package dev.dong4j.zeka.stack.idea.plugin.common.ui;

import com.intellij.openapi.application.ApplicationManager;
import com.intellij.ui.ComboBox;
import com.intellij.ui.speedSearch.SpeedSearchSupply;
import org.jetbrains.annotations.NotNull;
import org.jetbrains.annotations.Nullable;

import javax.swing.*;
import java.util.List;

/**
 * 可搜索的模型选择器
 * <p>
 * 基于 ComboBox + SpeedSearch 实现，提供原生的 IDE 搜索体验。
 *
 * @author IntelliAI Engine Team
 * @since 1.0.0
 */
public class SearchableModelComboBox {
    private final ComboBox<String> comboBox;
    private final ModelListProvider modelListProvider;

    /**
     * 创建可搜索的模型选择器
     *
     * @param modelListProvider 模型列表提供者（用于异步加载模型）
     */
    public SearchableModelComboBox(@NotNull ModelListProvider modelListProvider) {
        this.modelListProvider = modelListProvider;
        this.comboBox = new ComboBox<>();

        // 安装 SpeedSearch（启用搜索功能）
        SpeedSearchSupply.installOn(comboBox);

        // 异步加载模型列表
        loadModels();
    }

    /**
     * 获取 ComboBox 组件（用于添加到 UI）
     *
     * @return ComboBox 组件
     */
    @NotNull
    public ComboBox<String> getComboBox() {
        return comboBox;
    }

    /**
     * 获取当前选中的模型
     *
     * @return 当前选中的模型名称，如果未选中则返回 null
     */
    @Nullable
    public String getSelectedModel() {
        return (String) comboBox.getSelectedItem();
    }

    /**
     * 设置选中的模型
     *
     * @param modelName 模型名称
     */
    public void setSelectedModel(@Nullable String modelName) {
        comboBox.setSelectedItem(modelName);
    }

    /**
     * 刷新模型列表
     */
    public void refresh() {
        loadModels();
    }

    /**
     * 异步加载模型列表
     */
    private void loadModels() {
        // 显示加载状态（可选）
        comboBox.setEnabled(false);

        // 在后台线程获取模型列表
        ApplicationManager.getApplication().executeOnPooledThread(() -> {
            try {
                List<String> models = modelListProvider.fetchModels();

                // 切换到 EDT 更新 UI
                ApplicationManager.getApplication().invokeLater(() -> {
                    comboBox.setModel(
                        new DefaultComboBoxModel<>(models.toArray(new String[0]))
                    );
                    comboBox.setEnabled(true);
                });
            } catch (Exception e) {
                // 处理错误（可选：显示错误提示）
                ApplicationManager.getApplication().invokeLater(() -> {
                    comboBox.setEnabled(true);
                    // TODO: 显示错误通知
                });
            }
        });
    }

    /**
     * 模型列表提供者接口
     */
    @FunctionalInterface
    public interface ModelListProvider {
        /**
         * 获取模型列表（在后台线程执行）
         *
         * @return 模型名称列表
         * @throws Exception 如果获取失败
         */
        @NotNull
        List<String> fetchModels() throws Exception;
    }
}
```

#### 4.3.2 使用示例


### 4.4 SpeedSearch 特性说明

#### 4.4.1 默认行为

- ✅ **忽略大小写**: 搜索时自动忽略大小写
- ✅ **连续输入**: 连续输入的字符会形成搜索串
- ✅ **ESC 清空**: 按 ESC 键清空搜索
- ✅ **超时重置**: 一段时间不输入后自动重置搜索

#### 4.4.2 匹配规则

- **前缀匹配**: 默认支持前缀匹配
- **子串匹配**: 取决于 renderer 的实现

#### 4.4.3 不支持的功能

- ❌ 不支持拼音/分词
- ❌ 不支持权重排序
- ❌ 不支持模糊评分（Levenshtein）

**说明**: 对于 100-300 条模型名，这些限制不影响使用体验。

#### 4.6.3 缓存优化

```java
// 可选：缓存模型列表，避免重复请求
private List<String> cachedModels;
private long lastFetchTime;
private static final long CACHE_DURATION = 5 * 60 * 1000; // 5 分钟

private List<String> fetchModelsWithCache() {
    long now = System.currentTimeMillis();
    if (cachedModels != null && (now - lastFetchTime) < CACHE_DURATION) {
        return cachedModels;
    }

    List<String> models = apiClient.fetchModels();
    cachedModels = models;
    lastFetchTime = now;
    return models;
}
```

## 五、总结

### 5.1 方案优势

1. **原生体验**: 与 IntelliJ IDEA 内置功能完全一致
2. **代码简洁**: 一行代码即可启用搜索功能
3. **性能优秀**: 100-500 项数据性能表现优异
4. **易于维护**: 无需手动实现过滤逻辑
5. **用户友好**: 符合 IDE 用户的交互习惯

### 5.2 实施建议

1. **第一阶段**: 基础实现
    - 替换现有的手动过滤逻辑
    - 集成 SpeedSearch
    - 验证基本功能

2. **第二阶段**: 优化增强
    - 完善异步加载逻辑
    - 添加错误处理
    - 优化用户体验

    - 封装为可复用组件
    - 支持加载状态显示
    - 添加缓存机制

### 5.3 注意事项

- ⚠️ **线程安全**: 确保所有 UI 更新都在 EDT 中执行
- ⚠️ **性能考虑**: 数据量超过 500 项时考虑升级方案
- ⚠️ **错误处理**: 网络请求失败时需要友好的错误提示
- ⚠️ **用户体验**: 加载过程中显示加载状态，避免用户困惑
