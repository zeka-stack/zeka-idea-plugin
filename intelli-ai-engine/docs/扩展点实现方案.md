# PluginAISettingsProvider 扩展点实现方案

## 📋 问题背景

### 问题描述

`intelli-ai-engine` 插件提供了一个统一的 AI 服务接口 `AIService`，供其他插件使用。每个使用 `intelli-ai-engine` 的插件需要实现
`PluginAISettingsProvider`
接口，提供自己的默认供应商选择和模型参数等配置。

**问题场景**：

- 插件 A 使用通义千问（QianWen）
- 插件 B 使用 Ollama
- 两个插件都依赖 `intelli-ai-engine`，都实现了 `PluginAISettingsProvider` 接口

**原有方案的问题**：

- 如果使用 `ApplicationManager.getApplication().getService(PluginAISettingsProvider.class)` 获取服务
- 当多个插件都注册了同一接口时，IntelliJ Platform 可能：
    - 返回第一个找到的实现（不确定是哪个）
    - 抛出异常（如果检测到多个实现）
    - 行为不可预测

**结果**：插件 A 可能拿到插件 B 的配置，导致使用错误的服务提供商。

## ✅ 解决方案

使用 **IntelliJ Platform 扩展点（Extension Points）** 机制来解决多插件冲突问题。

### 方案优势

1. ✅ **标准机制**：使用 IntelliJ Platform 官方推荐的扩展点机制
2. ✅ **不依赖包名**：通过类加载器判断，不要求第三方开发者按特定包结构组织代码
3. ✅ **准确识别**：通过调用栈和类加载器准确识别调用者插件
4. ✅ **独立配置**：每个插件使用自己的配置，互不干扰

## 🔧 实现细节

### 1. 定义扩展点

在 `intelli-ai-engine/src/main/resources/META-INF/plugin.xml` 中定义扩展点：

```xml
<extensionPoints>
    <extensionPoint name="pluginAISettingsProvider"
                   interface="dev.dong4j.zeka.stack.idea.plugin.common.ai.service.PluginAISettingsProvider"/>
</extensionPoints>
```

### 2. 实现扩展点查找逻辑

在 `AIServiceImpl` 中使用扩展点：

```java
/**
 * 扩展点名称：插件 AI 设置提供者
 */
private static final ExtensionPointName<PluginAISettingsProvider> EP_NAME =
    ExtensionPointName.create("dev.dong4j.zeka.stack.idea.plugin.common.ai.pluginAISettingsProvider");

/**
 * 获取插件配置
 * <p>
 * 通过扩展点查找调用者插件对应的 PluginAISettingsProvider 实现。
 * 通过调用栈识别调用者插件，然后从扩展点中找到对应的实现。
 */
@NotNull
private PluginAISettingsProvider getPluginSettings(@NotNull Project project) {
    // 通过调用栈查找调用者插件的类
    Class<?> callerClass = findCallerPluginClass();
    if (callerClass != null) {
        // 从扩展点中查找所有注册的实现
        for (PluginAISettingsProvider provider : EP_NAME.getExtensionList()) {
            // 检查该实现是否属于调用者插件（通过类加载器判断）
            if (isProviderFromCallerPlugin(provider, callerClass)) {
                return provider;
            }
        }
    }

    // 如果找不到，返回默认实现（使用全局配置的默认值）
    return new DefaultPluginAISettingsProvider();
}
```

### 3. 识别调用者插件

通过调用栈和类加载器识别调用者插件：

```java
/**
 * 通过调用栈查找调用者插件的类
 */
@Nullable
private Class<?> findCallerPluginClass() {
    StackTraceElement[] stackTrace = Thread.currentThread().getStackTrace();
    String thisClassName = AIServiceImpl.class.getName();
    String serviceClassName = AIService.class.getName();

    for (StackTraceElement element : stackTrace) {
        String className = element.getClassName();
        // 跳过当前类、接口类和系统类
        if (!className.equals(thisClassName) &&
            !className.equals(serviceClassName) &&
            !className.startsWith("java.") &&
            !className.startsWith("sun.") &&
            !className.startsWith("com.intellij.")) {
            try {
                return Class.forName(className);
            } catch (ClassNotFoundException ignored) {
                // 继续查找下一个
            }
        }
    }
    return null;
}

/**
 * 检查 Provider 是否属于调用者插件
 * <p>
 * 通过比较类加载器来判断 Provider 和调用者是否属于同一个插件。
 */
private boolean isProviderFromCallerPlugin(@NotNull PluginAISettingsProvider provider,
                                           @NotNull Class<?> callerClass) {
    ClassLoader providerClassLoader = provider.getClass().getClassLoader();
    ClassLoader callerClassLoader = callerClass.getClassLoader();

    // 如果类加载器相同，肯定属于同一个插件
    if (providerClassLoader == callerClassLoader) {
        return true;
    }

    // 如果类加载器不同，检查是否是父子关系
    // 通过检查调用者类是否能被 Provider 的类加载器加载来判断
    try {
        String callerClassName = callerClass.getName();
        Class<?> loadedClass = providerClassLoader.loadClass(callerClassName);
        return loadedClass == callerClass;
    } catch (ClassNotFoundException e) {
        // 如果无法加载，说明不属于同一个插件
        return false;
    }
}
```

## 📖 使用方式

### 第三方插件注册实现

在第三方插件的 `plugin.xml` 中注册自己的实现：

```xml
<!-- 依赖 IntelliAI Engine 插件 -->
<depends>dev.dong4j.zeka.stack.idea.plugin.common.ai</depends>

<!-- 注册到 intelli-ai-engine 的扩展点 -->
<extensions defaultExtensionNs="dev.dong4j.zeka.stack.idea.plugin.common.ai">
    <pluginAISettingsProvider implementation="com.example.plugin.settings.MyPluginAISettingsProvider"/>
</extensions>
```

### 实现 PluginAISettingsProvider 接口

```java
package com.example.plugin.settings;

import com.intellij.openapi.components.Service;
import com.intellij.openapi.project.Project;
import org.jetbrains.annotations.NotNull;
import dev.dong4j.zeka.stack.idea.plugin.common.ai.AIProviderType;
import dev.dong4j.zeka.stack.idea.plugin.common.ai.service.PluginAISettingsProvider;
import dev.dong4j.zeka.stack.idea.plugin.common.config.AIModelParameters;
import dev.dong4j.zeka.stack.idea.plugin.common.config.AIRuntimeSettings;

@Service(Service.Level.PROJECT)
public final class MyPluginAISettingsProvider implements PluginAISettingsProvider {
    
    private final Project project;

    public MyPluginAISettingsProvider(@NotNull Project project) {
        this.project = project;
    }

    @Override
    @NotNull
    public AIProviderType getDefaultProviderType() {
        // 从插件的配置中读取默认供应商
        MyPluginSettings settings = MyPluginSettings.getInstance();
        return settings.providerType != null ? settings.providerType : AIProviderType.QIANWEN;
    }

    @Override
    @NotNull
    public AIModelParameters getModelParameters() {
        // 返回插件的模型参数配置
        MyPluginSettings settings = MyPluginSettings.getInstance();
        return settings.modelParameters != null 
            ? settings.modelParameters 
            : AIProviderSettings.getInstance().modelParameters;
    }

    @Override
    @NotNull
    public AIRuntimeSettings getRuntimeSettings() {
        // 返回插件的运行时设置
        MyPluginSettings settings = MyPluginSettings.getInstance();
        return settings.runtimeSettings != null 
            ? settings.runtimeSettings 
            : AIProviderSettings.getInstance().runtimeSettings;
    }

    @Override
    public boolean isPerformanceMode() {
        MyPluginSettings settings = MyPluginSettings.getInstance();
        return settings.performanceMode;
    }
}
```

## 🔄 工作原理

### 调用流程

1. **插件 A 调用 AI 服务**：
   ```java
   AIService aiService = AIService.getInstance();
   String result = aiService.generateContent(project, systemPrompt, userPrompt, null);
   ```

2. **AIServiceImpl 识别调用者**：
    - 通过调用栈找到调用者类（如 `TaskExecutor`）
    - 获取调用者类的类加载器

3. **查找对应的 Provider**：
    - 从扩展点获取所有注册的 `PluginAISettingsProvider` 实现
    - 遍历每个 Provider，通过类加载器判断是否属于调用者插件
    - 找到匹配的 Provider 后返回

4. **使用插件配置**：
    - 使用找到的 Provider 获取默认供应商类型、模型参数等
    - 从全局配置中获取供应商详情
    - 生成 AI 内容

### 示例场景

**场景 1：插件 A（IntelliDoc Assistant）调用**

```
调用栈：TaskExecutor -> AIService.generateContent() -> AIServiceImpl.getPluginSettings()
识别：TaskExecutor 的类加载器 = JavaDocAISettingsProvider 的类加载器
结果：返回 JavaDocAISettingsProvider（使用通义千问）
```

**场景 2：插件 B（IntelliChangelog Generator）调用**

```
调用栈：ChangelogGenerator -> AIService.generateContent() -> AIServiceImpl.getPluginSettings()
识别：ChangelogGenerator 的类加载器 = ChangelogAISettingsProvider 的类加载器
结果：返回 ChangelogAISettingsProvider（使用 Ollama）
```

## ⚠️ 注意事项

1. **类加载器判断**：通过类加载器判断插件归属，不依赖包名结构，因此第三方开发者可以自由组织代码结构。

2. **默认实现**：如果找不到对应的 Provider，会返回默认实现，使用全局配置的默认值。

3. **性能考虑**：调用栈查找和类加载器比较有一定的性能开销，但影响很小，因为：
    - 只在获取配置时执行一次
    - 调用栈通常不会很深
    - 类加载器比较是简单的引用比较

4. **兼容性**：如果第三方插件没有注册扩展点，会使用默认实现，保证向后兼容。

## 🎯 总结

通过使用 IntelliJ Platform 的扩展点机制，我们成功解决了多插件实现同一接口时的冲突问题：

- ✅ 每个插件可以独立配置自己的 AI 服务提供商
- ✅ 插件之间互不干扰，配置隔离
- ✅ 使用标准机制，易于维护和扩展
- ✅ 不依赖包名结构，灵活性强
