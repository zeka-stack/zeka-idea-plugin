# 模型下拉列表搜索筛选实现方案

## 📋 背景与目标

在 `Settings → Tools → IntelliAI Engine` 中，模型选择下拉框 `modelComboBox` 仅以纯列表形式展示模型。随着服务商数量与可用模型列表的增长，用户需要在几十甚至上百个模型名称中滚动查找，效率低且容易误选。需求为：
**下拉列表支持搜索筛选，忽略大小写**，以便用户快速定位目标模型。

## ✅ 功能范围

- 在当前模型下拉框中提供实时搜索能力，输入任意字符后仅展示匹配项（`contains`，忽略大小写）。
- 保留现有功能：手动输入模型名、刷新模型列表、根据提供商切换默认模型等。
- 搜索逻辑仅作用于展示层，不修改原始模型列表。

## 🧩 方案概述

| 关注点   | 方案                                                        |
|-------|-----------------------------------------------------------|
| 搜索触发  | 监听下拉框编辑器文本（`JTextComponent`）变化，实时过滤                       |
| 数据源   | 缓存完整模型列表 `allModelOptions`，过滤时生成 `filteredModelOptions`   |
| 匹配规则  | `candidate.toLowerCase().contains(keyword.toLowerCase())` |
| UI 行为 | 搜索时保留用户输入，自动展开匹配结果；清空输入时还原完整列表                            |
| 自动选择  | 若筛选后仍含当前模型则保持选择，否则不强制覆盖，避免干扰用户输入                          |

## 🔧 实现细节

### 1. 数据结构与初始化

1. 在 `AIProviderConfigPanel` 中新增字段：
    - `private final List<String> allModelOptions = new ArrayList<>();`
    - `private boolean suppressFilterEvents;`（防抖，避免在刷新列表时触发搜索逻辑）
2. 在加载默认模型、切换服务商或刷新模型列表时，先更新 `allModelOptions`，再调用统一方法 `applyModelFilter(String keyword)`。

### 2. 文本监听与过滤

1. 获取 `modelComboBox.getEditor().getEditorComponent()`（`JTextComponent`），注册 `DocumentListener`。
2. 在 `insertUpdate`/`removeUpdate` 中读取当前文本，交给 `applyModelFilter`：
    - 若 `keyword` 为空，直接展示 `allModelOptions`。
    - 否则按忽略大小写的包含关系过滤。
3. 更新 `ComboBoxModel` 时，使用 `DefaultComboBoxModel<>(filteredData.toArray(new String[0]))`，并确保不会触发二次过滤（依赖
   `suppressFilterEvents` 标志位）。

### 3. 与现有流程的集成

| 场景                                                         | 调整内容                                                                 |
|------------------------------------------------------------|----------------------------------------------------------------------|
| Provider 初始化（`loadSettings` / `updateBasicConnectionInfo`） | 更新 `allModelOptions` 为 `providerType.getSupportedModels()`，清空关键字     |
| 切换 Provider                                                | 同上，保持默认模型仍可选                                                         |
| 手动刷新模型列表（`refreshModelsAsync` 成功回调）                        | 将远端结果排序后写入 `allModelOptions`，若用户正输入则延续现有关键字筛选                        |
| 手动输入模型名并 `Apply`                                           | 搜索逻辑不干扰 `modelComboBox` 的 `getEditor().getItem()`；若用户输入的模型不在列表，也允许保留 |

### 4. 细节与 UX

- **大小写忽略**：通过 `Locale.ROOT` 的 `toLowerCase` 确保一致。
- **空结果提示**：保持下拉框空白即可，不额外弹窗；用户可继续输入完整名称。
- **性能**：列表通常 <200 条，使用顺序过滤即可；若未来需要可替换为 `SearchableComboBox`，当前先实现定制逻辑。
- **可维护性**：过滤逻辑封装到独立私有方法，便于后续扩展（例如前缀匹配、正则等）。

## 🧪 测试计划

1. **基础筛选**：输入 `q`，确认仅显示包含 `q`/`Q` 的模型；清空后恢复全集。
2. **大小写忽略**：输入 `GPT`、`gpt`、`GpT`，匹配结果应一致。
3. **刷新流程**：点击“刷新模型”，等待结果返回，检查搜索关键字仍然生效。
4. **自定义模型**：输入不存在的模型名称，仍可 `Apply` 并在下次打开时展示该值。
5. **Provider 切换**：切换为不支持的 provider（列表为空），确认下拉框无异常；再切回支持列表，搜索仍可用。
