# 思考能力三探针探测实现方案

## 功能概述

在「测试连接」基础连通成功后，对 OpenAI 兼容 `/chat/completions` 并发发起三次最小请求，探测 `enable_thinking` 的三种传法，汇总为能力画像并展示/持久化。

> 说明：`enable_thinking` **不是** OpenAI 官方规范字段，而是兼容厂商扩展。本探测仅针对该扩展；官方 `reasoning_effort` 不在本期范围。

## 探针矩阵

| 探针 | 请求 | 记录 |
|------|------|------|
| OMIT | 不传 `enable_thinking` | 是否成功、响应是否含思考痕迹 |
| TRUE | `enable_thinking: true` | 同上 |
| FALSE | `enable_thinking: false` | 同上 |

三路在 BGT 线程池并发，整体超时约 45s；单探针沿用较短 `timeout`（默认取配置超时，上限 20s）。

## 能力枚举

- `UNSUPPORTED`：参数均失败，仅 omit 成功 → 永不写字段
- `REQUIRED_TRUE`：true 成功且 false 失败 → 始终写 `true`，默认勾选 Think
- `OPTIONAL`：true/false 均可 → 勾选才写 `true`；关闭时**不写字段**（不写 false）
- `DEFAULT_ON_NO_PARAM`：omit 即可（常默认思考）→ 默认不写字段
- `UNKNOWN`：超时/矛盾 → 保持用户勾选；勾选才写 `true`

## 集成点

1. `testConnection` 基础验证成功后调用探测
2. 结果写入 `AIProviderConfig.thinkingProbeResult`，随可用服务商持久化
3. 成功弹窗追加「思考能力探测」摘要
4. `buildRequestBody` 按 `resolveThinkingSendMode()` 决定 omit / true
5. 设置对话框展示探测结论提示

## 非目标

- Anthropic / Gemini 协议探测
- OpenAI 官方 `reasoning_effort` 探测
- 修改基础连通失败时的行为（失败不做思考探测）
