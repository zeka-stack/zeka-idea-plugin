IntelliAI Engine

Engine 的存在，是为了让插件保持简单。而插件保持简单，是为了让用户保持信任。

IntelliAI Engine is a foundational AI infrastructure layer for IntelliJ plugins. It provides unified AI capabilities abstraction, not functionality. Engine's responsibility is "how to call AI", not "what to do with AI".

⚠️ Important Note: This plugin alone has no functionality. You need to install one of the sub-plugins (IntelliAI Javadoc, IntelliAI Changelog, IntelliAI Tracer, etc.) to use AI features. This plugin only provides AI service provider integration and manages the list of available service providers for other sub-plugins.

What Engine Does (Infrastructure Layer)

Engine is AI capability infrastructure, not a feature provider. It handles "how to do", not "what to do".

  • 🤖 Model & Provider Management: Unified access to OpenAI, Qwen, Ollama, LM Studio, SiliconFlow with preset endpoints and parameter templates
  • ⚙️ Prompt Execution & Context Assembly: Handles prompt scheduling and context building
  • ⚡ Request Lifecycle Management: Orchestrates requests, streaming responses, and error recovery off the EDT
  • 📊 Token & Usage Statistics: Automatic token counting and usage tracking
  • 🔒 Secure Credentials: Password Safe based key storage with unique service names to avoid overwrites
  • ⚙️ Unified Configuration UI: One panel for credentials, models and rate limits with instant validation
  • 🎨 Reusable UI Widgets: Inline generation buttons, status bar entries, progress dialogs ready for downstream plugins

What Engine Does NOT Do

Engine explicitly does not handle:

  • ❌ UI presentation and interaction design
  • ❌ Business logic and decision making
  • ❌ Context semantic understanding
  • ❌ User operation workflows

In one sentence: Engine doesn't know "what the user is doing", it only knows "how to call AI correctly".

Architecture: Separation of Concerns

The design follows a layered structure:

[ Engine ] - Stable, reusable, low-change infrastructure
   ↑
[ Focused Plugin ] - Small, focused, fast iteration
   ↑
[ User Interaction ] - Users don't need to know Engine exists

This separation allows:

  • Plugins evolve freely: Each plugin focuses on its core functionality (Javadoc generation, Changelog creation, etc.)
  • Clear trust boundaries: Engine = capability foundation, Plugin = problem solution
  • Consistent behavior: All plugins share the same error handling, logging, and statistics collection

How to Use

  1. 📦 Add dependency: Add IntelliAI Engine as a dependency in your custom plugin
  2. 🚀 Invoke API: Call AIService (or provider facades) to run chat/completion tasks
  3. 🎯 Focus on business logic: Let Engine handle all AI infrastructure details
  4. 🎨 Optional integration: Reuse the provided UI components, notification utilities and settings entries for consistent UX

Long-term Value

  • Reduce code duplication: All AI-related common capabilities are implemented once in Engine, reused by all plugins
  • Ensure consistent behavior: All plugins share the same error handling, logging format, and statistics collection
  • Clear responsibility boundaries: When users encounter issues, it's clear whether it's an Engine (AI call) or Plugin (business logic) problem
  • Easy to extend: Adding new plugins doesn't require re-implementing AI call logic, just focus on business logic
  • Lower maintenance cost: Engine maintained once, all plugins benefit

Example: Adding a new Code Review plugin with Engine takes 2 days instead of 2 weeks, because you only need to focus on business logic while Engine handles all AI infrastructure details.

Plugins Powered by IntelliAI Engine

  • 📝 IntelliAI Javadoc: Automatically generate Javadoc comments using AI

  • 🔍 IntelliAI Tracer: Trace and analyze code execution with AI assistance

With IntelliAI Engine, you can focus on business logic and UX, while the engine centralizes provider integrations, credential management and UI scaffolding.

IntelliAI Engine

Engine 的存在，是为了让插件保持简单。而插件保持简单，是为了让用户保持信任。

IntelliAI Engine 是 IntelliJ 插件的 AI 能力基础设施层，提供统一的 AI 能力抽象，而非功能提供。Engine 的职责是 "如何调用 AI"，而不是 "用 AI 做什么"。

⚠️ 重要说明：单独下载此插件没有任何功能，需要安装子插件（IntelliAI Javadoc、IntelliAI Changelog、IntelliAI Tracer 等）才能使用 AI 功能。此插件仅提供 AI 服务商对接能力，为其他子插件管理可用服务商列表。

Engine 负责什么（基础设施层）

Engine 是 AI 能力的基础设施，而不是功能提供者。它负责 "如何做"，而不是 "做什么"。

  • 🤖 模型与服务商管理：统一接入 OpenAI、通义千问、Ollama、LM Studio、SiliconFlow，内置 Endpoint 与参数模板
  • ⚡ Prompt 执行与上下文拼装：处理 Prompt 调度和上下文构建
  • ⚡ 请求生命周期管理：封装请求调度、流式输出和错误处理，确保在 IDE 中稳定运行
  • 📊 Token / 使用量统计：自动统计 Token 数量和使用情况
  • 🔒 安全凭证存储：基于 IntelliJ Password Safe 的 API Key 管理策略，自动生成隔离的服务名，避免覆盖
  • ⚙️ 统一配置面板：集中式设置页管理所有服务商的密钥、模型与速率限制，支持即时验证
  • 🎨 可复用 UI 组件：提供生成按钮、状态栏入口、进度弹窗等 UI 组件，帮助下游插件快速搭建交互

Engine 明确不负责什么

Engine 明确不负责：

  • ❌ UI 展示和交互设计
  • ❌ 业务逻辑和决策判断
  • ❌ 上下文语义理解
  • ❌ 用户操作流程

一句话总结：Engine 不知道"用户在做什么"，它只知道"如何正确调用 AI"。

架构设计：关注点分离

设计采用分层结构：

[ Engine ] - 稳定、可复用、低变更的基础设施
   ↑
[ 专注的插件 ] - 小而专注、快速迭代
   ↑
[ 用户交互 ] - 用户无需感知 Engine 的存在

这种分离带来的好处：

  • 插件可以自由演进：每个插件专注于自己的核心功能（Javadoc 生成、Changelog 创建等）
  • 用户信任模型更清晰：Engine = 能力底座，插件 = 问题解法
  • 保证行为一致性：所有插件共享相同的错误处理、日志格式和统计信息收集

使用步骤

  1. 📦 添加依赖：在自定义插件的依赖中添加 IntelliAI Engine
  2. 🚀 调用 API：通过 AIService 或对应的 Provider Facade 发起推理请求
  3. 🎯 专注于业务逻辑：让 Engine 处理所有 AI 基础设施细节
  4. 🎨 可选集成：复用提供的 UI 组件、通知工具类与设置项，保持一致的交互体验

这种设计的长期价值

  • 降低重复代码：所有 AI 相关的通用能力都在 Engine 中实现一次，所有插件复用
  • 保证行为一致性：所有插件共享相同的错误处理、日志格式和统计信息收集
  • 清晰的职责边界：当用户遇到问题时，可以清楚地知道是 Engine（AI 调用）还是插件（业务逻辑）的问题
  • 易于扩展：添加新插件不需要重新实现 AI 调用逻辑，只需专注于业务逻辑
  • 降低维护成本：Engine 维护一次，所有插件受益

实际例子：使用 Engine 架构添加新的 Code Review 插件，开发时间从 2 周缩短到 2 天，因为只需要专注于业务逻辑，Engine 自动处理所有底层细节。
