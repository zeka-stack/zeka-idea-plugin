## 1 能力清单

- 🤖 **依赖 IntelliAI Engine**：AI 服务商、控制台、状态栏聚合
- ⚙️ **设置页面**：含 AI 服务商选择、提示词配置
- 💾 **持久化配置**：`SettingsState` 实现配置持久化
- 🧩 **状态栏扩展点接入**：通过 Engine 扩展点注册状态栏菜单
- 🧪 **AI 接口调用示例**：非流式调用，包含错误处理
- 🌍 **国际化与图标示例**：多语言支持和图标管理
- 🔄 **插件更新信息入口**：`PluginUpdateInfoProvider` 集成
- 💬 **反馈面板**：`FeedbackPanel` 集成
- 📝 **插件信息常量**：`PluginContents` 统一管理插件信息

## 2 推荐扩展路径

### 2.1 替换示例 Action 为你的业务逻辑

在 `TerminalAction` 中：

- 替换示例提示词为你的业务提示词
- 修改 `AIChatRequest` 的构建逻辑
- 根据业务需求处理 AI 响应结果
- 添加业务特定的错误处理

### 2.2 在设置页中增加业务参数与开关

在 `SettingsState` 和 `TerminalSettingsPanel` 中：

- 添加新的配置字段（如开关、下拉选择、文本输入等）
- 在设置面板中添加对应的 UI 组件
- 在 `isModified()` 和 `apply()` 方法中处理新配置项
- 使用 `FormBuilder` 构建布局

### 2.3 为状态栏菜单增加业务快捷入口

在 `TerminalStatusBarPopupProvider` 中：

- 添加新的菜单项
- 实现菜单项的动作逻辑
- 使用 `AnAction` 或直接调用业务方法

### 2.4 使用 Engine 控制台输出调试日志

使用 `AIConsoleLoggerUtil` 工具类：

```java
// 记录带时间戳的日志
AIConsoleLoggerUtil.printWithTimestamp(project, "开始处理");

// 记录成功日志（绿色）
AIConsoleLoggerUtil.printSuccess(project, "处理完成");

// 记录普通日志
AIConsoleLoggerUtil.print(project, "处理结果：\n" + result);

// 记录错误日志（红色）
AIConsoleLoggerUtil.printError(project, "处理失败：" + error);
```

### 2.5 配置 PluginUpdateInfoProvider 并接入更新信息

在 `TerminalPluginUpdateInfoProvider` 中：

- 实现 `getUpdateInfo()` 方法
- 返回插件的更新信息（版本号、更新内容等）
- 更新信息会在 Engine 的更新检查中显示

### 2.6 使用 FeedbackPanel 收集用户反馈

`FeedbackPanel` 已集成在设置页面底部：

- 自动处理反馈提交
- 包含插件 ID、名称等信息
- 用户可以直接提交反馈、报告问题或提出建议

### 2.7 统一从 PluginContents 读取插件 ID/名称

避免硬编码，统一使用 `PluginContents`：

```java
String pluginId = PluginContents.PLUGIN_ID;
String pluginName = PluginContents.PLUGIN_NAME;
```

## 4 开发最佳实践

### 4.1 线程安全

遵循 IntelliJ Platform 的线程模型：

- **UI 操作**：必须在 EDT（Event Dispatch Thread）中执行
- **AI 调用**：在后台线程中执行，使用 `ProgressManager` 和 `Task.Backgroundable`
- **写操作**：必须使用 `WriteCommandAction` 包装
- **UI 更新**：从后台线程更新 UI 时，使用 `ApplicationManager.getApplication().invokeLater()`

示例：

```java
ProgressManager.getInstance().run(new Task.Backgroundable(project, "处理中", true) {
    @Override
    public void run(@NotNull ProgressIndicator indicator) {
        // 后台线程：执行 AI 调用
        String result = aiService.generateContent(project, request, providerConfig, null);

        // 切换到 EDT 更新 UI
        ApplicationManager.getApplication().invokeLater(() -> {
            // EDT：更新 UI
            updateUI(result);
        });
    }
});
```

### 4.2 AI 服务调用

#### 4.2.1 非流式调用

```java
AIService aiService = ApplicationManager.getApplication().getService(AIService.class);
AIChatRequest request = new AIChatRequest(systemPrompt, userPrompt);

try {
    String result = aiService.generateContent(project, request, providerConfig, null);
    // 处理结果
} catch (AIServiceException ex) {
    // 处理错误
    String message = AIServiceException.build(ex);
    AIConsoleLoggerUtil.printError(project, message);
}
```

#### 4.2.2 流式调用（可选扩展）

如果需要流式调用，可以使用 `AIService.generateContentStream()` 方法：

```java
aiService.generateContentStream(project, request, providerConfig, null,
    new AIContentStreamCallback() {
        @Override
        public void onContent(String content) {
            // 处理流式内容
        }

        @Override
        public void onComplete() {
            // 处理完成
        }

        @Override
        public void onError(AIServiceException error) {
            // 处理错误
        }
    });
```

### 4.3 配置管理

#### 4.3.1 SettingsState 设计

- 使用 `@State` 注解指定配置名称和存储位置
- 实现 `PersistentStateComponent` 接口
- 使用 `getInstance()` 静态方法获取单例实例
- 配置字段使用 `public` 修饰符，支持 XML 序列化

#### 4.3.2 设置面板设计

- 使用 `FormBuilder` 构建表单布局
- 在 `isModified()` 中比较所有配置项
- 在 `apply()` 中保存配置
- 在 `reset()` 中恢复配置

### 4.4 资源管理

- **图标文件**：使用 SVG 格式，放置在 `src/main/resources/dev/.../icons/` 目录
- **国际化资源**：放置在 `src/main/resources/messages/` 目录
- **使用工具类**：使用 `TerminalIcons` 和 `TerminalBundle` 统一管理资源

### 4.5 代码规范

- 使用 Google Java Format 格式化代码
- 遵循 IntelliJ Platform 编码规范
- 为公共类和方法添加 Javadoc 注释
- 使用 `@NotNull` 和 `@Nullable` 注解标注参数和返回值

### 4.6 测试

- 为关键功能编写单元测试
- 使用 JUnit 5 和 Mockito 进行测试
- 测试代码放置在 `src/test/java/` 目录

## 5 常见开发场景

### 5.1 场景 1：添加新的 AI Action

1. 创建 Action 类：

```java
public class MyAIAction extends AnAction {
    public MyAIAction() {
        super(TerminalBundle.message("action.my.title"),
              TerminalBundle.message("action.my.description"),
              TerminalIcons.TERMINAL_16);
    }

    @Override
    public void actionPerformed(@NotNull AnActionEvent e) {
        Project project = e.getProject();
        if (project == null) return;

        SettingsState settings = SettingsState.getInstance();
        AIProviderConfig providerConfig = resolveProviderConfig(settings);
        if (providerConfig == null) {
            NotificationUtil.showError(project, "请先配置 AI 服务商");
            return;
        }

        ProgressManager.getInstance().run(new Task.Backgroundable(project, "处理中", true) {
            @Override
            public void run(@NotNull ProgressIndicator indicator) {
                AIService aiService = ApplicationManager.getApplication()
                    .getService(AIService.class);
                AIChatRequest request = new AIChatRequest(
                    settings.systemPrompt,
                    "你的业务提示词"
                );

                try {
                    String result = aiService.generateContent(
                        project, request, providerConfig, null);
                    AIConsoleLoggerUtil.print(project, result);
                    NotificationUtil.showInfo(project, "处理完成");
                } catch (AIServiceException ex) {
                    AIConsoleLoggerUtil.printError(project,
                        AIServiceException.build(ex));
                    NotificationUtil.showError(project, "处理失败");
                }
            }
        });
    }

    private AIProviderConfig resolveProviderConfig(SettingsState settings) {
        if (settings.providerConfig != null) {
            return settings.providerConfig.copy();
        }
        AIProviderSettings global = AIProviderSettings.getInstance();
        List<AIProviderConfig> verified = global.getVerifiedProviders();
        return verified.isEmpty() ? null : verified.get(0).copy();
    }
}
```

2. 在 `plugin.xml` 中注册：

```xml
<action id="dev.dong4j.zeka.stack.idea.plugin.terminal.action.MyAIAction"
        class="dev.dong4j.zeka.stack.idea.plugin.terminal.action.MyAIAction">
    <add-to-group group-id="EditorPopupMenu" anchor="last"/>
</action>
```

## 6 构建和调试

### 6.1 本地开发

```bash
# 运行插件（会自动构建和安装 Engine 插件）
./gradlew runIde

# 构建插件
./gradlew buildPlugin

# 运行测试
./gradlew test
```

### 6.2 调试技巧

1. **使用断点调试**：在代码中设置断点，运行 `./gradlew runIde` 进行调试
2. **查看日志**：在 `Help → Show Log in Explorer` 查看插件日志
3. **使用控制台**：打开 Engine Console 查看 AI 请求和响应日志
4. **使用通知**：使用 `NotificationUtil` 显示调试信息

## 7 发布准备

1. **更新版本号**：在 `gradle.properties` 中更新 `pluginVersion`
2. **更新更新记录**：在 `includes/pluginChanges.html` 中添加更新内容
3. **更新文档**：确保文档与功能一致
4. **测试**：确保所有功能正常工作，特别是 AI 调用功能
5. **构建**：执行 `./gradlew buildPlugin` 生成插件包
6. **检查依赖**：确保 `plugin.xml` 中已正确声明 Engine 依赖

## 8 IntelliAI Engine 集成说明

### 8.1 依赖配置

在 `build.gradle.kts` 中：

```kotlin
dependencies {
    // 编译时依赖
    compileOnly("dev.dong4j.zeka.stack:intelli-ai-engine:$engineVersion")
}
```

在 `plugin.xml` 中：

```xml
<depends>dev.dong4j.zeka.stack.idea.plugin.common.ai</depends>
```

### 8.2 本地开发流程

1. `./gradlew runIde` 触发：
    - `buildAiCommonPlugin` → 构建 `intelli-ai-engine` 插件
    - `copyAiCommonPlugin` → 复制到沙盒环境
    - `runIde` → 启动带完整依赖的 IDE

### 8.3 生产发布流程

1. 确保 `plugin.xml` 中已声明 `<depends>`
2. 执行发布流程
3. 用户在 Marketplace 安装时，系统会自动提示安装 IntelliAI Engine 依赖
