# 基于代码真实改动的 Changelog 生成方案论证

## 1. 问题背景

当前实现基于 Git 提交记录（commit message）生成 Changelog，但这种方式存在以下问题：

### 1.1 提交记录与代码改动不匹配

- **提交记录可能不准确**：开发者可能忘记更新提交信息，或者提交信息过于简单（如 "fix bug"、"update"）
- **提交记录可能过时**：代码经过多次修改后，原始的提交信息可能已经不再准确反映当前的代码状态
- **提交记录可能缺失**：某些提交可能没有详细的提交信息，只有简单的 "merge" 或 "update"

### 1.2 无法反映真实的代码变更

- **无法识别代码重构**：提交记录可能说"添加功能"，但实际代码可能是重构
- **无法识别 Bug 修复**：提交记录可能说"优化性能"，但实际代码可能是修复了一个严重的 Bug
- **无法识别功能增强**：提交记录可能说"修复问题"，但实际代码可能是添加了新功能

## 2. 基于代码真实改动的优势

### 2.1 准确性更高

通过分析代码的实际改动（diff），可以：

- **准确识别变更类型**：
    - 新增文件 → 新功能
    - 删除代码 → 功能移除或重构
    - 修改逻辑 → Bug 修复或功能增强
    - 修改注释/文档 → 文档更新

- **识别代码模式**：
    - 添加测试用例 → 测试工作
    - 修改配置 → 配置更新
    - 性能优化代码 → 性能优化

### 2.2 信息更丰富

代码改动包含的信息比提交记录更丰富：

- **文件变更**：哪些文件被修改、新增或删除
- **代码行数**：变更的代码行数可以反映工作量
- **变更模式**：可以识别重构、Bug 修复、新功能等模式
- **依赖关系**：可以识别模块间的依赖关系变化

### 2.3 自动化程度更高

- **无需人工维护**：不需要开发者手动编写详细的提交信息
- **自动分类**：可以根据代码变更自动分类（新功能、Bug 修复等）
- **自动生成描述**：AI 可以根据代码变更自动生成更准确的描述

## 3. 实现方案

### 3.1 技术实现

#### 3.1.1 获取代码改动

使用 JGit 或 IntelliJ Platform API 获取提交的代码改动：

```java
// 使用 JGit 获取 diff
try (Git git = new Git(repository)) {
    ObjectId oldCommit = repository.resolve(oldHash);
    ObjectId newCommit = repository.resolve(newHash);
    
    List<DiffEntry> diffs = git.diff()
        .setOldTree(prepareTreeParser(repository, oldCommit))
        .setNewTree(prepareTreeParser(repository, newCommit))
        .call();
    
    for (DiffEntry entry : diffs) {
        // 分析每个文件的变更
        analyzeFileChange(entry);
    }
}
```

#### 3.1.2 分析代码变更

对每个文件的变更进行分析：

- **变更类型**：新增、删除、修改、重命名
- **变更内容**：具体的代码行变更
- **变更模式**：识别常见的代码模式（如添加方法、修改条件判断等）

#### 3.1.3 生成变更描述

将代码变更信息传递给 AI，生成更准确的变更描述：

```java
String prompt = buildCodeDiffPrompt(diffs);
// AI 根据代码变更生成描述，而不是根据提交记录
String changelog = aiService.generateChangelog(prompt);
```

### 3.2 Prompt 设计

#### 3.2.1 系统提示词

```
你是一位经验丰富的代码审查专家和技术文档编写者。
你的任务是根据代码的实际改动（diff）生成准确、详细的变更日志。

你需要：
1. 分析代码变更的实际内容，而不是依赖提交记录
2. 识别代码变更的类型（新功能、Bug 修复、重构等）
3. 生成准确、技术性的变更描述
4. 忽略无意义的变更（如格式化、空白字符等）
```

#### 3.2.2 用户提示词模板

```
请根据以下代码变更生成变更日志：

提交信息: {commitMessage}
提交时间: {commitDate}
提交作者: {commitAuthor}

代码变更:
{codeDiff}

要求：
1. 根据代码变更的实际内容生成描述，而不是依赖提交信息
2. 识别变更类型（新功能、Bug 修复、重构、文档更新等）
3. 描述要准确、技术性，包含具体的变更内容
4. 如果提交信息与代码变更不符，以代码变更为准
```

### 3.3 集成到现有系统

#### 3.3.1 修改 ChangelogService

```java
public String generateChangelog(@NotNull List<String> commitHashes) throws Exception {
    List<CommitInfo> commits = readCommits(commitHashes);
    
    // 新增：获取代码改动
    List<CodeDiff> codeDiffs = readCodeDiffs(commitHashes);
    
    // 使用代码改动构建 prompt，而不是提交记录
    String prompt = buildPromptFromCodeDiff(codeDiffs, commits);
    
    return callAIService(prompt);
}
```

#### 3.3.2 代码改动数据结构

```java
public class CodeDiff {
    public String filePath;           // 文件路径
    public ChangeType changeType;     // 变更类型：ADD, DELETE, MODIFY, RENAME
    public int addedLines;            // 新增行数
    public int deletedLines;          // 删除行数
    public String diffContent;        // Diff 内容
    public List<String> keyChanges;   // 关键变更点
}
```

## 4. 对比分析

### 4.1 准确性对比

| 方面       | 基于提交记录       | 基于代码改动       |
|----------|--------------|--------------|
| 变更类型识别   | 依赖提交信息，可能不准确 | 基于代码分析，更准确   |
| 变更内容描述   | 可能过于简单或过时    | 基于实际代码，更详细   |
| Bug 修复识别 | 可能被误分类       | 可以通过代码模式识别   |
| 重构识别     | 难以识别         | 可以通过代码结构变化识别 |

### 4.2 适用场景

#### 4.2.1 基于提交记录适合：

- 提交记录规范、详细的项目
- 需要快速生成 Changelog 的场景
- 提交记录与代码变更高度一致的项目

#### 4.2.2 基于代码改动适合：

- 提交记录不规范或缺失的项目
- 需要高准确性的 Changelog
- 代码变更复杂，需要详细分析的项目
- 需要自动识别变更类型的场景

## 5. 实施建议

### 5.1 渐进式实施

1. **第一阶段**：保留现有基于提交记录的实现，作为备选方案
2. **第二阶段**：实现基于代码改动的功能，作为主要方案
3. **第三阶段**：在设置中提供选择，让用户选择使用哪种方式

### 5.2 性能考虑

- **代码分析耗时**：分析代码改动比读取提交记录更耗时
- **优化方案**：
    - 缓存代码改动分析结果
    - 异步分析代码改动
    - 只分析关键文件的变更

### 5.3 用户体验

- **提供选择**：在设置中让用户选择使用提交记录还是代码改动
- **混合模式**：可以同时使用提交记录和代码改动，取长补短
- **智能推荐**：根据项目情况自动推荐使用哪种方式

## 6. 结论

基于代码真实改动生成 Changelog 的方案具有以下优势：

1. **准确性更高**：直接分析代码变更，不依赖可能不准确的提交记录
2. **信息更丰富**：可以获取更详细的变更信息
3. **自动化程度更高**：减少对人工维护提交记录的依赖

建议采用渐进式实施策略，先实现基于代码改动的功能，然后与现有方案结合，提供更好的用户体验。

## 7. 后续优化方向

1. **智能变更分类**：使用机器学习自动识别变更类型
2. **变更影响分析**：分析代码变更对系统的影响范围
3. **变更关联分析**：识别相关的代码变更，合并描述
4. **多语言支持**：支持分析不同编程语言的代码变更
5. **可视化展示**：提供代码变更的可视化展示
