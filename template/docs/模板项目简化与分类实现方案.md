# 模板插件项目简化与分类实现方案

## 1. 背景与目标

- 现有 `template` 模板项目结构复杂、功能耦合度高，不利于快速复制创建新插件。
- 需要提供一套可同时覆盖“普通插件”和“需要集成 intelli-ai-engine 的插件”两种场景的模板。
- 目标：简化基础 Action、统一包名、补齐图标与脚本、完善文档结构，并按照是否集成 AI 引擎拆分配置。

## 2. 范围与交付

1. **Action 精简**：保留单一示例 Action（右键菜单弹出提示），演示最小入口。
2. **图标体系**：引入 `ChangelogIcons` 风格的图标管理类与 `/icons` 资源。
3. **包名统一**：源代码包名重命名为 `dev.dong4j.zeka.stack.idea.plugin.example`。
4. **构建配置**：
    - `build.gradle.kts`、`gradle.properties` 参考 `intelli-ai-changelog` 结构。
    - 引入/去除与 intelli-ai-engine 相关的依赖、任务、Gradle 属性。
5. **脚本与落地页**：新增 `deploy.sh`、`landing.html`。
6. **文档体系**：新增 `docs/用户手册.md`，指导使用。
7. **双模板模式**：
    - **集成 AI 引擎**：包含设置页面、持久化配置（提供商下拉 + 提示词模板管理）、对应 UI 与国际化、`plugin.xml` 注册项。
    - **普通插件**：保留最小功能集，无 AI 依赖。
8. 其他：国际化、通知、代码规范、更新日志、用户手册同步。

## 3. 概要设计

### 3.1 Action 简化

- 删除多余示例动作，仅保留 `GenerateExampleAction`（名称可调整）。
- 入口：`EditorPopupMenu` + `ProjectViewPopupMenu`，点击后弹出 `NotificationUtil` 提示。
- 结构：继承 `AnAction`，使用 `JavaDocBundle.message` 提供文案。

### 3.2 图标体系

- 新建 `icons/ExampleIcons.java`（或 `ExampleIcons.kt`），参考 `ChangelogIcons`.
- 资源路径：`src/main/resources/icons/{example_16.svg,...}`。
- 提供至少 `16x16` 主图标，必要时扩展 `24x24/32x32`。

### 3.3 包结构调整

- `src/main/java/dev/dong4j/zeka/stack/idea/plugin/example/...`
- `plugin.xml` `action`、`applicationService`、`configurable` 等指向新包。

### 3.4 构建与属性

- `build.gradle.kts` 复制 `intelli-ai-changelog` 样式：
    - `org.jetbrains.intellij.platform` 2.x 管理依赖。
    - `pluginConfiguration` 读取 `includes` 下描述与更新记录。
    - `pluginVerifier`, `zipSigner`, `instrumentationTools`, `testFramework`。
    - Java 版本、签名、发布配置沿用。
- `gradle.properties`：补充 `pluginGroup`, `pluginName`, `pluginVersion`, `javaVersion`, `platformType`, `platformVersion`,
  `platformSinceBuild`, `platformUntilBuild`, `publishChannels` 等。

### 3.5 脚本与落地页

- `deploy.sh`：对齐 `intelli-ai-changelog/deploy.sh` 的结构，保留基本发布流程（校验、构建、上传）。
- `landing.html`：可基于 `template/landing1.html`（或 `intelli-ai-changelog/landing.html`）取精简版，展示插件介绍。

### 3.6 文档体系

- 新增 `docs/用户手册.md`：
    - 安装方式
    - 快速开始
    - 功能说明（区分普通/AI 集成）
    - 配置说明（特别是设置页面）
    - 常见问题

### 3.7 集成模式拆分

| 项目类型     | 需求          | 构建                                    | plugin.xml                                       | 设置与持久化                                                                                                                                                                                                                                                                                 |
|----------|-------------|---------------------------------------|--------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 普通插件     | 无 AI 引擎     | 无需 engine 依赖；无额外任务                    | 仅注册 Action/通知                                    | 无设置页                                                                                                                                                                                                                                                                                   |
| 集成 AI 引擎 | 需要调用 engine | 同普通版（无 engine compileOnly）；无需 copy 任务 | 需注册 `projectConfigurable` / `applicationService` | - `SettingsState`（PersistentStateComponent）<br>- `SettingsConfigurable` + `SettingsPanel`（SearchableConfigurable）<br>- UI 包含：提供商下拉、提示词模板表格（JBTable + ToolbarDecorator）<br>- 国际化文案补充<br>- 持久化字段示例：`public String provider`, `public List<PromptTemplate> templates = new ArrayList<>()` |

### 3.8 插件 XML 调整

- 注册 `applicationService`：`SettingsState`.
- 注册 `projectConfigurable`: `ExampleSettingsConfigurable`.
- 注册通知组 `Example Notifications`.
- 为 Action 指定图标 `icon="/icons/example_16.svg"`.
- 集成模式下新增 `component` or `service`?
    - 设置同步、可能的任务/意图入口。

## 4. 详细实施步骤

1. **目录与包名重构**
    - 重命名源代码包
    - 更新 `plugin.xml`、`META-INF` 相关引用
2. **Action 精简**
    - 删除多余 Action/Intention
    - 添加新 Action + Bundle 文案
3. **图标体系**
    - 新建 `src/main/java/dev/.../icons/ExampleIcons.java`
    - 添加 `icons/example_16.svg`（可提前准备 24/32 尺寸）
4. **构建配置**
    - 更新 `build.gradle.kts`、`gradle.properties`
    - 清理未用任务，统一 Gradle 插件版本
5. **脚本与 landing**
    - `deploy.sh` + `landing.html` 模板化
6. **文档**
    - `docs/用户手册.md` 编写
    - （后续）更新 `includes/pluginChanges.html` 描述
7. **集成模式**
    - `settings` 包：State + Configurable + Panel + Model
    - 持久化字段：provider 选择、prompt 模板列表
    - UI：`FormBuilder` + `JBTable` + `ToolbarDecorator`
    - 国际化：`messages.properties` / `_zh_CN`
8. **普通模式**
    - 保留默认配置，不注册 settings
9. **测试与验证**
    - `./gradlew build`
    - `./gradlew runIde`
    - 单元测试（若添加）
    - 手动验证设置页/Action/通知

## 6. 技术细节

- **设置持久化**：`@State(name="ExampleSettings", storages=@Storage("example-settings.xml"))`，字段
  `public String provider = "local"; public List<PromptTemplate> promptTemplates = new ArrayList<>();`
- **UI 组件**：`SearchableConfigurable` + `ExampleSettingsPanel`，使用 `FormBuilder`，`JBTable` + `ToolbarDecorator` 管理模板列表。
- **Prompt 模型**：`PromptTemplate` 包含 `name`, `description`, `content`，并在 UI 中可增删改。
- **国际化键**：以 `example.settings.*` 为前缀；确认 `messages.properties` 与 `messages_zh_CN.properties` 均补充。
- **通知**：重用 `NotificationUtil` 或提供轻量封装；通知组 `Example Notifications`.

## 7. 测试计划

1. `./gradlew build` 验证编译。
2. `./gradlew runIde`：
    - 右键菜单 Action 是否出现、点击提示是否正常。
    - 设置页加载、修改、保存、重启后持久化校验。
    - Prompt 模板表格增删改逻辑验证。
3. 国际化切换：中文环境下显示中文。
4. `deploy.sh` 本地 dry-run。

## 8. 风险与缓解

- **包名调整**：需全局搜索替换，避免遗漏 `plugin.xml`、测试、资源路径。
- **双模式配置**：需确保模板用户能清晰区分；建议在 README/用户手册中说明使用方式。
- **UI 复杂度**：Prompt 管理需遵循 IntelliJ UI 规范（JB 组件 + ToolbarDecorator）。
- **依赖差异**：集成模式默认不强依赖 engine，避免市场安装冲突；说明如何手动复制 engine 插件（如有需求）。
